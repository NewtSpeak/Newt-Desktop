## 1. 功能概述

本文档定义 Owl-Desktop 的未读消息体系与通知体系，完全对标 Discord 的分层模型：

- **未读（Unread）**：被动标记，表示「有你没看过的内容」——服务器图标白点/高亮、频道名加粗 + 频道列表左侧未读白条（Discord 的 unread pill）。
- **提及（Mention）**：主动召唤，表示「有人 @ 你」——红色数字角标，穿透大多数静音设置。
- **通知（Notification）**：操作系统级提醒——桌面系统通知、声音、Dock/任务栏角标。

数据来源全部是文档 14 定义的 Gateway 事件流（`MESSAGE_CREATE/UPDATE/DELETE` 等，Server-13 AR.5）；已读状态的服务端存储与跨端同步为**依赖服务端待补充**项（文档 14 §7-8），本文按 Discord read state 惯例先行定义客户端行为与所需协议形态。

## 2. 用户故事 / 使用场景

| # | 场景 | 期望 |
|---|------|------|
| US-1 | 我离开电脑 1 小时，多个服务器有新消息 | 回来后：有新消息的服务器图标出现白点；进入后有未读的频道名加粗、显示白条；点开频道显示「以下是新消息」分割线（对标 Discord NEW 分割线） |
| US-2 | 有人在我不在看的频道 @ 我 | 服务器图标出现红色数字；频道旁红色数字；系统通知弹出（除非被抑制）；Dock 角标 +1 |

| US-4 | 我在专注工作，切换到勿扰模式 | 所有系统通知、声音、角标闪烁全部抑制；未读状态照常累计 |

## 3. 功能需求明细（FR）

### 3.1 未读模型

- **FR-01（未读判定）** 频道未读 = 该频道最新消息 ID > 本人在该频道的 `last_read_message_id`（雪花 ID 可时间排序，Server-13 AP.1）。仅统计用户具备可见性的频道（`VIEW_CHANNEL` 且无 `view_text` Restriction，Server-13 §10）。
- **FR-02（已读推进）** 满足以下任一条件即将频道标记为已读并上报服务端 ack（协议见 §7-1）：频道处于前台可见且窗口聚焦、消息列表滚动位置在底部（或用户滚动越过新消息线）；用户手动「标记为已读」（频道/服务器右键菜单，对标 Discord）；快捷键 `Shift+Esc`（标记当前服务器全部已读，对标 Discord）。
- **FR-03（未读聚合）** 服务器级未读 = 其下任一可见频道未读；分组（category）级未读 = 组内任一频道未读且未被折叠静音。静音实体不向上聚合白点，但 @ 提及计数**始终向上聚合**（对标 Discord：mute 不吃 @）。
- **FR-04（提及计数）** `MESSAGE_CREATE` 中含对本人的提及（直接 @user、@role 含本人角色、@everyone/@here——payload 字段见 §7-2）即计入该频道 mention 计数；服务器图标红色角标 = 其下所有频道 mention 数之和；全局 Dock/任务栏角标 = 所有服务器 mention 数之和 + **私信/群组私信未读与好友请求待处理**（私信细则见 [文档 19](./19-隐私设置好友与私信.md) §6.3；主页 Home 图标角标规则同 19 FR-D12/F17）。
- **FR-05（计数校正）** `MESSAGE_DELETE`/`MESSAGE_UPDATE`（编辑移除提及）需相应扣减；重连全量重同步后以服务端 read state 快照重建全部计数（防漂移）。
- **FR-06（新消息分割线）** 打开有未读的频道时，在 `last_read_message_id` 之后第一条消息上方渲染红色「新消息」分割线，并在频道顶部显示「自 X 以来的新消息 / 标记已读」浮条（对标 Discord）。分割线在离开频道前保持位置不跳动。
- **FR-07（无历史权限）** 用户无 `READ_MESSAGE_HISTORY` 的频道（Server-13 AR.3）：未读只基于进频后收到的实时消息计算，不做历史回溯。

### 3.2 通知设置层级

- **FR-08（三层设置）** 通知偏好按 **全局 → 服务器 → 频道** 三层继承覆盖（对标 Discord）：每层可取值 `全部消息` / `仅 @提及` / `无`；频道未显式设置时继承服务器，服务器未设置时继承全局默认（全局默认=`仅 @提及`，与 Discord 服务器默认一致）。
- **FR-09（静音开关）** 独立于 FR-08，提供服务器/分组/频道「静音」开关及定时静音（15 分钟 / 1 小时 / 8 小时 / 24 小时 / 直到我重新开启，对标 Discord）。静音 = 不产生系统通知与声音 + 未读白点不显示（视觉降噪），但 @ 计数保留（FR-03）。可选「静音时同时抑制 @everyone/@here」子开关（对标 Discord Suppress @everyone）。
- **FR-10（决策管线）** 每条 `MESSAGE_CREATE` 是否触发系统通知，按序判定：① 自己发的 → 否；② 频道正在前台聚焦阅读 → 否；③ 该频道被「禁看」或不可见 → 否（兜底，正常时服务端不推，Server-12 §6.2）；④ 勿扰模式 → 否（FR-14）；⑤ 静音且非 @ 本人（或 @everyone 被抑制）→ 否；⑥ 有效层级设置为 `无` → 否，`仅 @提及` 且未提及本人 → 否；⑦ 其余 → 触发。
- **FR-11（设置存储）** 通知偏好属于用户账号数据，需服务端持久化并跨端同步（协议见 §7-3）；本地保留副本供离线读取。

### 3.3 桌面系统通知

- **FR-12** 使用操作系统原生通知中心：macOS `UNUserNotificationCenter`（首次使用引导授权）、Windows Toast（AUMID 注册）。通知内容：发送者头像、`发送者（#频道名 · 服务器名）`、消息正文预览（超长截断；附件显示「[图片] / [文件名]」）。提供「通知中不显示消息内容」隐私开关（仅显示「你有一条新消息」）。
- **FR-13（点击跳转）** 点击通知：唤起/聚焦主窗口 → 切换到对应服务器与频道 → 滚动定位到该消息并高亮 2s（对标 Discord 通知点击行为与 @ 跳转高亮）。应用被关闭到托盘时同样生效。
- **FR-14（勿扰）** 用户 presence 设为「勿扰」（跨端同步，文档 14 FR-20）时：抑制全部系统通知、声音、角标闪烁/任务栏高亮；Dock/任务栏数字角标是否保留由子开关控制（默认保留计数、不闪烁）。同时尊重操作系统级勿扰/专注模式（交由系统通知中心自行抑制，客户端不重复弹）。
- **FR-15（聚合与限流）** 同一频道 5s 内多条通知合并为「#频道 N 条新消息」；全局每分钟系统通知上限（建议 20 条）防轰炸，超限只更新角标。

### 3.4 声音提示

- **FR-16** 内置提示音事件（各自独立开关 + 全局音量，见文档 16 通知设置）：新消息通知音（仅当同时满足 FR-10 触发条件）、@提及音（可与普通消息音不同）、语音频道成员加入音 / 离开音（对标 Discord join/leave 音，仅本人在该语音频道时播放）、自己被服务器静音/取消静音提示音、断线/重连提示音（默认关，避免与文档 13 UX-06 冲突——迁移恢复不发声）。
- **FR-17** 声音输出走用户在文档 16 中配置的**输出设备**；勿扰模式抑制所有提示音；本人 self_deaf 时抑制语音频道进出音。

### 3.5 角标（Badge）

- **FR-18** macOS Dock 角标 / Windows 任务栏 overlay icon 显示全局 mention 总数（FR-04）；为 0 时清除角标。仅有未读（无提及）时：macOS 显示红色圆点（无数字）、Windows 显示无数字 overlay，可通过设置切换为「仅提及计数」（对标 Discord「仅在收到提及时显示红色角标」选项）。
- **FR-19** 应用最小化到托盘时角标逻辑不变；托盘图标同步显示未读/提及状态（图标变体）。
- **FR-20** 退出登录或全部已读时立即清零所有系统级角标与通知中心内本应用的历史通知（可选清理开关）。

### 3.6 @提及高亮与跳转

- **FR-21** 消息列表中提及本人的消息整行浅色高亮背景（对标 Discord 黄色高亮）；@自己 的 token 以强调色胶囊渲染。
- **FR-22** 提供「收件箱」面板（对标 Discord Inbox）：聚合所有未读提及，按时间倒序，点击跳转原文；支持逐条/一键「已读」。
- **FR-23** 跳转到历史消息时按需分页拉取上下文（`before/after` 游标，Server-13 AR.2），定位消息高亮 2s。

## 4. UI/UX 要求

- **UX-01** 服务器栏（最左列）：未读 = 图标左侧白色胶囊短条；提及 = 图标右下红色数字角标；悬停显示服务器名。视觉与交互对标 Discord 服务器栏。
- **UX-02** 频道列表：未读频道名白色加粗；已读频道灰色；提及数以红色胶囊显示在频道行右侧；静音频道置灰且不加粗（对标 Discord）。
- **UX-03** 「新消息」分割线为红色细线 + 居右「NEW」标签；频道顶部未读浮条常驻直到点击「标记已读」或滚到底部（对标 Discord jump bar）。
- **UX-04** 所有角标数字 99+ 封顶显示「99+」。
- **UX-05** 未读/角标状态变化动画轻量（150ms 淡入淡出），事件风暴时批量合并渲染（文档 14 边界表「极端事件风暴」）。
- **UX-06** 通知设置入口：服务器右键菜单「通知设置」、频道右键「静音/通知设置」、全局设置页（文档 16 §通知）；三处状态互相一致。
- **UX-07** 声音提示音量与主音量独立；提供每个音效的「试听」按钮。

## 6. 边界与异常情况

| 场景 | 行为 |
|------|------|
| 断线期间产生的提及 | 重连补齐（resume/重同步，文档 14 FR-03/04）后一次性校正计数；补齐消息**不逐条**弹系统通知，只弹一条聚合通知（「离线期间 N 条提及」） |
| 频道被删除 | 清除其未读/提及计数并从聚合中扣除 |
| 被「禁看」后又解除 | 禁看期间服务端不推、客户端清理角标；解除后从解除时刻起重新计未读，禁看期间的消息按有无 `READ_MESSAGE_HISTORY` 决定是否可见（Server-13 AR.3） |
| 消息被删除且含对我的提及 | 扣减计数；收件箱中该条移除 |
| 多窗口/多端同时阅读 | 以最先上报的 ack 为准，其余端收到 read state 同步事件后清除角标（协议见 §7-1） |
| 系统通知权限被拒（macOS） | 设置页显示权限状态与「前往系统设置」引导；应用内角标与声音不受影响 |
| 时钟回拨/ID 乱序 | 未读判定只依赖雪花 ID 单调性，不使用本地时钟 |
| 用户在语音频道但文字页在别处 | 语音频道内嵌文字消息（若有）按普通频道未读规则处理 |
| 勿扰模式下被 @ | 不弹通知不发声；计数照常；退出勿扰不补弹历史通知（对标 Discord） |

## 7. 依赖服务端待补充

1. **Read state 协议**（文档 14 §7-8 同项）：`last_read_message_id` 的 ack 上报端点、READY 快照中的 read state 列表、跨端 `READ_STATE_UPDATE`（拟名）广播事件、每频道 mention_count 服务端计数（重同步校正依赖）。

## 8. 实现约定：通知决策管线与数据结构

### 8.1 客户端 read state 结构（与文档 14 §8 `readState` 域一致）

```text
ReadState {
  channel_id
  last_read_message_id      // 雪花 ID；已读推进的唯一依据（FR-01）
  mention_count             // 本频道未读提及数（FR-04）
  last_ack_at               // 最近一次上报服务端 ack 的时间（诊断用）
}

NotificationSettings {
  global_default: ALL | MENTIONS_ONLY | NONE      // 默认 MENTIONS_ONLY
  per_guild:   { guild_id → { level?, muted_until?, suppress_everyone? } }
  per_channel: { channel_id → { level?, muted_until? } }
}
```

有效级别解析顺序：频道显式设置 → 服务器显式设置 → 全局默认（FR-08）。

### 8.2 决策管线伪代码（FR-10 的可实现表述）

```text
on MESSAGE_CREATE(msg):
  if msg.author == self: return                       # ①
  update unread/mention counters                       # 未读永远先记账
  if channel is focused-foreground: ack_and_return     # ②
  if channel invisible/restricted: clear_and_return    # ③（Server-12 §6.2 兜底）
  if presence == DND: return                           # ④ 计数保留，不打扰
  mentioned = mentions_me(msg) and not (is_everyone(msg) and suppress_everyone)
  if muted(channel or guild) and not mentioned: return # ⑤
  level = effective_level(channel)
  if level == NONE: return                             # ⑥
  if level == MENTIONS_ONLY and not mentioned: return
  emit system_notification + sound + badge             # ⑦（经 FR-15 聚合限流）
```

### 8.3 对标映射表（评审对照用）

| 本文能力 | Discord 对应 | KOOK 对应 |

| 服务器白点/频道白条 | Server unread pill / channel bold | 服务器与频道红点 |
| @ 红色数字角标 | Mention badge（穿透 mute） | @提醒红点计数 |

## 9. 验收标准

| # | 验收项 | 通过条件 |
|---|--------|----------|
| AC-01 | 他端向未聚焦频道发普通消息 | 服务器白点 + 频道加粗 1s 内出现；按层级设置正确决定是否弹系统通知 |
| AC-02 | 他端 @ 我 | 频道与服务器红色数字 +1；系统通知弹出；Dock/任务栏角标 +1；点击通知跳转并高亮该消息 |
| AC-03 | 阅读频道到底部 | 白条/加粗消失；ack 上报；另一端角标同步清除（read state 协议就绪后） |
| AC-04 | 「新消息」分割线 | 位置 = 上次已读后第一条；标记已读后消失 |
| AC-05 | 三层通知设置矩阵测试 | 全局/服务器/频道 3×3 组合下，通知触发与否全部符合 FR-08/FR-10 |
| AC-06 | 静音服务器 + 被 @ | 无白点；红色 @ 计数仍出现并向上聚合 |
| AC-07 | 勿扰模式 | 通知、声音、闪烁全抑制；计数照常；切回在线不补弹 |
| AC-08 | 离线 100 条含 3 条提及后重连 | 计数准确（3）；仅一条聚合系统通知 |
| AC-09 | 禁看 Restriction 生效 | 该频道未读/提及即刻清零且不再累计（US-8） |
| AC-10 | 语音进出提示音 | 仅本人在房时播放；self_deaf 与勿扰时不播放 |
| AC-11 | 通知限流 | 每分钟超限后不再弹窗仅更新角标；无通知丢失导致的计数错误 |
| AC-12 | macOS/Windows 双平台 | 通知、角标、点击跳转在两平台行为一致 |
