## 1. 功能概述

本文档定义 Owl-Desktop 的**站内通知收件箱**与**官方系统私信**两个界面能力，消费 Server-16 BQ 定义的五类通知：

- **收件箱（Inbox）**：顶栏铃铛入口的下拉面板，倒序聚合好友请求、好友接受、服务器处罚、系统公告、账号安全五类通知；打开即按水位线已读。
- **官方系统私信**：DM 列表中的「OwlSpeak 官方」只读会话（Server-16 BQ.4），承载重大通知的完整正文。
- 与文档 15 的关系：15 管「消息未读/提及」与桌面通知**决策管线**；本文管「非消息类通知」的**数据源与界面**——`NOTIFICATION_CREATE` 是否升级为桌面系统通知，仍走 15 的层级与勿扰规则（Server-16 BQ.5）。

## 2. 用户故事 / 使用场景

| # | 场景 | 期望 |
|---|------|------|
| US-1 | 有人向我发好友请求 | 铃铛角标 +1；桌面通知弹出（勿扰时抑制）；收件箱内可直接「接受 / 忽略」，不必跳转好友页 |
| US-2 | 我在某服务器被禁言 24h | 收件箱出现处罚通知：服务器名、动作、原因、到期时间（与 08 号文档展示口径一致） |
| US-3 | 运营发布版本公告 | 铃铛角标 +1，**不弹**桌面通知不响声；点开可读 Markdown 正文与跳转链接 |
| US-4 | 我的账号在新设备登录 | 收件箱出现安全通知（设备/大致位置）；默认弹桌面通知（安全类穿透大多数抑制） |
| US-5 | 我被封禁后申诉成功 | 「OwlSpeak 官方」系统私信收到完整结果说明；该会话置顶显示且无法回复 |
| US-6 | 我三天没上线 | 上线后 READY 带回未读数，铃铛角标一次性正确显示，无通知轰炸回放 |
| US-7 | 我在手机端（未来）读过收件箱 | 桌面端角标随水位线同步消失 |

## 3. 功能需求明细（FR）

### 3.1 入口与角标

| # | 需求 | 验收 |
|---|------|------|
| FR-01 | 顶栏常驻铃铛图标（对标 Discord Inbox 位置）；未读数气泡 = READY `notification_unread_count` + `NOTIFICATION_CREATE` 增量 − ack 水位线覆盖数；99+ 封顶显示。 | 角标与服务端计数一致 |
| FR-02 | 铃铛未读**不计入**全局 Dock/任务栏角标（15 FR-04 公式不变：mention + DM；避免公告刷角标），但好友请求类同时驱动 Home 入口的待处理红点（19 FR-F17，同一事实两处呈现，去重由数据层保证）。 | Dock 角标不受公告影响 |

### 3.2 收件箱面板

| # | 需求 | 验收 |
|---|------|------|
| FR-03 | 点击铃铛弹出面板（宽约 480px 下拉卡片）：倒序列表，首屏 20 条，滚动分页（`GET /users/@me/notifications?before=`，Server-16 BR.4）；顶部「全部已读」按钮。 | 分页与已读可用 |
| FR-04 | 打开面板即发送水位线 ack（`POST notifications/ack {last_read_id}` = 当前最新 ID），角标清零；未读项在本次面板会话内保留「未读点」视觉直至关闭（对标 Discord 已读但高亮的过渡态）。 | ack 时机正确 |
| FR-05 | 五类通知的行渲染（type → 模板）：`FRIEND_REQUEST` 头像+「xxx 请求添加你为好友」+ 行内 ✓/✗（直接调 19 的接受/忽略接口，成功后行内状态翻转）；`FRIEND_ACCEPT` 头像+文案，点击跳好友页；`GUILD_MODERATION` 服务器图标+动作+原因+到期倒计时；`SYSTEM_ANNOUNCE` 官方图标+标题，点击展开 Markdown 正文（子集渲染复用 05 号渲染器，链接需确认跳转）；`ACCOUNT_SECURITY` 盾牌图标+设备摘要，点击跳设置「已登录设备」（16 FR-05）。 | 五类模板齐全 |
| FR-06 | 单条删除：行 hover「×」→ `DELETE notifications/{id}`；收到 `NOTIFICATION_DELETE`（公告撤回，Server-16 BQ.3）时实时移除，若正在展示则替换为「该通知已被撤回」占位 3s。 | 撤回实时生效 |
| FR-07 | 空态：插画 +「暂时没有新通知」。 | — |

### 3.3 桌面系统通知升级策略

| # | 需求 | 验收 |
|---|------|------|
| FR-08 | `NOTIFICATION_CREATE` 进入 15 号文档决策管线，按 type 的默认策略（Server-16 BQ.5 客户端裁量权）：`FRIEND_REQUEST`/`FRIEND_ACCEPT` 默认弹横幅+声音；`GUILD_MODERATION`、`ACCOUNT_SECURITY` 默认弹横幅；`SYSTEM_ANNOUNCE` 默认**仅角标**。全部受勿扰抑制，但 `ACCOUNT_SECURITY` 穿透勿扰（安全例外，仅横幅无声音）。 | 各 type 策略正确 |
| FR-09 | 通知设置页（16 号文档通知分栏）新增「系统通知」组：好友请求、好友接受、服务器处罚、公告四项可各自开关桌面通知（安全类不可关）。 | 设置项生效 |
| FR-10 | 点击桌面通知：聚焦应用并按 type 路由——好友请求 → Home 待处理；处罚 → 打开收件箱定位该条；公告 → 展开正文；安全 → 设置设备页（复用 15 FR 的聚焦跳转机制）。 | 跳转落点正确 |

### 3.4 官方系统私信

| # | 需求 | 验收 |
|---|------|------|
| FR-11 | 「OwlSpeak 官方」会话（Server-16 BQ.4）：DM 列表中有未读时自动置顶第一位；头像带官方蓝标角标；不可关闭、不可屏蔽、右键菜单仅「标为已读」。 | 置顶与菜单裁剪 |
| FR-12 | 会话内输入框替换为灰置提示条「系统消息无法回复」；消息渲染复用 05 号全套（Markdown/链接）；发送尝试（粘贴回车等）本地拦截，不发请求（服务端 `SYSTEM_CHANNEL_READONLY` 兜底）。 | 只读态完整 |
| FR-13 | 系统会话消息与收件箱可能双落同一事件（重大通知，Server-16 BQ.4）：两处独立已读，互不联动（会话走 DM read state，收件箱走水位线），不做去重（对标 Discord 官方消息 + Inbox 并存）。 | 两套已读独立 |

## 4. UI / UX 要求

1. **面板视觉**：与 Quick Switcher 同层级的浮层，暗色模式适配；每类通知有专属左侧图标色（处罚红、安全黄、公告蓝、好友绿）。
2. **相对时间**：行内时间用相对格式（「3 分钟前」「昨天」），hover 显示绝对时间。
3. **正文安全**：公告 Markdown 渲染禁用原始 HTML；外链点击弹「即将离开 OwlSpeak」确认（防钓鱼，官方域白名单直跳）。
4. **无障碍**：铃铛 aria-label 含未读数；面板列表可键盘上下导航，✓/✗ 可键盘触达；屏幕阅读器播报新通知摘要。
5. **性能**：面板打开 ≤150ms（本地缓存最近 20 条 + 后台增量）；`NOTIFICATION_CREATE` 到角标更新 ≤500ms。

## 5. 与服务端的交互（出处索引）

| 交互 | 协议 | 出处 |
|------|------|------|
| 未读快照 | READY `notification_unread_count` | Server-16 BS.1 |
| 列表/分页 | `GET /users/@me/notifications?before=&limit=` | Server-16 BR.4 |
| 已读水位线 | `POST /users/@me/notifications/ack {last_read_id}` | Server-16 BR.4 |
| 单条删除 | `DELETE /users/@me/notifications/{id}` | Server-16 BR.4 |
| 实时推送/撤回 | `NOTIFICATION_CREATE` / `NOTIFICATION_DELETE` | Server-16 BS |
| 行内接受/忽略好友请求 | `PUT/DELETE /users/@me/relationships/{id}` | Server-16 BR.1、19 §5.3 |
| 系统私信只读 | `system=true` DM、403 `SYSTEM_CHANNEL_READONLY` | Server-16 BQ.4/BV |

## 6. 边界与异常情况

| 场景 | 行为 |
|------|------|
| 离线期间积累大量通知 | READY 只带未读数；列表打开时才分页拉取；**不回放**桌面通知（仅对连接期间的 CREATE 弹） |
| ack 请求失败 | 本地乐观清零保留，静默重试 3 次；重连后以服务端计数纠偏 |
| 好友请求通知行内接受时请求已被取消 | 接口 409 → 行内替换为「该请求已失效」 |
| 处罚通知的服务器已退出/被解散 | 保留通知文本，跳转按钮灰置 |
| 通知保留期（90 天，Server-16 BQ.3）外的分页 | 服务端自然截断，客户端显示「更早的通知已过期」尾部提示 |
| 多端同时打开面板 | 各端独立 ack，水位线取 max，后到端角标自动清零（`USER_SETTINGS_UPDATE` 不涉及；依赖 ack 幂等） |

## 7. 验收标准

1. 五类通知端到端联调：触发 → 角标 ≤500ms → 面板渲染模板正确 → ack 后多端角标一致。
2. 好友请求全流程可在收件箱行内完成（接受/忽略/失效态），与 Home 待处理页状态一致。
3. 桌面通知升级策略矩阵（5 type × 勿扰开/关 × 设置开关）测试通过；安全类穿透勿扰。
4. 公告撤回实时移除；Markdown 无 HTML 注入；外链确认弹层生效。
5. 系统私信只读、置顶、不可屏蔽/关闭；与收件箱双落时两套已读互不干扰。
6. 断网 3 天后重连：角标正确、无通知回放轰炸、分页完整。
