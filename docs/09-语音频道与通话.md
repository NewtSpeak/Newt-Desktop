## 1. 功能概述

语音频道是 OwlSpeak 的核心场景。桌面客户端 Owl-Desktop 需要实现与 Discord / KOOK 完全一致的「点击即入」语音体验：用户在频道列表中单击语音频道即加入通话，无需弹窗确认；加入后频道名下实时展示成员头像与说话高亮；用户可随时静音自己、闭麦闭听、调节他人音量，或被管理员禁言 / 移动。

媒体面架构：客户端先向 **Owl-Server** 申请进房（REST `POST /voice/join`），获取 **Media Token（Ed25519 JWT）**、目标 **SFU 节点地址**、`room_id`、ICE 配置等；随后与 **Owl-SFU** 建立 **WSS + JSON 信令** 连接并完成 WebRTC 协商，音频媒体只在客户端与 SFU 之间流动，**不经 Owl-Server**（依据 05 §1、§3）。

本文档覆盖：进房/离房/切换频道全流程、信令状态机、语音状态面板、静音体系（自我 / 本地对他人 / 服务端）、管理操作、token 续期、心跳、设备与音频处理设置、按键说话、频道人数限制的 UI 表现。

## 2. 用户故事 / 使用场景

| # | 用户故事 |
|---|----------|
| US-1 | 作为普通成员，我单击左侧频道列表中的语音频道，1 秒内听到提示音并进入通话，与 Discord 体验一致。 |
| US-2 | 作为通话参与者，我能看到频道内所有人，谁在说话谁的头像亮绿圈（对标 Discord 说话指示）。 |
| US-3 | 作为参与者，我一键静音自己的麦克风（Ctrl/Cmd+Shift+M，对标 Discord 默认快捷键可配），别人立刻看到我的静音图标。 |

| US-9 | 作为用户，我在设置中切换麦克风/扬声器设备，通话中切换立即生效不掉线。 |
| US-10 | 作为用户，网络抖动或 token 过期时客户端自动恢复，我最多感知短暂静音，绝不需要手动重新点进频道（07 专项 1.1 硬性禁止回大厅手动重进）。 |

## 3. 功能需求明细（FR）

### 3.1 加入 / 离开语音频道

| 编号 | 需求 | 验收口径 |
|------|------|----------|
| FR-01 | 单击语音频道即加入，无二次确认弹窗（对标 Discord）。若已在同服其他语音频道，则触发切换流程（先离后进，见 FR-10）。 | 单击 → 状态变化，无弹窗 |
| FR-02 | 加入流程：客户端调用 `POST /voice/join { guild_id, channel_id, self_mute, self_deaf }`，携带当前自我静音状态（例如用户在未入会时已按下闭麦，入会请求即带 `self_mute=true`）。 | 抓包可见请求体 |
| FR-03 | join 成功响应包含 `token, node_id, room_id, ice_servers, sfu_endpoint_hint, caps, session_id`（05 §3.1 步骤 9），客户端据此进入媒体连接阶段。 | 字段全部被消费 |
| FR-04 | join 失败按 05 §3.2 处理：401 跳登录；403（非成员 / 无 VIEW_CHANNEL / 无 CONNECT）弹「无权加入」提示；404 刷新频道列表；503 `NO_SFU_CAPACITY` 提示「语音服务繁忙，请稍后再试」并允许重试；403 `CHANNEL_FULL` 见 FR-40。 | 每个错误码有独立文案 |
| FR-05 | 离开：点击底部语音状态面板的「断开」按钮（电话挂断图标，对标 Discord）→ `POST /voice/leave` → 收到确认或超时 1s 后本地关闭 PeerConnection 与 WSS。 | 离开后面板消失，SFU 连接关闭 |
| FR-06 | 强杀进程 / 断网离开：客户端无需特殊处理，由 SFU ICE 超时触发 `ParticipantLeft`，Server 最终一致校正（05 §5）。客户端重启后应以 Gateway 的 `VOICE_STATE_UPDATE` 快照为准渲染。 | 重启后状态正确 |

### 3.2 进房完整流程（媒体连接状态机）

| 编号 | 需求 | 验收口径 |
|------|------|----------|
| FR-07 | RTT 探测：在调用 join 前或收到候选节点列表时，对候选节点发起 `GET /rtt`（无鉴权、注意服务端限速，客户端探测频率 ≤ 1 次/节点/30s），结果作为调度参考上报或本地选点（07 专项 2.3：RTT 是三类调度信号之一）。 | 探测请求符合频控 |
| FR-08 | WSS 连接：向 `wss://<node>/ws` 建连，**连接建立后 5 秒内必须发送 `auth` 首帧** `{"op":"auth","d":{"token":"<media token>"}}`；token 严禁放 URL query（协议 §2）。 | 首帧为 auth 且 <5s |
| FR-09 | 协商时序严格遵循协议 §2.3：`auth` → 收 `ready`（含 `session_id, room_id, participants[]` 房间快照）→ 客户端发 `offer`（含上行音频轨）→ 收 `answer` → 双向 trickle `ice` → 媒体连通。房内他人发布/退订变化时由 **SFU 发起 `offer`**，客户端必须回 `answer`。 | 时序与协议一致 |
| FR-10 | 切换频道：同 guild 同时只能在一个语音频道（05 §2.2）。客户端对新频道发 join，响应带 `move: true, previous_channel_id`；若 `force_reconnect: true`（换节点），**必须重建 PeerConnection 与 WSS**（05 §6），期间 UI 显示「正在连接…」而非静默。 | 跨节点切换成功重连 |
| FR-11 | 连接状态机对用户可见：`RTC 未连接 → 请求中 → 信令连接中 → 协商中 → 语音已连接`；底部面板显示状态文本与信号质量图标（对标 Discord「Voice Connected」绿字 + 信号柱）。 | 每个状态有 UI 态 |
| FR-12 | 连接任一阶段失败自动重试，指数退避（1s/2s/4s，上限 3 次），重试前如 token 可能失效则先 refresh 或重新 join；连续失败后提示「连接语音失败」并给「重试」按钮。**禁止**要求用户手动重新点进频道作为常规恢复手段（07 专项 1.1）。 | 断言重试与限次 |

### 3.3 语音状态面板与说话指示

| 编号 | 需求 | 验收口径 |
|------|------|----------|
| FR-13 | 频道列表内嵌参与者：语音频道名称下方缩进展示成员（头像 + 昵称 + 状态小图标），实时响应 `participant_joined` / `participant_left` 与 Gateway `VOICE_STATE_UPDATE`（对标 Discord 频道树内嵌成员列表）。 | 进出实时可见 |
| FR-14 | 说话指示：消费 SFU `speaking` 事件 `{ user_ids: [...] }`（RFC 6464 audio level 聚合，~250ms 节流）。在列表中的名单里的用户头像加绿色描边，事件不含该用户后延迟 ~200ms 熄灭防闪烁。**不得**依赖客户端本地解码音量做他人指示。 | 高亮跟随事件 |
| FR-15 | 自己说话指示：本地采集侧检测（配合 PTT/VAD 门限），麦克风未静音且过门限即亮，无需等 SFU 回传。 | 本地无延迟高亮 |
| FR-16 | 底部语音状态面板（对标 Discord 左下角）：当前频道名 + 服务器名、连接状态/延迟、闭麦按钮、闭听按钮、断开按钮、屏幕共享入口（见文档 11）。 | 元素齐全 |
| FR-17 | 成员状态小图标：自我静音（麦克风斜杠）、自我闭听（耳机斜杠）、服务器静音（红色麦克风斜杠 + 角标，与自我静音视觉区分，对标 Discord）、正在共享屏幕（Live 角标）。 | 各状态图标可区分 |

### 3.4 自我静音 / 闭听（mute / deafen）

| 编号 | 需求 | 验收口径 |
|------|------|----------|
| FR-18 | 自我静音：本地立即停采（主保险），同时 `PATCH VoiceState { self_mute }` 上报 Server 广播（05 §9）。UI 即时切换不等待服务端回包（乐观更新）。 | 切换 <50ms 生效 |
| FR-19 | 自我闭听（deafen）：停止播放全部下行 + 自动连带 self_mute（对标 Discord：deafen 必 mute）；取消闭听恢复之前的 mute 状态。 | 联动逻辑正确 |
| FR-20 | 恢复说话前置校验：`self_mute=false` 且 `server_mute=false` 且 caps 含 `publish_audio`，三者缺一不可（05 §9 注意）。任一不满足时麦克风按钮呈对应禁用/提示态。 | 状态组合矩阵通过 |

### 3.5 对他人：本地音量与本地静音（= 退订）

| 编号 | 需求 | 验收口径 |
|------|------|----------|
| FR-21 | 右键成员 → 「用户音量」滑杆 0–200%（对标 Discord），本地增益，仅影响自己，持久化按 (guild, user) 记忆。 | 重启后记忆保留 |
| FR-22 | 本地静音他人：右键 →「静音」。实现为向 SFU 发 `{"op":"unsubscribe","d":{"user_id":"…"}}`，**真实停止转发**（协议 §2.1，08 D.5 订阅剪枝）；取消静音发 `subscribe` 恢复。音量拉到 0 与本地静音等价，也应触发退订以省带宽。 | 抓包见 unsubscribe |
| FR-23 | 默认订阅策略：进房后 SFU 默认自动全订本房已授权轨（协议 §2.1 subscribe 说明），客户端只需对「被本地静音名单」内用户补发 `unsubscribe`。 | 进房自动出声 |
| FR-24 | 被本地静音的用户在我的视图中显示灰色静音角标（仅自己可见），且其 `speaking` 高亮仍可显示（我知道他在说话但听不到）——对标 Discord 本地静音行为。 | 视觉与行为一致 |

### 3.6 服务端禁言 / caps 变更

| 编号 | 需求 | 验收口径 |
|------|------|----------|
| FR-25 | 收到 SFU `caps_updated` 且新 caps 不含 `publish_audio`：立即停止上行采集发送，麦克风按钮变红色禁用态，提示「你已被服务器静音」或「你已被禁言」（结合 Gateway `VOICE_CAPS_UPDATE` / `VOICE_STATE_UPDATE` 判定来源：server_mute / 失去 SPEAK / Restriction / CAPACITY_QUEUE，各来源文案不同，05 §7.3、11 AD.5）。 | 1s 内 UI 生效 |
| FR-26 | caps 恢复含 `publish_audio`：解除禁用态并 toast 提示「你已被解除静音」；若用户此前处于 self_mute，仍保持自我静音不自动开麦。 | 不越权自动开麦 |
| FR-27 | 收到 caps 不含 `subscribe_audio`（服务器 deafen）：停止下行播放，显示「已被服务器禁听」。 | UI 有明确标识 |

### 3.7 管理操作（客户端 UI）

| 编号 | 需求 | 验收口径 |
|------|------|----------|
| FR-28 | 具备 `MUTE_MEMBERS` 权限者：右键成员出现「服务器静音 / 取消服务器静音」「服务器禁听」；操作走 Server REST，客户端不直接对 SFU 下指令（05 §13.3：权限下调必须 Server→SFU 控制指令）。 | 无权限者不显示菜单项 |
| FR-29 | 具备 `MOVE_MEMBERS` 权限者：右键成员 →「移动到频道」二级菜单列出可达语音频道；也支持拖拽成员到目标频道（对标 Discord 拖拽移人）。被移动方客户端按 join 响应自动重连（05 §7.3）。 | 拖拽与菜单均可用 |
| FR-30 | 踢出语音：管理员「断开连接」菜单 → `POST /guilds/{gid}/voice/disconnect`；被踢方收到 Gateway 事件 `reason=ADMIN_DISCONNECT`，关闭 PC 并 toast「你已被管理员移出语音频道」，**不自动重连**（05 §8.1）。 | 被踢不重连 |

### 3.8 Token 刷新与心跳

| 编号 | 需求 | 验收口径 |
|------|------|----------|
| FR-31 | Media Token TTL 为 2–5 分钟（协议 §1）。客户端解析 JWT `exp`，在 **过期前 ≥30s**（建议 exp−45s，加 ±10s 抖动）调用 `POST /voice/refresh-token` 获取新 token。 | 长通话 30 分钟不断线 |
| FR-32 | 新 token 通过信令 **`auth` 帧在位重发**（协议 §2.3.3），SFU 在位更新，**不断媒体、不重建 PC**。 | 刷新期间音频无中断 |
| FR-33 | refresh 失败（如 caps 已无 `join`）：按踢出流程处理，关闭连接并按 Gateway 事件提示原因（05 §4）。 | 有明确退出提示 |
| FR-34 | 心跳：每 **15s** 发 `{"op":"ping","d":{}}`，等待 `pong`；连续 2 次（30s）未收到 pong 判定信令通道异常，进入重连流程（协议 §2.1 建议 15s）。 | 心跳周期正确 |

### 3.9 设备选择与音频处理

| 编号 | 需求 | 验收口径 |
|------|------|----------|
| FR-35 | 设置 → 语音与视频（对标 Discord Voice & Video 页）：输入设备、输出设备下拉框（枚举系统设备 + 「默认」项）、输入音量、输出音量滑杆、麦克风测试（Mic Test 回环试听）。 | 页面元素齐全 |
| FR-36 | 通话中热切换设备：替换采集/播放轨道，不重建 PeerConnection；设备拔出自动回退系统默认设备并 toast 提示。 | 切换不断线 |
| FR-37 | 音频处理开关（对标 Discord）：回声消除（AEC）、噪声抑制（NS，含标准/高级档位）、自动增益控制（AGC），默认全开；修改即时生效并持久化。 | 三开关独立生效 |
| FR-38 | 输入模式二选一（对标 Discord Input Mode）：**语音激活（VAD）**——灵敏度滑杆 + 自动灵敏度开关，低于门限不发包（DTX/静音帧）；**按键说话（PTT）**——可绑定全局热键（应用未聚焦也生效，需系统辅助功能权限，macOS 提示授权），可配置释放延迟 0–2000ms。 | 两模式行为正确 |
| FR-39 | PTT 状态下未按键时：本地采集保持但不发送（或停发 RTP），UI 麦克风图标半透明；按下时正常发送并本地高亮。 | 按/放行为正确 |

## 4. UI / UX 要求

1. **频道树**：语音频道用喇叭图标；悬停显示「加入语音」提示；已在频道内时该频道高亮。参与者行高 32px，头像 24px，说话绿圈 2px 描边（对标 Discord 视觉规格量级，最终以设计稿为准）。
2. **底部语音面板**：常驻左下角（频道列表下方），两行布局——第一行连接状态（绿色「语音已连接」/黄色「RTC 连接中」）+ 延迟毫秒数悬浮提示；第二行频道名/服务器名 + 断开按钮。下方一排：闭麦、闭听、屏幕共享、设置齿轮。
3. **快捷键**（全部可自定义，默认对标 Discord）：切换静音 `Ctrl/Cmd+Shift+M`、切换闭听 `Ctrl/Cmd+Shift+D`、PTT 自定义。
4. **提示音**：加入频道、离开频道、他人加入、他人离开、静音/取消静音各有独立短提示音（对标 Discord Sounds，可在设置逐项关闭）。
5. **右键菜单（成员）**：用户音量滑杆、本地静音、（有权限时）服务器静音/禁听、断开连接、移动到频道、舞台操作（见文档 10）。
6. **无障碍**：所有状态变化（被禁言、被移动、连接断开）除图标外必须有 toast 文字提示；支持屏幕阅读器朗读连接状态。
7. **KOOK 对标点**：频道内嵌成员列表与人数显示样式同时参考 KOOK「语音频道在线成员」呈现；静音图标语义与 KOOK 保持一致（红色 = 服务端强制，灰色 = 自我）。

## 5. 与服务端 / SFU 的交互

### 5.1 进房完整时序（引用 05 §3.1、协议 §2.3）

```text
Client                         Owl-Server                    Owl-SFU
  │ (可选) GET /rtt 对候选节点探测 ────────────────────────────►│
  │ 1. POST /voice/join {guild_id, channel_id, self_mute, self_deaf}
  │ ──────────────────────────►│ RBAC + 选点 + CreateRoom + 签 token
  │ ◄── 200 {token, node_id, room_id, ice_servers,
  │          sfu_endpoint_hint, caps, session_id}
  │ 2. WSS 连接 wss://<node>/ws ────────────────────────────►│
  │ 3. ≤5s 内 {"op":"auth","d":{token}} ─────────────────────►│ 验 sig/exp/nid/rid/caps
  │ ◄── {"op":"ready","d":{session_id, room_id, participants}} │
  │ 4. {"op":"offer","d":{sdp}}（含上行音频轨） ───────────────►│
  │ ◄── {"op":"answer","d":{sdp}}                              │
  │ ◄─► {"op":"ice", …} trickle 双向                           │
  │ ═══ 媒体连通（SRTP） ═══════════════════════════════════════│
  │ 之后：他人变化 → SFU 发 offer，客户端回 answer                │
  │ 周期：ping/pong 15s；exp−45s 时 refresh-token → auth 在位重发 │
```

### 5.2 消费的信令事件（协议 §2.2 全表）

| op | 客户端处理 |
|----|-----------|
| `ready` | 渲染参与者快照；进入 offer 阶段 |
| `answer` / `offer` / `ice` | WebRTC 协商 |
| `participant_joined/left` | 更新成员列表 + 提示音 |
| `track_published` / `track_ended` | 更新发布状态（音频/屏幕角标） |
| `caps_updated` | FR-25/26/27 |
| `speaking` | FR-14 |
| `pong` | 心跳确认 |
| `closed` | 见 §6 关闭码矩阵 |

### 5.3 消费的 Gateway 事件（05 §11）

`VOICE_STATE_UPDATE`（成员进出/静音/台上台下）、`VOICE_SERVER_UPDATE`（辅助路径：endpoint/token 推送，重连与热迁移入口，客户端收到后按其中信息重建/更新连接）、`VOICE_CAPS_UPDATE`、`VOICE_CHANNEL_STATUS`。

## 6. 边界与异常情况

### 6.1 关闭码处理矩阵（协议 §2.4，必须逐一实现）

| 关闭码 | 含义 | 客户端处理策略 |
|--------|------|----------------|
| `TOKEN_EXPIRED` | token 已过期 | 静默调用 `POST /voice/refresh-token` 拿新 token 重连；连续 2 次失败改走完整 re-join；全程限次防死循环（05 §3.3） |
| `TOKEN_INVALID` | 签名/结构非法 | 不重试同 token；重新 `POST /voice/join` 获取全新 token；再失败则报错退出语音并上报日志 |
| `WRONG_NODE` | token 的 nid 与本节点不符 | 丢弃当前节点地址，重新 join 或等待 `VOICE_SERVER_UPDATE` 获取正确节点后重连 |
| `ROOM_MISMATCH` | rid 与房间不符 | 同 WRONG_NODE：本地路由信息已脏，完整 re-join |
| `CAP_DENIED` | caps 不满足（如无 join） | 不自动重试；提示「无权加入该频道」，退出语音态；等待 Gateway 权限事件 |
| `SESSION_REVOKED` | 会话被撤销（踢出/管理操作/新会话顶替） | 不自动重连；按 Gateway 事件展示原因（如被管理员断开）；清理本地语音态 |
| `NODE_DRAINING` | 节点排空中 | 不在原节点重试；立即等待/请求 `VOICE_SERVER_UPDATE` 迁移到新节点（07 专项 1.5 Drain 自动迁移），UI 允许短暂静音但不允许回大厅 |
| `AUTH_TIMEOUT` | 5s 内未发 auth 首帧 | 客户端 bug 或网络极端拥塞；立即带 token 重连并优先发送 auth；记录埋点 |

### 6.2 其他边界

1. **信令断开但媒体仍在**：ICE 未断时保持播放，后台重建 WSS + auth 在位恢复；30s 未恢复按完整重连处理。
2. **SFU 节点崩溃**：媒体与信令同时断 → 等待 `VOICE_SERVER_UPDATE` 自动迁移（07 专项 1）；期间 UI 显示「重新连接语音中…」，禁止弹「已断开请重进」。
3. **Server 重启**：客户端保持媒体，Gateway 重连后以服务端快照校正本地状态。
4. **时钟偏差**：token 刷新时机以 `exp − 本地时间` 计算并预留余量；若 SFU 返回 TOKEN_EXPIRED 早于预期，记录偏差并提前后续刷新。
5. **多端互斥**：同账号他端进同 guild 语音导致本端 `SESSION_REVOKED` 时，提示「你已在其他设备加入语音」。
6. **设备异常**：无麦克风权限（macOS/Windows 隐私设置）时仍允许入会「仅听」，麦克风按钮提示授权引导。
7. **重试上限**：任何自动恢复循环（refresh/re-join/重连）单一故障窗口内 ≤5 次，超过后停止并给手动重试入口，防风暴。

### 6.3 依赖服务端待补充

| 项 | 说明 |
|----|------|
| join 响应中候选节点列表与 RTT 上报接口 | 07 专项 2.3 要求客户端 RTT 作为调度输入，但 05 §3.1 响应仅含单一 node；「先探测后 join 上报」的具体 API 待定 |
| 频道人数上限字段 | 软 50 / 硬 200 的频道配置项与 `CHANNEL_FULL` 判定字段下发格式待协议明确 |
| 管理员超限进入满员频道 | Discord 惯例允许，服务端未见明确条款，待裁决 |
| `speaking` 事件是否包含自己 | 影响本地指示实现取舍，待确认 |

## 7. 验收标准

1. 单击进房到听见声音 P50 < 1.5s、P95 < 3s（同 region）。
2. 协商时序、心跳周期、auth 首帧时限经抓包核验与协议 §2 完全一致。
3. 30 分钟连续通话（跨 ≥6 个 token 周期）0 次媒体中断，refresh 全部走 auth 在位重发。
4. 8 个关闭码逐一注入测试，客户端行为与 §6.1 矩阵一致，无死循环重试。
5. 本地静音他人后 SFU 侧确认对应转发停止（服务端指标核验）。
6. 服务器静音生效端到端 < 1s（对齐 05 §7.4 P99 < 1s）。
7. mute/deafen/PTT/VAD/设备切换全组合手测通过；PTT 全局热键在失焦时生效。
8. 满员频道置灰与错误文案正确；人数刷新延迟 < 2s。
9. 被管理员断开后不自动重连；节点 Drain 场景自动迁移成功率 ≥ 99%（联调环境）。
