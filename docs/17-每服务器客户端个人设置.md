## 1. 功能概述

### 1.1 要解决什么问题

用户加入的每个服务器是**独立社区**。同一账号在 A 服可能想「全部消息都响」，在 B 服只想「仅 @ 才响」；在 A 服用游戏 ID 作昵称，在 B 服用真名；在 C 服关掉私信骚扰。  
这些偏好**按服务器隔离**、**仅影响本人**、**不改变服务器对其他成员的行为**——对标 Discord 的 *User Guild Settings*（用户视角的「这个服务器对我怎么表现」），而非管理员的 *Server Settings*。

### 1.2 与现有文档的边界（必须分清）

| 能力域 | 文档 | 谁能改 | 影响范围 |
|--------|------|--------|----------|
| **服务器管理设置面板** | [18 服务器管理设置面板](./18-服务器管理设置面板.md)（业务细则 02/03/04/08/12） | 持对应管理权限的服管 / 所有者 / 系统管 | 全服所有人（名称、角色、节点池、语音包库…） |
| **账号 / 全局客户端设置** | [16 用户设置与客户端设置](./16-用户设置与客户端设置.md) | 本人 | 全账号（主题、设备、全局通知默认…） |
| **通知决策管线细节** | [15 通知与未读](./15-通知与未读.md) | 本人 | 通知是否弹出的判定逻辑 |
| **每服务器客户端个人设置（本文）** | 本文 | 本人（各服独立） | **仅本人**在该服的体验与对外展示（昵称/服内资料等部分对外） |

**一句话**：**18 =「管这个服」**；16 =「管我的客户端」；**17 =「管我对每个服的个人偏好」**。

### 1.3 本文覆盖范围

1. **入口与面板框架**：服务器右键 / 服务器名下拉 / 设置内「服务器覆盖」列表；对标 Discord 分层入口。
2. **通知与静音（服级）**：层级、静音、抑制 @everyone/@here / 角色提及等；与 15 对齐并补齐服级专属项。
3. **服内身份**：昵称；服内资料（头像/横幅/简介，分阶段）。
4. **隐私**：是否允许本服成员私信（能力依赖私信体系，接口预留）。
5. **频道列表个人化**：折叠分类记忆、隐藏已静音频道。
6. **服务器栏个人化**：拖拽排序、（P1）文件夹。
7. **服内语音相关个人项**：本人入场语音包选择（发送侧，见 12）；本服对他人入场音屏蔽名单。
8. **数据模型、本地存储、跨端同步、API / Gateway**。
9. **与 18 服管设置 UI 的并存关系**（个人中型面板 vs 管理全屏面板，不得混淆）。

**不在本文范围**：角色/权限编辑、邀请管理、节点池、封禁、审计——一律归 [18](./18-服务器管理设置面板.md) 及 02/04/08。

## 2. 用户故事 / 使用场景

| # | 用户故事 | 期望 |
|---|----------|------|
| US-01 | 作为同时加了 20 个服的用户，我右键某个吵闹的服，把它设为「仅 @提及」并静音 8 小时 | 仅该服生效；其他服通知策略不变；到点自动解除静音 |
| US-02 | 作为游戏玩家，我在「公会服」改昵称为角色名，在「同学服」保持真名 | 各服展示名独立；展示优先级：服内昵称 > 全局显示名 > 用户名（01 FR-14） |
| US-03 | 作为用户，我在某服不想被陌生人私信骚扰 | 关闭「允许本服成员私信」后，该服成员无法新开私信（若产品已有私信） |
| US-04 | 作为用户，我折叠了某个分类，下次进服仍保持折叠 | 折叠状态按服+分类记忆，换端后尽量同步 |
| US-05 | 作为用户，我拖拽侧栏服务器图标排序 | 顺序仅本人可见；跨端同步 |
| US-06 | 作为用户，我在某服选了入场语音包，另一服不选 | 进语音时只在对应服播放我选的包（12 FR 发送侧） |
| US-07 | 作为用户，全局默认「仅 @」，但工作服要「全部消息」 | 该服覆盖全局；频道级还可再覆盖（15 FR-08） |
| US-08 | 作为用户，我在用户设置「通知」页看到「已覆盖的服务器」列表 | 可一键跳转编辑或清除覆盖，回到继承全局 |
| US-09 | 作为无 `CHANGE_NICKNAME` 权限的成员 | 「修改昵称」入口隐藏或灰置 + tooltip，不可提交 |
| US-10 | 作为用户，我退出服务器 | 该服个人设置本地与云端条目应清理或标记失效，不泄漏到 UI |

## 3. 功能需求明细（FR）

### 3.1 概念模型

- **FR-01（服级个人设置文档）** 对每个用户、每个已加入的 `guild_id`，存在一份 **Guild Personal Settings（GPS）** 文档，键为 `guild_id`。未写过任何字段的服不强制落库（稀疏存储，与当前 `notifications.perGuild` 一致）。
- **FR-02（字段分类）** GPS 字段按同步与可见性分为三类：

| 类别 | 含义 | 示例 | 存储 |
|------|------|------|------|
| **A. 账号同步偏好** | 仅影响本人体验，需跨端一致 | 通知层级、静音、折叠、排序、隐藏已静音频道 | `user_settings` 文档内 `guilds` 域（见 §7） |
| **B. 成员公开字段** | 他人可见，写成员资源 | 服内昵称、（P1）服内头像/横幅/简介 | `PATCH /guilds/:id/members/@me` 等 |
| **C. 纯本机** | 设备相关或不值得上云 | 本机调试开关、（可选）某服最后打开的频道 | 本地 `owl.settings` / 会话态 |

- **FR-03（继承关系）** 通知类字段继续遵守 **全局 → 服务器 → 频道** 三层继承（15 FR-08）；本文只定义「服务器层」的完整形状与 UI，不重复定义决策管线（15 FR-10）。

### 3.2 入口与面板框架

- **FR-04（服务器右键菜单）** 服务器栏图标右键菜单至少包含（对标 Discord）：
  - 邀请其他人（权限控制见 02）
  - **通知设置**（子菜单或打开面板）
  - **静音服务器**（时长子菜单）
  - **服务器个人设置**（打开本文面板，聚焦概览/通知）
  - 修改昵称（有权限时）
  - 标记为已读
  - 退出服务器（所有者拦截见 02）
  - （有权限时）**服务器设置** → 进入 [18](./18-服务器管理设置面板.md) 服管全屏页  
  「服务器个人设置」与「服务器设置」文案必须区分，禁止混用同一入口。
- **FR-05（服务器名下拉）** 频道列表顶部服务器名下拉同步提供「服务器个人设置」与（有权时）「服务器设置」。
- **FR-06（个人设置面板形态）** 「服务器个人设置」采用 **中型模态 / 半屏面板**（对标 Discord 的 Notification Settings 弹层 + 昵称对话框的组合），**不要**做成与 18 服管全屏页同级的「第二个 Server Settings」，避免用户以为在改全服配置。
  - 标题：`{服务器名} · 个人设置`
  - 左侧或顶部分栏：概览 · 通知 · 隐私 · 入场语音 · 高级
  - `Esc` 关闭；修改默认即时生效（昵称等写服务端的字段提交后生效，失败回滚）。
- **FR-07（用户设置内统一管理）** 文档 16「通知」分栏已有「已覆盖列表」要求（16 FR-16）：本文将其扩展为 **「服务器个人偏好」汇总区**：
  - 列出所有存在非默认 GPS 的服务器（图标 + 名称 + 摘要：如「仅 @ · 静音中」）
  - 点击打开该服个人设置面板
  - 「重置为默认」清除该服 A 类字段（不影响昵称等 B 类）
- **FR-08（上下文参数）** 打开面板必须绑定 `guildId`；切换当前浏览服务器时，若面板已打开，**不自动切换目标服**（避免误改），除非用户从另一服入口再次打开。

### 3.3 通知与静音（服级）

对齐并扩展 15 / 现有 `GuildNotifyOverride`：

| 字段 | 类型 | 说明 | 优先级 |
|------|------|------|--------|
| `level` | `all` \| `mentions` \| `none` \| 缺省 | 缺省 = 继承全局 | P0 |
| `muted` | boolean | 直到重新开启的静音 | P0 |
| `muted_until` | number (ms) | 定时静音截止；与 `muted` 互斥语义见 15 | P0 |
| `suppress_everyone` | boolean | 抑制 @everyone / @here 通知（仍可产生未读策略按 15） | P0 |
| `suppress_roles` | boolean | 抑制身份组 @ 通知（直接 @ 用户不受影响） | P1 |
| `mobile_push` | `all` \| `mentions` \| `none` \| 缺省 | 移动端推送覆盖（桌面可存，首期无移动端则只同步字段） | P2 |

- **FR-09** 服级通知 UI 提供三档单选 +「跟随全局默认」；展示当前全局默认值文案（如「跟随全局（仅 @提及）」）。
- **FR-10** 静音时长选项与 15 / 现有 `MUTE_DURATION_OPTIONS` 一致：15 分钟 / 1 小时 / 8 小时 / 24 小时 / 直到重新开启；已静音时显示剩余时间与「取消静音」。
- **FR-11** `suppress_everyone` 默认关；开启后决策管线在 15 FR-10 第⑤步对 @everyone/@here 不再弹系统通知与声音（@ 红点是否保留：与 15 一致——**计数仍保留**，仅抑制打断）。
- **FR-12** 频道级覆盖优先级高于服级；UI 在服级面板底部展示「本服下已单独设置的频道」列表（只读摘要 + 跳转清除），数据源 `notifications.perChannel` 按该服频道过滤。
- **FR-13** 右键菜单的通知/静音快捷项与面板内状态**必须同源**（同一 store 字段），禁止两套状态。

### 3.4 服内身份（昵称与资料）

- **FR-14（修改本人昵称）** 个人设置「概览」提供昵称输入框（0–32 字符，空 = 清除服内昵称，回退全局显示名）。提交调用已有成员昵称 API（`PATCH .../members/@me` 或等价路径，见客户端 `patchMemberNickname`）。需 `CHANGE_NICKNAME`；管理员改他人昵称仍走 08/成员菜单，不在本文面板。
- **FR-15（展示优先级）** 全客户端统一：`member.nickname` > `display_name` > `username`（01 FR-14）；个人设置预览区实时显示「他人将看到的名字」。
- **FR-16（服内资料 P1）** 对标 Discord Server Profile：
  - 服内头像、横幅、简介（仅在该服资料卡展示）
  - 无 Nitro 类付费门槛（NewtSpeak 默认全员可用或由系统管开关，产品可配置）
  - 接口未就绪前 UI 隐藏整块，不显示半残入口
- **FR-17（权限与错误）** 403/缺失权限：字段只读 + tooltip「缺少修改昵称权限」；网络错误 toast + 本地不假成功。

### 3.5 隐私

- **FR-18（本服成员私信）** 开关「允许该服务器的成员向我发送私信」，默认开（对标 Discord）。完整裁决矩阵、与全局 `dmFrom` / 好友关系的优先级见 [文档 19](./19-隐私设置好友与私信.md) §4.3–4.4。  
  - **私信体系未实装前**：开关可展示但标注「即将推出」或隐藏。  
  - **实装后（19 M3）**：关闭后，**仅因共同在该服**而获得的新私信资格失效；**已是好友的 DM 不受影响**；历史会话可继续。对发起方使用模糊拒绝文案（19 原则 2）。
  - **存储定稿（Server-16 BM.2 / §13-D7）**：该字段为**服务端一等字段**（B 类，同昵称），读写走专用 API `PUT /users/@me/guilds/:gid/privacy { allow_dm }`，`GET /users/@me/privacy` 响应含 `guild_overrides`；**不写入** `user_settings` 不透明 JSON；跨端经 `USER_SETTINGS_UPDATE(privacy)` 同步。
- **FR-19（消息请求）** 非好友私信是否进「消息请求」由账号级 `messageRequestFilter` 控制（19 §3.4 / §4），不在本服级重复设置；本页可展示说明链接到用户设置「隐私与安全」。

### 3.6 频道列表个人化

- **FR-20（分类折叠记忆）** 用户折叠/展开某分类后，状态写入 GPS：`collapsed_category_ids: string[]`。切换服、重启客户端后恢复。默认全展开。
- **FR-21（隐藏已静音频道）** 开关「隐藏已静音的频道」，默认关。开启后：频道列表不展示被静音（服/频道静音）的频道行，但**当前选中频道**与**有 @ 提及**的频道仍显示（对标 Discord 行为：避免丢提及）。
- **FR-22（最后浏览频道 P1）** 可选记录 `last_channel_id`，再次进入该服时定位；若频道已删/不可见则回落到系统默认频道。

### 3.7 服务器栏个人化

- **FR-23（拖拽排序）** 服务器栏图标可拖拽排序；顺序数组 `guild_order: string[]` 存于**用户级**设置（非单服 GPS 内，因是全局序列）：建议 `user_settings.guild_folder_settings.guild_positions` 或顶层 `guild_order`。未出现在数组中的服按加入时间排在末尾。
- **FR-24（文件夹 P1）** 对标 Discord Server Folders：命名、颜色、折叠；数据结构预留 `folders: { id, name, color?, guild_ids[] }[]`。首期可只做扁平排序。
- **FR-25（未读与排序无关）** 排序不改变未读/角标聚合逻辑（15）。

### 3.8 入场语音（服内个人项）

与 12 文档分层一致——**发送侧在服务器个人设置**：

- **FR-26** 「我的入场语音」：列出本服可用包（服管配置 + 身份组授权过滤），单选或「不使用」。写入 GPS 或专用成员字段（若服务端将选包存在 member 上则以服务端为准）。
- **FR-27** 本服「不再播放此人的入场音」名单（12 FR-19 要求按服持久化）：从全局 `voice.voicePackMutedUsers` **迁移/拆分**为 GPS 字段 `voice_pack_muted_user_ids: string[]`，避免跨服误伤。迁移策略：首读时若仅有全局名单，可复制到当前活跃服或保留全局作为兜底（实现时二选一，推荐 **按服存储 + 全局仍作总开关**）。
- **FR-28** 接收侧总开关与音量仍在 16「语音」全局设置，不在本文重复。

### 3.9 生命周期

- **FR-29（加入服务器）** 不预创建空 GPS；首次修改再写入。
- **FR-30（退出 / 被踢 / 被封）** 收到 `GUILD_DELETE` 或等价移除后：本地删除该 `guild_id` 的 GPS 与 `perGuild` 通知覆盖；`guild_order` 移除该 id；频道覆盖中属于该服的 channel_id 一并清理（需能映射 channel→guild，或延迟惰性清理）。
- **FR-31（多端冲突）** 与 16 / settings-sync 相同：以服务端文档为权威；本地防抖 PUT；`USER_SETTINGS_UPDATE` 合并。B 类字段以成员资源 Gateway 事件为准（如 `GUILD_MEMBER_UPDATE`）。

## 4. 数据模型（客户端约定）

### 4.1 建议的 `user_settings` 文档形状

服务端现有实现：`GET/PATCH/PUT /users/@me/settings` 存储**不透明 JSON**（`userapi/settings.go`），客户端约定结构。在现有 `voice` / `appearance` / `notifications` / `presence` 基础上扩展：

```jsonc
{
  "voice": { /* 16 已有 */ },
  "appearance": { /* 16 已有 */ },
  "presence": { /* 16 已有 */ },
  "notifications": {
    "globalLevel": "mentions",
    "perGuild": {
      "<guild_id>": {
        "level": "all",
        "muted": false,
        "mutedUntil": 0,
        "suppressEveryone": true,
        "suppressRoles": false
      }
    },
    "perChannel": { /* 15 */ },
    "soundMessageEnabled": true,
    "soundMentionEnabled": true,
    "soundVolume": 60
  },
  // 本文新增域：非通知类的服级个人偏好
  "guildPreferences": {
    "<guild_id>": {
      "collapsedCategoryIds": ["..."],
      "hideMutedChannels": false,
      "lastChannelId": null,
      "voicePackId": null,
      "voicePackMutedUserIds": []
    }
  },
  "guildOrder": ["guild_id_1", "guild_id_2"],
  "guildFolders": []  // P1
}
```

说明：
- **通知仍放在 `notifications.perGuild`**，与现网 `settings-sync` / `NotifyOverrideMenu` 兼容，避免无意义大迁移。
- **非通知偏好**进 `guildPreferences`，保持域清晰。
- 昵称等 B 类字段**不要**写入 `user_settings`，避免双源真相。
- `allowDmsFromMembers`（allow_dm）**不在**本 JSON：已定稿为服务端一等字段（FR-18、Server-16 BM.2/D7），因其位于服务端私信裁决路径上。

### 4.2 TypeScript 形态（实现参考）

```ts
/** 服级通知覆盖——扩展现有 GuildNotifyOverride */
export type GuildNotifyOverride = {
  level?: NotifyLevel
  muted?: boolean
  mutedUntil?: number
  suppressEveryone?: boolean
  suppressRoles?: boolean
}

/** 服级非通知个人偏好 */
export type GuildPreferences = {
  collapsedCategoryIds?: string[]
  hideMutedChannels?: boolean
  lastChannelId?: string | null
  voicePackId?: string | null
  voicePackMutedUserIds?: string[]
}

// settings store 扩展
// guildPreferences: Record<string, GuildPreferences>
// guildOrder: string[]
```

### 4.3 本地持久化

- 继续使用 zustand `persist` 键 `owl.settings`（与 16 一致）。
- `partialize` 增加 `guildPreferences`、`guildOrder`（及 P1 `guildFolders`）。
- 面板开关、当前编辑的 `guildId` 为会话态，不持久化。

## 5. UI / UX 要求

1. **文案规范**  
   - 个人侧：「服务器个人设置」「通知设置」「修改我的昵称」  
   - 管理侧：「服务器设置」（[18](./18-服务器管理设置面板.md)）  
   禁止在个人入口出现「管理角色」「删除服务器」等管理项（那些只在 18 入口）。
2. **即时生效**：开关/单选 150ms 内反映到角标、列表加粗、系统通知行为；写远端的字段先乐观更新，失败回滚 + toast。
3. **危险操作**：无。退出服务器仍走 02 确认流。
4. **空状态**：某服从未覆盖时，面板显示继承说明而非空白错误。
5. **无障碍**：分栏可键盘切换；开关有 `aria-checked`；昵称错误 `aria-invalid`。
6. **视觉**：个人设置面板宽度建议 480–640px，对比 18 全屏管理设置形成层级差异（对标 Discord 弹层 vs 全屏 Server Settings）。
7. **权限**：无 `CHANGE_NICKNAME` 时昵称区灰置；隐私项在私信未上线时隐藏整节。

## 6. 与服务端的交互

| 客户端动作 | 接口 / 事件 | 状态 | 备注 |
|------------|-------------|------|------|
| 拉取/同步 A 类偏好 | `GET/PATCH/PUT /users/@me/settings` | **已有**（不透明 JSON） | 扩展文档字段即可，服务端无需理解业务 |
| 他端修改设置 | Gateway `USER_SETTINGS_UPDATE` | 需确认事件名与 payload | 16 / settings-sync 已按此设计 |
| 修改本人昵称 | `PATCH /guilds/:gid/members/@me`（或 members/:id） | **已有**（moderation/members） | 权限 `CHANGE_NICKNAME` |
| 昵称变更广播 | `GUILD_MEMBER_UPDATE` | 已有方向 | 本地 members store 更新 |
| 服内资料 P1 | 待定 `PATCH .../members/@me/profile` | 待补充 | 见 §8 |
| 入场包选择 | 待定（member 字段或 GPS only） | 待补充 | 与 12 对齐 |
| 退出服清理 | `GUILD_DELETE` / leave API | 见 02 | 客户端删 GPS |
| 私信隐私（allow_dm） | `PUT /users/@me/guilds/:gid/privacy` | **已定义**（Server-16 BM.2/BR.1） | 服务端一等字段，不走 settings JSON；变更推 `USER_SETTINGS_UPDATE(privacy)` |

**同步策略（A 类）**：复用 `app/lib/settings-sync.ts`  
- 将 `guildPreferences`、`guildOrder` 加入 `SYNC_DOMAINS`（或嵌在已有域）。  
- 防抖 PUT、回环抑制逻辑保持不变。  
- 单字段高频操作（折叠分类）可合并进同一防抖窗口，避免每点一次折叠就打满请求。

## 7. 关键时序

### 7.1 修改服级通知

```text
用户右键服务器 → 通知设置 → 选择「全部消息」
  → settings.setGuildNotify(guildId, { level: "all" })
  → 本地立即：该服未读白点/系统通知按 15 FR-10 新层级生效
  → settings-sync 防抖 1.5s → PUT /users/@me/settings
  → 他端 Gateway USER_SETTINGS_UPDATE → applyRemoteSettings 合并
```

### 7.2 修改服内昵称

```text
打开「{服} · 个人设置」→ 概览 → 输入昵称 → 失焦或点保存
  → 乐观更新 members store 中本人 nickname
  → PATCH /guilds/:id/members/@me { nickname }
  ├─ 200 → 保持；Gateway 回声可幂等合并
  └─ 403/400 → 回滚 nickname + 字段错误提示
```

### 7.3 拖拽服务器排序

```text
拖拽结束 → setGuildOrder(nextIds) → 侧栏立即重排
  → 防抖同步 guildOrder 至 user_settings
```

### 7.4 退出服务器清理

```text
确认退出 → leave API 成功 / 或收到 GUILD_DELETE
  → 侧栏移除（02）
  → delete guildPreferences[guildId]
  → delete notifications.perGuild[guildId]
  → 过滤 notifications.perChannel 中属于该服的频道
  → guildOrder = guildOrder.filter(id ≠ guildId)
  → 触发一次 settings 同步
```

## 9. 边界与异常情况

| 场景 | 客户端行为 |
|------|-----------|
| 设置同步失败（离线） | A 类本地先行；恢复网络后重试 PUT；冲突以服务端为准合并（16 同原则） |
| `mutedUntil` 已过期 | 惰性视为未静音（现有 `isOverrideMuted`）；可读时清理字段 |
| 折叠了已删除的分类 ID | 渲染时忽略未知 id，下次保存时过滤掉 |
| `guildOrder` 含已退出的服 | 渲染过滤；保存时压缩数组 |
| 无 `CHANGE_NICKNAME` 仍调 API | 服务端 403；客户端本不应展示可编辑态 |
| 用户同时打开个人设置与服管设置 | 允许同时概念上存在，但 18 规定全屏壳与用户设置互斥；个人中型面板可与主界面并存，勿与 18 全屏叠成双全屏 |
| 设置 JSON 损坏 / 缺字段 | merge 时用默认值填充（现有 settings merge 模式） |
| 超大 `voicePackMutedUserIds` | 客户端限制单服最多 500；超出拒绝新增并提示 |
| 隐私开关关闭但已有私信会话 | 历史会话可继续（对标 Discord），仅拦截**新会话**（产品可再定） |

## 10. 验收标准

| # | 验收项 | 通过条件 |
|---|--------|----------|
| AC-01 | 双服通知隔离 | A 服「全部消息」、B 服「无」：仅 A 的普通消息弹系统通知 |
| AC-02 | 静音定时 | 静音 15 分钟后自动恢复通知；倒计时展示正确 |
| AC-03 | 菜单与面板同源 | 右键改层级后打开个人设置面板，选中态一致 |
| AC-04 | 昵称 | 修改后成员列表/消息作者名立即变为新昵称；刷新/重登仍在；清空后回退显示名 |
| AC-05 | 无权限昵称 | 无 `CHANGE_NICKNAME` 时无法改自己的昵称 |
| AC-06 | 分类折叠 | 折叠后切走再回来仍折叠；另一端登录后同步（在 sync 可用时） |
| AC-07 | 隐藏静音频道 | 开启后静音频道隐藏，但有 @ 的频道仍可见 |
| AC-08 | 服务器排序 | 拖拽后顺序保持；重登保持；他端同步 |
| AC-09 | 退出清理 | 退出后 GPS/通知覆盖/排序中无该 guildId |
| AC-10 | 与服管设置隔离 | 普通成员能开个人设置；无任何管理分栏权限时看不到 18「服务器设置」入口 |
| AC-11 | 入场包选包 | 仅在选了包的服触发本人入场音；另一服不触发（12 联调） |
| AC-12 | 覆盖列表 | 用户设置通知页能列出并重置服级覆盖 |
