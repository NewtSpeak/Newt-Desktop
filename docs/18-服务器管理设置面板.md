## 1. 功能概述

### 1.1 要解决什么问题

服务器管理员需要在**桌面客户端内**完成对某个服务器的日常治理：改名换图标、管角色权限、看成员与封禁、管邀请、配语音节点、管入场语音包库、看审计日志等。  
交互对标 Discord：**全屏覆盖层 + 左侧导航 + 右侧内容区 + 底部未保存提示条**，与「用户设置」（文档 16）形态一致，但数据域与权限门槛完全不同。

### 1.2 三套设置面板对照（强制）

| 面板 | 文档 | 入口文案 | 形态 | 谁能开 | 改谁的数据 |
|------|------|----------|------|--------|------------|
| 用户设置 | [16](./16-用户设置与客户端设置.md) | 齿轮 / `⌘+,` | 全屏 | 登录用户 | 账号 + 本机 |
| 服务器**个人**设置 | [17](./17-每服务器客户端个人设置.md) | 「服务器个人设置」 | 中型面板 | 任意成员 | **仅本人**在该服偏好 |
| 服务器**管理**设置（本文） | 本文 | 「服务器设置」 | **全屏** | 持有任一管理向权限者 | **整服**配置与成员治理 |

- 个人入口与管理入口**禁止合并成一个面板的两个 tab**。
- 普通成员：只见个人设置；**完全看不到**「服务器设置」入口（04 FR-19：整块无权限 → 隐藏）。
- 仅有部分管理权限者（如只有 `KICK_MEMBERS`）：能打开管理面板，但**导航只显示其有权的分栏**。

### 1.3 本文职责 vs 专题文档

本文定义：

1. **面板壳层**：入口、布局、导航信息架构、Esc/脏数据拦截、保存条、权限裁剪、路由与会话态。
2. **各分栏的产品边界、权限门槛、主操作与 API 索引**。
3. **实现分期与验收**。

各分栏的深度业务规则**以专题文档为准**，本文不重复展开：

| 分栏 | 细则文档 |
|------|----------|
| 概览 / 邀请 / 节点池 / 删除与转让 | [02](./02-服务器Guild管理.md) |
| 频道结构（若嵌入）/ 频道设置另入口 | [03](./03-频道体系.md) |
| 角色 / 权限位 / 覆盖概念 | [04](./04-角色与权限RBAC.md) |
| 成员踢封 / Restriction / 审计 | [08](./08-成员管理与限制.md) |
| 入场语音包库（服管） | [12](./12-入场语音包.md) |
| 舞台模式频道级配置 | [10](./10-舞台频道与麦序.md)（主入口多为频道设置） |

**频道设置**（单频道齿轮）是另一套中型面板，**不**并入本文全屏壳；本文「频道」分栏仅提供结构管理总览（可选）或跳转说明。

## 2. 用户故事

| # | 用户故事 | 期望 |
|---|----------|------|
| US-01 | 作为所有者，我从服务器名下拉点「服务器设置」 | 全屏打开，默认「概览」，可改名称/图标 |
| US-02 | 作为只有 `MANAGE_ROLES` 的管理员 | 能打开设置，导航仅见「角色」等有权项，不见「概览」「语音节点」等 |
| US-03 | 作为管理员，我改了名称但未保存就按 Esc | 提示「有未保存的更改」，可选保存 / 放弃 / 取消关闭 |
| US-04 | 作为管理员，我在「角色」页拖排序并改权限 | 按 04 层级与防提权规则；保存后全服 Gateway 更新 |
| US-05 | 作为持 `BAN_MEMBERS` 者 | 「封禁」页可解封；无权限者导航无此项 |
| US-06 | 作为服管，我配置语音节点池 | 只能勾选系统管授权的候选节点（02/07） |
| US-07 | 作为服管，我管理入场语音包库 | 上传/启停/授权身份组（12） |
| US-08 | 作为所有者，我转让所有权或删除服务器 | 危险区二次确认 + 输名称/密码；成功后面板关闭 |
| US-09 | 作为系统管理员（`system_admin`） | 可打开任意服的管理设置（含节点池等），并可见平台级字段 |
| US-10 | 作为普通成员 | 菜单中无「服务器设置」；无法通过深链打开管理面板 |

## 3. 面板框架（FR）

### 3.1 入口

- **FR-01** 以下入口展示「服务器设置」（齿轮图标可选）：
  1. 频道列表顶部**服务器名下拉**
  2. 服务器栏图标**右键菜单**
  3. （可选）成员较少时的空状态引导——仅所有者
- **FR-02** 入口可见条件：当前用户在该服的最终服级权限满足  
  `canOpenServerSettings = owner || system_admin || ADMINISTRATOR || 任一管理分栏所需权限`  
  管理分栏权限集合见 §4 导航表。任一为真即显示入口；否则**完全隐藏**（不对普通成员灰置该项，避免噪音）。
- **FR-03** 与「服务器个人设置」（17）并列出现时：个人在上/管理在下，或分组分隔；文案不得近似到难以区分。

### 3.2 布局与交互（对标 Discord Server Settings）

- **FR-04** 全屏覆盖层（`z-index` 高于主壳、可与用户设置同级互斥——同时只开一个全屏设置壳）。
- **FR-05** 结构：

```text
┌──────────────────────────────────────────────────────────┐
│ [关闭 ×]                                                 │
│  ┌────────────┬───────────────────────────────────────┐  │
│  │ 服务器名    │  分栏标题                              │  │
│  │ 左侧导航    │  右侧滚动内容                           │  │
│  │ · 概览      │                                       │  │
│  │ · 角色      │                                       │  │
│  │ · …        │                                       │  │
│  │ ─────────  │                                       │  │
│  │ 删除服务器  │                                       │  │
│  └────────────┴───────────────────────────────────────┘  │
│  ┌─ 有未保存的更改 ──────── [重置] [保存修改] ─────────┐  │  ← 脏时浮出
└──────────────────────────────────────────────────────────┘
```

- **FR-06** 左侧导航分组标题使用弱样式大写小字（对标 Discord）：如「服务器设置」「用户管理」「安全」「语音」等。
- **FR-07** `Esc`：无脏数据 → 关闭；有脏数据 → 拦截并弹出确认（保存 / 放弃 / 继续编辑）。关闭按钮同理。
- **FR-08** 点击遮罩外区域：**不**关闭（管理误触成本高；对标 Discord Server Settings 以 Esc/关闭钮为准）。用户设置若已采用点遮罩关闭可保持，但服管面板一律不点遮罩关闭。
- **FR-09** 打开时绑定 `guildId`；面板打开期间用户切换服务器栏到其他服：**不自动切换**管理目标（与 17 FR-08 一致）；标题始终显示目标服名称与图标。
- **FR-10** 支持深链/程序打开：`openGuildAdminSettings(guildId, section?)`，供审计跳转、系统通知等使用；无权限时 no-op + toast。

### 3.3 脏数据与保存条

- **FR-11** 采用 **分栏级脏状态**（非全局单表单）：切换左侧导航时，若当前分栏 dirty，先确认保存/放弃再切换（对标 Discord）。
- **FR-12** 底部保存条文案：「小心 — 你有未保存的更改！」；按钮「重置」回滚当前分栏草稿，「保存修改」提交。
- **FR-13** 即时生效 vs 保存条：
  | 类型 | 行为 | 示例 |
  |------|------|------|
  | 表单草稿 | 保存条 | 名称、简介、公开性、节点池勾选、角色权限勾选批量编辑 |
  | 显式动作 | 立即请求 + toast | 踢人、解封、撤销邀请、删除角色、上传图标（上传成功即生效，可另提供「移除」） |
  | 排序拖拽 | 松手后立即 PATCH 排序 或 进入 dirty 点保存（二选一，**推荐松手防抖提交**，失败回滚顺序） | 角色排序、多 banner 排序 |
- **FR-14** 保存成功：清 dirty、toast 可选（Discord 无 toast，仅条消失即可）；失败：条保留 + 字段级/顶部错误。

### 3.4 权限裁剪与系统管

- **FR-15** 导航项渲染前用本地权限投影（`GET /guilds/:id/permissions/@me` 或成员+角色缓存计算，04 FR-16）过滤；**无权限的分栏不出现**。
- **FR-16** 若过滤后导航为空（理论上不应发生，因入口已判断）：关闭面板并 toast「没有可管理的项目」。
- **FR-17** `system_admin = true`：所有分栏可见；可编辑平台级字段（如 `restriction_reason_required`，见 guild PATCH）；UI 用「平台」徽章标注仅系统管可改的控件。
- **FR-18** 所有者：隐式全权限；危险区显示「转让所有权」「删除服务器」。
- **FR-19** 权限在面板打开后被剥夺（Gateway 角色变更）：立即按 FR-15 重算导航；若当前分栏已无权 → 跳到第一个仍有权的分栏或关闭；进行中的草稿丢弃并提示「你的权限已变更」。

### 3.5 会话态 store（实现约定）

建议独立 store（勿塞进用户 `owl.settings`）：

```ts
type GuildAdminSection =
  | "overview"
  | "roles"
  | "emoji"          // 表情与贴图：服 ban 包等，对齐 Owl-Server 17 / MANAGE_EXPRESSIONS
  | "members"
  | "bans"
  | "restrictions"
  | "invites"
  | "voice-nodes"
  | "voice-packs"
  | "moderation"     // 安全/限制相关开关
  | "audit-log"
  | "danger"         // 或并入 overview 底部

type GuildAdminSettingsState = {
  open: boolean
  guildId: string | null
  section: GuildAdminSection
  // 各分栏草稿与 dirty 由分栏子 store 或 sectionDraft 映射管理
  openPanel: (guildId: string, section?: GuildAdminSection) => void
  closePanel: () => void
  setSection: (section: GuildAdminSection) => void
}
```

与用户设置 `panelOpen` **互斥**：打开服管设置时关闭用户设置，反之亦然。

### 4.1 完整导航（分组）

| 服务器设置 | `channels` | 频道（可选） | `MANAGE_CHANNELS` \| … | §5.3、03；P1 可仅作说明+列表 |
| 用户管理 | `members` | 成员 | `KICK_MEMBERS` \| `BAN_MEMBERS` \| `MANAGE_NICKNAMES` \| `MANAGE_ROLES` \| `MODERATE_MEMBERS` \| ADMINISTRATOR \| owner \| system_admin | §5.4、02/08 |

| 语音 | `voice-nodes` | 语音节点 | `MANAGE_GUILD` 或服级节点配置节点（若单独位）\| ADMINISTRATOR \| owner \| system_admin | §5.8、02 §3.9 |
| 语音 | `voice-packs` | 入场语音包 | `MANAGE_GUILD` \| ADMINISTRATOR \| owner \| system_admin | §5.9、12 |
| 安全 | `moderation` | 安全与合规 | `MANAGE_GUILD` \| ADMINISTRATOR \| owner \| system_admin | §5.10 |
| 安全 | `audit-log` | 审计日志 | `VIEW_AUDIT_LOG` \| ADMINISTRATOR \| owner \| system_admin | §5.11、08 |
| 危险 | `danger` | 危险操作 | **仅 owner**（转让/删除）；system_admin 不可越权删他人服除非产品另定 | §5.12、02 |

**邀请管理页权限说明**：生成邀请走 `CREATE_INSTANT_INVITE`（常在频道菜单）；**列活跃邀请并撤销**建议要求 `MANAGE_GUILD` 或「管理邀请」能力（与 02 FR-17 一致）。无管理权但有创建权者只用邀请弹窗，不进本页。

### 4.2 默认着陆分栏

打开面板时：

1. 若指定了 `section` 且仍有权 → 该分栏；
2. 否则按导航顺序第一个有权分栏；
3. 通常有 `MANAGE_GUILD` 时默认 `overview`。

## 5. 分栏规格摘要

### 5.1 概览（Overview）

| 项 | 说明 |
|----|------|
| **权限** | `MANAGE_GUILD` |
| **字段** | 名称（2–100）、简介（≤1024）、图标、横幅（单张兼容 + 多 banner 列表） |
| **图标** | 上传 `POST /guilds/:id/icon`，删除 `DELETE .../icon`；裁剪正方形，≤8MB（01 裁剪器复用） |
| **横幅** | 兼容单张 `POST/DELETE .../banner`；多图 `GET/POST/PATCH/DELETE .../banners`（服务端已有） |
| **公开性 P1** | 加入方式：仅邀请 / 公开可发现（02 FR-21） |
| **保存** | 名称/简介走 `PATCH /guilds/:id`；媒体即时上传 |
| **预览** | 右侧或顶部实时预览侧栏图标与邀请卡片外观 |
| **API 现状** | get/patch/delete guild、icon、banner(s) **已有**（`guildapi`） |

### 5.2 角色（Roles）

| 项 | 说明 |
|----|------|
| **权限** | `MANAGE_ROLES` |
| **布局** | 左列表 + 右编辑（显示 / 权限 / 成员），04 FR-01 |
| **约束** | 层级拖拽、防提权灰置、@everyone 固定底，04 FR-02–07 |
| **API** | roles CRUD / reorder / member roles **已有** |
| **Gateway** | `GUILD_ROLE_*`、`GUILD_MEMBER_UPDATE` |

### 5.3 频道（Channels）— 可选分栏

| 项 | 说明 |
|----|------|
| **权限** | `MANAGE_CHANNELS` |
| **首期建议** | **不强制**做完整树编辑器（主路径仍是频道列表内拖拽 + 频道齿轮设置，见 03）；本分栏可做：频道数量统计、跳转说明、「在列表中管理频道」。 |
| **P1** | 内嵌可排序频道树（复用 `sortable-channel-tree`） |
| **不包含** | 单频道权限覆盖编辑器 → 频道设置面板（04 FR-09） |

### 5.4 成员（Members）

| 项 | 说明 |
|----|------|
| **权限** | 见 §4 表；行内操作再按位与层级裁剪 |
| **功能** | 搜索、角色筛选、加入时间；行菜单：改昵称、身份组、踢出、封禁、限制、转让所有权（仅 owner 对目标） |
| **层级** | 不可管理 position ≥ 自己的成员（04 FR-22） |
| **性能** | 虚拟滚动；大服分页/Lazy members（02 FR-25） |
| **API** | 成员列表/踢封等见 02§8、08；昵称 PATCH 已有 |

### 5.5 封禁（Bans）

| 项 | 说明 |
|----|------|
| **权限** | `BAN_MEMBERS` |
| **功能** | 列表（用户、原因、操作者、时间）、搜索、解封 |
| **对标** | Discord Bans 页 |
| **API** | 见 08 待补/已有 moderation 模块 |

### 5.6 限制（Restrictions）

| 项 | 说明 |
|----|------|
| **权限** | `MODERATE_MEMBERS` 等（08） |
| **功能** | 生效中限制列表、筛选、解除/编辑；创建入口也可从成员菜单进 |
| **细则** | 08 FR-33、Server-12 |

### 5.7 邀请（Invites）

| 项 | 说明 |
|----|------|
| **权限** | 管理向（§4） |
| **功能** | 活跃邀请表：码、创建者、频道、已用/上限、过期、撤销 |
| **不含** | 「邀请其他人」快捷生成 → 仍用频道/服务器菜单弹窗（02 FR-15） |
| **API** | 02 §8 邀请 CRUD |

### 5.8 语音节点（Voice Nodes）

| 项 | 说明 |
|----|------|
| **权限** | 服管 / owner / system_admin（02 FR-28） |
| **功能** | 候选节点列表勾选、空池回落提示、跨区说明、删节点热迁移警告 |
| **硬约束** | 不可提交候选外节点；调度禁止出池（产品总览硬约束 14） |
| **API** | 02 FR-34 待补 REST |

### 5.9 入场语音包（Voice Packs）

| 项 | 说明 |
|----|------|
| **权限** | 服管向 |
| **功能** | 包 CRUD、试听、身份组授权、触发场景、听到范围、打扰警告（12 FR-13/14） |
| **注意** | 成员「我选哪个包」在 **17 个人设置**，不在本页 |

### 5.10 安全与合规（Moderation settings）

| 项 | 说明 |
|----|------|
| **权限** | `MANAGE_GUILD`；部分字段仅 system_admin |
| **字段示例** | `restriction_badge_visible`（受限徽章是否展示，08）；`restriction_reason_required`（**仅系统管**，guild PATCH 已支持） |
| **P1** | 默认通知级别（服对成员的推荐默认，若产品需要）、验证等级等 Discord 类项按需加 |
| **保存** | `PATCH /guilds/:id` |

### 5.11 审计日志（Audit Log）

| 项 | 说明 |
|----|------|
| **权限** | `VIEW_AUDIT_LOG` |
| **功能** | 时间线、筛选操作类型/操作人、分页；只读 |
| **细则** | 08 FR-35 |
| **P1** | 首期可占位「即将推出」若 API 未就绪，但导航在有权限时显示占位优于隐藏（可选产品决策：**无 API 则隐藏**） |

### 5.12 危险操作（Danger Zone）

| 项 | 说明 |
|----|------|
| **可见** | 仅所有者（转让 + 删除）；非所有者不渲染整组 |
| **转让所有权** | 选成员 + 密码/二次确认 → `POST /guilds/:id/transfer-ownership`（服务端已有路由） |
| **删除服务器** | 输入**完整服务器名**确认 → `DELETE /guilds/:id` + `confirm_name`（服务端已校验） |
| **成功后** | 关面板；删除则回主页；转让后刷新权限（可能失去部分管理分栏） |

## 6. UI / UX 要求

1. **视觉**：与文档 16 用户设置全屏壳同一设计语言（左导航宽约 218px、内容区 max-width 约 740px、Discord 式排版），通过**标题区服务器图标 +「服务器设置」**与用户设置区分。
2. **危险色**：删除、封禁、撤销等用破坏性按钮样式；转让/删除分区红色描边容器。
3. **加载**：分栏首次进入显示 skeleton；失败显示重试。
4. **空状态**：无封禁/无邀请/无限制时友好插画或短文案 + 无操作暗示。
5. **无障碍**：焦点陷阱在全屏层内；`Esc` 行为见 FR-07；导航 `aria-current`。
6. **图标上传**：进度条；失败可重试；成功后侧栏与标题即时变。
7. **只读预览**：有权查看列表但某操作层级不足 → 行内按钮灰置 + tooltip（04 FR-19）。
8. **中文**：所有标签、权限说明、错误码映射中文（与 04 权限说明表一致）。

| 分栏 | 主要 API | 客户端现状 / 服务端现状 |
|------|----------|-------------------------|

| 权限投影 | `GET .../permissions/@me` | 服务端已有；应用入口可见性 |

## 8. 关键时序

### 8.1 打开面板

```text
用户点击「服务器设置」
  → 计算 canOpenServerSettings(guildId)
  → false：无入口（不应触发）
  → true：closeUserSettings()；openPanel(guildId)
  → GET /guilds/:id（若缓存过期）
  → GET /guilds/:id/permissions/@me（或用缓存位）
  → 过滤导航 → 着陆默认分栏 → 懒加载分栏数据
```

### 8.2 保存概览

```text
编辑名称/简介 → dirty
  → 保存条 → PATCH /guilds/:id
  ├─ 200 → 更新 guilds store；清 dirty；侧栏名即时变
  └─ 400/403 → 展示错误，保持 dirty
```

### 8.3 上传图标

```text
选择图片 → 裁剪 → POST /guilds/:id/icon
  ├─ 200 → GUILD_UPDATE / 响应内 icon URL → 全端更新
  └─ 413/415 → 本地校验文案
```

### 8.4 删除服务器

```text
危险区 → 输入名称 → 确认
  → DELETE /guilds/:id { confirm_name }
  ├─ 200 → GUILD_DELETE → 关面板、清状态、回主页
  └─ CONFIRM_NAME_MISMATCH → 按钮保持可点，字段错误
```

## 9. 边界与异常

| 场景 | 行为 |
|------|------|
| 面板打开时被踢出服 | 收 `GUILD_DELETE` → 强制关面板 + toast |
| 保存时名称冲突/非法 | 字段下红字；保存条不消失 |
| 多端同时改角色 | 以 Gateway 最新为准；本地 dirty 与远端冲突时提示「内容已在其他处更新」可强制刷新 |
| 节点池 API 未上线 | 分栏显示「平台暂未开放」占位，不伪造勾选 |
| 上传中关闭面板 | 确认中断或后台完成（推荐：阻止关闭直至结束/用户确认取消） |
| 所有者打开但仅想改通知 | 应去 17 个人设置，不在本面板提供通知偏好 |
| system_admin 非成员 | 服务端允许管理任意服时，客户端需能打开（01/04 系统管能力）；列表数据来源走 admin 可见 API |

## 10. 验收标准

| # | 验收项 | 通过条件 |
|---|--------|----------|
| AC-01 | 入口权限 | 普通成员无「服务器设置」；有 `MANAGE_GUILD` 或任一管理分栏权限者可见 |
| AC-02 | 导航裁剪 | 仅 `BAN_MEMBERS` 时导航含封禁等，**无**概览/节点池 |
| AC-03 | 全屏壳 | Esc/关闭、脏数据拦截、与用户设置互斥 |
| AC-04 | 概览改名 | PATCH 成功后侧栏与下拉标题更新；刷新仍在 |
| AC-05 | 图标 | 上传后全员侧栏更新（Gateway 或重拉） |
| AC-06 | 角色 | 创建/改权/排序符合 04 层级与防提权；无权限位不可授 |
| AC-07 | 成员操作 | 层级不足目标时踢/封灰置；足够时成功并刷新列表 |
| AC-08 | 封禁页 | 解封后用户可再邀请加入 |
| AC-09 | 危险区 | 非所有者不可见删除；删除须名称一致；成功全员掉服 |
| AC-10 | 与 17 隔离 | 本面板无「仅 @提及」等个人通知项；个人面板无「删除服务器」 |
| AC-11 | 权限变更 | 打开中被降权，无权分栏消失且不报崩溃 |
| AC-12 | 系统管字段 | 非 system_admin 不可改 `restriction_reason_required` |
