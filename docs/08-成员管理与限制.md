## 1. 功能概述

本文档定义 Newt-Desktop 的成员管理与多维限制（Restriction）体验，覆盖：

- **成员列表与成员卡片**：右侧成员栏按角色分组、在线状态、受限徽章；点击弹出成员卡片，含管理操作入口。
- **踢出与封禁**：`KICK_MEMBERS` 踢出、`BAN_MEMBERS` 封禁（Ban Member = 移出服务器并阻止再加入，独立于 Restriction，12 文档 AG.4 / 07 文档 4.5）。
- **多维 Restriction**：四个维度——文字**看/说**、语音**听/讲** × 作用域（单频道 / 全服对应类型）（07 文档 4.1、12 文档 AG–AH）；只收紧不放宽，叠加于 RBAC 之上。
- **管理端施加限制 UI**：选维度、选作用域、时长（`expires_at`，60s–28 天或长期）、原因（默认必填，≤512 字符）。
- **视角差异**：当事人看到原因 + 到期时间；其他成员仅见「该用户被限制」；有权管理者见完整记录（12 文档 AM 系列）。
- **保护规则**：所有者不可被限制；不可限制 position ≥ 自己的成员；禁止自限（12 文档 AK、07 文档 4.3）。
- **协管窄权限**：默认仅本语音频道禁说/抱下（12 文档 AK.2、07 文档 4.2）。
- **禁看的客户端表现**：API 404 + Gateway 不推送，频道从列表消失（12 文档 §6.2、07 文档专项 4 注意 1）。
- **限制来源区分**：手动 Restriction vs `server_mute`（成员状态）vs 舞台自动禁说 `CAPACITY_QUEUE`，管理 UI 必须区分显示（07 文档专项 3 注意 2 / 专项 4 注意 2、12 文档 AO）。
- **审计日志查看**：`VIEW_AUDIT_LOG` 权限（02 文档 bit 7）查看管理操作记录；Restriction 全字段审计（12 文档 §12）。

## 2. 用户故事 / 使用场景

| 编号 | 用户故事 |
|------|----------|
| US-01 | 作为成员，我在右侧成员列表按角色分组看到所有可见成员及在线状态，点击某人弹出成员卡片。 |
| US-02 | 作为管理员，我在成员卡片上选择「限制」，在弹窗中勾选「文字：禁止发言」、作用域「本频道」、时长 24 小时、填写原因「刷屏」，提交后立即生效。 |
| US-03 | 作为被限制的当事人，我在频道输入框上方看到「你已被禁止在此频道发言，原因：刷屏，将于 7月21日 14:00 解除」。 |
| US-04 | 作为普通成员，我看到被限制成员头像上有受限徽章，但看不到原因。 |
| US-05 | 作为管理员，我尝试限制一个角色比我高的成员，操作入口置灰并提示层级不足。 |
| US-06 | 作为语音频道协管，我在成员右键菜单只能看到「禁说」与「抱下」，看不到全服限制选项。 |
| US-07 | 作为被某文字频道「禁看」的成员，该频道直接从我的频道列表消失，我不会看到「无权限」的提示。 |
| US-08 | 作为管理员，我在语音频道成员列表中能区分：谁是被我手动禁说、谁是 server_mute、谁是超员自动禁说（CAPACITY_QUEUE），三者图标与文案不同。 |
| US-09 | 作为管理员，我封禁（Ban）一名成员，确认弹窗告知他将被移出服务器且无法再加入，其全部生效中 Restriction 同时失效归档。 |
| US-10 | 作为持 `VIEW_AUDIT_LOG` 的管理员，我在服务器设置的审计页查看谁在何时对谁施加/解除了什么限制。 |
| US-11 | 作为当事人，限制到期时我收到解除通知，输入框自动恢复可用，无需刷新。 |

## 3. 功能需求明细（FR）

### 3.1 成员列表

- **FR-01 布局**：服务器界面右侧成员栏（可折叠），按角色分组（hoist 角色单独成组，02 文档 Role 字段），组内按在线状态 + 名称排序；离线成员归入「离线」组（对标 Discord 成员栏）。
- **FR-02 成员条目**：头像（叠加在线状态点）、显示名（角色颜色）、状态图标（语音中/静音/受限徽章等）。
- **FR-03 受限徽章**：生效中 Restriction 的成员显示受限图标徽章，**默认开启**，跟随服务器配置可关（12 文档 AM.4）；徽章 hover 时普通成员仅见「该用户已被限制」，有权管理者可见维度摘要。
- **FR-04 可见性**：成员列表仅展示当前频道可见的成员集合（大服懒加载/虚拟滚动）；成员数据同步协议见 §8。
- **FR-05 搜索成员**：成员栏顶部搜索框按显示名/用户名过滤。

### 3.2 成员卡片

- **FR-06 卡片内容**：点击成员弹出卡片：头像横幅、显示名/用户名、角色标签列表、加入时间；本人卡片附加「编辑资料」入口（01 文档）。
- **FR-07 管理入口**：按操作者权限动态显示管理区块：修改昵称（`MANAGE_NICKNAMES`）、踢出（`KICK_MEMBERS`）、封禁（`BAN_MEMBERS`）、限制（`MODERATE_MEMBERS` 或细分节点，12 文档 AK）、语音管理（`MUTE_MEMBERS` / `DEAFEN_MEMBERS` / `MOVE_MEMBERS`）。无对应权限的项不渲染（不置灰隐藏语义，对标 Discord）。
- **FR-08 层级前置判断**：目标成员最高角色 position ≥ 操作者时，踢出/封禁/限制入口置灰并 tooltip「无法管理角色等级高于或等于你的成员」（02 文档 §4 层级规则）；目标为所有者时管理区块整体不显示（系统管理员除外，12 文档 AK）。
- **FR-09 自我保护**：本人卡片不显示踢出/封禁/限制入口（12 文档 AK.5 禁止自限）。
- **FR-10 受限状态区块**：卡片内显示目标成员生效中的限制：当事人视角见 FR-24；管理者视角显示完整列表（维度、作用域、剩余时间），每条带「解除」按钮（有权者）。

### 3.3 踢出（Kick）与封禁（Ban）

- **FR-11 踢出**：需 `KICK_MEMBERS`（02 文档 bit 1）+ 层级允许；确认弹窗含成员名与可选原因输入；踢出后成员离开服务器但可通过邀请再加入（对标 Discord Kick 语义）。
- **FR-12 封禁**：需 `BAN_MEMBERS`（02 文档 bit 2）+ 层级允许；确认弹窗红色警示：「将把 xxx 移出服务器并阻止其再次加入」+ 原因输入；Ban Member 独立于 Restriction（12 文档 AG.4/AO.3），是全服踢出+禁入。
- **FR-13 Ban 联动清理**：封禁成功后，该用户在本服的全部 Restriction 由服务端失活归档（12 文档 AO.3）；客户端收到相应事件后清理本地限制状态缓存。
- **FR-14 封禁列表**：服务器设置中「封禁列表」页（`BAN_MEMBERS` 可见）：被封禁用户、原因、操作人、时间，支持解封（对标 Discord Bans 设置页）。API 见 §8 待补充。
- **FR-15 被踢/被封的当事人表现**：收到相应 Gateway 事件后，该服务器从左侧服务器列表移除，若正处于该服界面则退回主页并 toast「你已被移出服务器 xxx」；封禁时使用邀请重新加入将被服务端拒绝，客户端展示拒绝原因。

### 3.4 施加限制（管理端 UI）

- **FR-16 入口**：成员卡片「限制」按钮、成员右键菜单「限制…」、语音成员条目右键快捷项（协管窄入口见 FR-22）。
- **FR-17 限制表单**（对标 Discord Timeout 弹窗，扩展为多维）：
  - **维度**：文字「禁止查看 / 禁止发言」、语音「禁止收听 / 禁止发言」多选框，按 scope 联动可选项（12 文档 AH.3 非法组合表：TEXT 作用域仅 view/send_text，VOICE 作用域仅 listen/speak_voice）；
  - **作用域**：单选——「本频道 / 指定频道（频道选择器）/ 全服文字 / 全服语音」，映射 `TEXT_CHANNEL | VOICE_CHANNEL | GUILD_ALL_TEXT | GUILD_ALL_VOICE`；
  - **时长**：预设档位 60 秒 / 5 分钟 / 1 小时 / 1 天 / 7 天 / 28 天 + 自定义（最短 60s，最长默认 28 天，12 文档 AI.3）；「长期（无到期）」选项仅在 kind=CHANNEL_BAN 或操作者具备特许权限时可选；
  - **原因**：文本框，**默认必填**、≤512 字符（12 文档 AI.1/AI.2），并提示「原因将对当事人可见」；
  - **类型**：普通制裁（SANCTION）默认；「频道封禁（CHANNEL_BAN，长期）」作为高级选项（单频道 scope 时可选，12 文档 AG.3）。
- **FR-18 蕴含规则即时反馈**：勾选「禁止查看」时自动勾选并锁定「禁止发言」；勾选「禁止收听」时自动勾选并锁定「禁止发言（语音）」，旁注「禁看即禁发 / 禁听即禁说」（12 文档 AH.4/AH.5）。
- **FR-19 提交**：`POST /guilds/{gid}/restrictions`（12 文档 AJ），body 含 target/scope/channel_id/deny/kind/reason/expires_at；成功后表单关闭，成员条目即时出现受限徽章。首期无批量多人（12 文档 AJ.5），表单单目标。
- **FR-20 修改与解除**：管理者可对生效中记录：修改 `expires_at` / `reason`（`PATCH`，**不可改 scope/channel/target**，改需解除重建，12 文档 AJ.4——UI 中 scope 等字段在编辑态只读并注明）；解除用 `DELETE`（lift）需二次确认。
- **FR-21 快捷静音语义**：语音成员右键「服务器静音」类快捷操作底层创建/解除 Restriction（`VOICE_CHANNEL` + `speak_voice`，短时或会话级，12 文档 AO.1）；UI 上呈现为一键开关，但在管理列表中以 Restriction 记录形式可见。
- **FR-22 协管窄权限**：仅持协管节点者（07 文档 3.5、12 文档 AK.2）：右键菜单只出现「本频道禁说」「抱下麦」；不出现全服作用域、文字维度选项（除非被授予扩展节点）；表单作用域锁定当前语音频道。
- **FR-23 错误映射**：服务端错误码映射为中文文案（12 文档 §11）：`INVALID_SCOPE_DENY`「维度与作用域不匹配」、`REASON_REQUIRED`「请填写原因」、`DURATION_OUT_OF_RANGE`「时长需在 60 秒到 28 天之间」、`CANNOT_RESTRICT_TARGET`「无法限制该成员（层级或所有者保护）」、`CANNOT_RESTRICT_SELF`「不能限制自己」。

### 3.5 当事人视角

- **FR-24 受限提示**：当事人在受影响界面看到完整信息（12 文档 AM.1）：
  - 文字禁发：输入框置灰 + 横幅「你已被禁止在此频道/本服务器发言 · 原因：xxx · 解除时间：xx」（长期则显示「长期」）；
  - 语音禁说：麦克风按钮锁定态 + tooltip 同上；舞台中不可申请上麦；
  - 语音禁听：尝试加入语音时被拒并弹窗说明；若正在房内被施加，收到断开后弹窗说明（12 文档 AL.3：禁听=禁止 join，已在房强制 disconnect）；
  - 全服限制：服务器名旁显示受限标识，进入任意对应类型频道均显示横幅。
- **FR-25 我的限制列表**：用户可在服务器菜单「我的限制」查看本服生效中的全部限制（`GET /guilds/{gid}/restrictions/@me`，12 文档 AJ），逐条显示维度、作用域、原因、到期时间。
- **FR-26 实时解除**：收到 `RESTRICTION_LIFT`（或过期推送，12 文档 AN.2）后：恢复输入框/麦克风可用、移除横幅、toast「你的限制已解除」；到期时间以服务端 UTC 为准（12 文档 AN.3），客户端倒计时仅为展示、以事件为最终依据。
- **FR-27 禁看表现**：被禁看的文字频道：从频道列表**直接消失**（收到 RESTRICTION_CREATE 后本地移除，且服务端 API 404 + Gateway 停止推送，12 文档 §6.2、07 文档专项 4 注意 1）；**不显示**「你被禁止查看 xx 频道」的频道级提示（防存在性泄露语义与频道一致）；但「我的限制」列表（FR-25）中当事人仍可看到该记录（服务端 @me 接口返回为准）。

### 3.6 他人视角

- **FR-28 脱敏展示**：其他成员对受限者仅见受限徽章与「该用户已被限制」文案（12 文档 AM.2）；**不展示** reason、维度细节、到期时间。
- **FR-29 语音房内表现**：被禁说成员在语音成员列表显示禁说图标（他人可见图标但不见原因）；被自动禁说（CAPACITY_QUEUE）显示排队图标（区别于制裁，见 FR-31）。

### 3.7 限制来源区分

- **FR-30 三种来源**（07 文档专项 3 注意 2 / 专项 4 注意 2、12 文档 AO）：

| 来源 | 本质 | 图标/文案 | 管理操作 |
|------|------|----------|---------|
| 手动 Restriction | 制裁记录（含快捷静音 AO.1） | 「已被限制」/ 管理者见维度详情 | PATCH/DELETE 记录 |
| `server_mute` / `server_deafen` | 成员状态字段（02 文档 §5.4，不是权限位；deafen 亦可用 listen_voice Restriction 表达，12 AO） | 「服务器静音/闭麦」 | MUTE_MEMBERS/DEAFEN_MEMBERS 开关 |
| 舞台自动禁说 `CAPACITY_QUEUE` | 超员队列状态，**不是 Restriction**（12 文档 AO.2、07 文档 3.1） | 「超员排队中，第 N 位」 | 不可手动解除，随名额自动释放 |

- **FR-31 管理 UI 区分**：语音频道管理面板中三类来源用不同图标与分区展示，禁止合并为同一「已禁言」状态；对 CAPACITY_QUEUE 用户不提供「解除限制」按钮（07 文档 3.1：有人离开按序自动解除）。
- **FR-32 来源字段**：客户端依赖服务端事件/状态中的 source 字段区分（07 文档专项 3 注意 2「自动禁说应标来源 CAPACITY_QUEUE」）；字段的正式定义见 §8。

### 3.8 限制列表与审计

- **FR-33 限制管理页**：服务器设置「限制管理」页（有权者可见）：`GET /guilds/{gid}/restrictions` 支持按 `user_id / channel_id / active / scope` 筛选（12 文档 AJ）；列表列：目标成员、维度、作用域、kind、原因、创建人、创建时间、到期时间、状态（生效/已解除/已过期），行内操作：编辑/解除。
- **FR-34 权限不足脱敏**：无完整查看权限者请求详情时服务端字段脱敏（12 文档 AJ 详情接口），客户端按返回字段渲染，不假设字段存在。
- **FR-35 审计日志页**：服务器设置「审计日志」页，需 `VIEW_AUDIT_LOG`（02 文档 bit 7）：展示管理操作流水（Restriction 创建/解除/过期、Kick、Ban、消息删除、编辑历史访问等，服务端审计范围为准：12 文档 §12、13 文档 AQ.3/AS.5）；支持按操作人、操作类型、时间筛选。审计查询 API 见 §8 待补充。
- **FR-36 多条叠加显示**：同一成员多条限制允许重叠、生效为 deny 并集（12 文档 AI.4）；管理 UI 逐条展示所有记录，当事人横幅显示合并后的最严格效果 + 最晚到期时间。

## 4. UI / UX 要求

- **UX-01 危险操作分级**：踢出为普通确认；封禁与「长期限制」为红色危险确认，需明示后果；解除限制为普通确认。
- **UX-02 限制表单可用性**：维度与作用域联动即时刷新（选全服文字后语音维度不可勾），非法组合在客户端不可构造（服务端 400 仅为兜底）。
- **UX-03 时长展示**：所有到期时间同时显示相对（「23 小时后」）与绝对（本地时区换算自服务端 UTC）格式。
- **UX-04 受限徽章克制**：徽章使用小尺寸单色图标，不给受限者施加羞辱性视觉；服务器配置关闭徽章时全员不显示（12 文档 AM.4）。
- **UX-05 管理动作可撤销感**：施加限制成功后的 toast 附带「撤销」快捷按钮（5s 内点击即调用 DELETE lift）。
- **UX-06 键盘与右键一致性**：成员卡片与右键菜单的管理项集合一致，权限不足项不渲染。
- **UX-07 语音房管理密度**：语音成员条目 hover 出现快捷禁说/抱下（按权限），长按/右键出完整菜单，操作 1–2 次点击可完成（对标 Discord 语音右键菜单效率）。
- **UX-08 视角切换测试要求**：设计稿需分别给出当事人/他人/管理者三视角的同一场景对照。
- **UX-09 通知**：当事人被施加/解除限制时收到应用内通知（横幅+通知中心），文案含维度与到期时间；被踢/被封收到系统级通知。

## 5. 与服务端的交互

| 交互 | API / 事件 | 权限 | 出处 |
|------|-----------|------|------|
| 创建限制 | `POST /guilds/{gid}/restrictions` | 系统管任意；服管/`MODERATE_MEMBERS` 层级内；协管窄节点 | 12 AJ、AK |
| 限制列表 | `GET /guilds/{gid}/restrictions?user_id=&channel_id=&active=&scope=` | 管理权限；不足则脱敏 | 12 AJ |
| 限制详情 | `GET /guilds/{gid}/restrictions/{id}` | 同上 | 12 AJ |
| 我的限制 | `GET /guilds/{gid}/restrictions/@me` | 当事人 | 12 AJ |
| 修改限制 | `PATCH /guilds/{gid}/restrictions/{id}`（仅 expires_at/reason） | 同创建 | 12 AJ.4 |
| 解除限制 | `DELETE /guilds/{gid}/restrictions/{id}` | 同创建 | 12 AJ |
| 限制事件 | Gateway `RESTRICTION_CREATE` / `RESTRICTION_UPDATE` / `RESTRICTION_LIFT`（当事人必推；管理订阅可选） | — | 12 AL.5 |
| 踢出/封禁 | Kick/Ban REST（路径待 OpenAPI，见 §8） | `KICK_MEMBERS` / `BAN_MEMBERS` + 层级 | 02 bit 1/2、§4 |
| 权限刷新 | Gateway `PERMISSIONS_UPDATE` 或重拉 members/@me | — | 02 §9 |
| 语音断开 | 禁听生效时服务端 disconnect + caps 变更 | — | 12 AL.3/AL.5 |

关键约定：

1. Restriction 只收紧、叠加在 RBAC 之后（12 AL.1、02 §11.1）；`ADMINISTRATOR` **不绕过** Restriction（12 §6.1），客户端权限展示逻辑须按「RBAC bits → Restriction 并集收紧」顺序计算本地缓存。
2. 禁看频道 API 一律 404 且 Gateway 不推（12 §6.2、06 §8），客户端所有 404 处理统一为「不可见」，不区分「不存在/无权限」。
3. 过期由服务端定时扫描 + 惰性判定（12 AN.1），过期推送 lift 事件；客户端不得以本地倒计时自行解除限制态，仅可展示倒计时。
4. 所有管理操作最终裁决在 Newt-Server，客户端置灰/隐藏仅为体验优化（02 §8）。

## 6. 边界与异常情况

| 场景 | 客户端行为 |
|------|-----------|
| 限制表单提交时目标已被更高优先级操作（已被 Ban） | 服务端报错 → 提示并刷新成员状态 |
| 操作者权限在表单打开期间被回收 | 提交返回 403 → 关闭表单、toast、触发权限重拉 |
| 当事人正处于被禁看频道界面 | 收到 RESTRICTION_CREATE 后立即退出该频道视图、从列表移除，toast 使用通用文案「频道不可用」 |
| 当事人在语音中被全服禁听 | 收到 disconnect：退出语音 UI，弹窗显示原因与到期时间（当事人可见 reason） |
| 同一用户叠加多条限制、其中一条解除 | 剩余并集仍生效：横幅按 FR-36 重算，不误恢复 |
| PATCH 尝试修改 scope（异常路径） | 客户端不提供入口；兜底 400 提示「作用域不可修改，请解除后重新创建」 |
| expires_at 早于当前时间（时钟偏差） | 以服务端校验为准；客户端表单校验用服务器时间偏移量修正 |
| 协管对非本频道成员操作 | 入口不出现；兜底 403 |
| 系统管理员限制所有者 | 客户端对 system_admin 账号放开所有者保护入口（12 AK：系统管可限所有者，必审计） |
| 受限徽章配置被服管关闭 | 收到配置变更后全员徽章即时隐藏（FR-03/UX-04） |
| CAPACITY_QUEUE 用户被尝试手动解除 | 无入口（FR-31）；随队列自动释放，图标自动消失 |
| Ban 后又收到该用户的 Restriction 事件（乱序） | 以成员已不在服为准，丢弃并清理缓存（FR-13） |
| 审计页数据量大 | 分页 + 时间范围默认最近 7 天 |

## 7. 验收标准

1. 成员列表按角色分组正确，受限成员显示徽章；服配置关闭徽章后全员不显示。
2. 管理员 A（position 高）可对成员 B 打开限制表单；对 position ≥ 自己的 C 入口置灰；对所有者不显示管理区块；对自己无限制入口。
3. 施加「本文字频道禁发 24h + 原因」后：B 端输入框 1s 内置灰并显示原因与到期时间；其他成员 D 仅见徽章与「该用户已被限制」，抓包确认 D 收到的数据不含 reason。
4. 勾选「禁止查看」时「禁止发言」自动锁定勾选；构造非法组合（语音作用域勾文字维度）在 UI 上不可能完成。
5. 时长选 30 秒被表单拦截（最短 60s）；29 天被拦截（最长 28 天）；不填原因提交被拦截。
6. 施加「单文字频道禁看」后：B 的频道列表该频道消失、历史/消息 API 返回 404、Gateway 不再推送（联调验证）；B 在「我的限制」中可见该记录。
7. 全服禁听：B 正在语音中被施加后自动断开并弹窗展示原因；尝试再加入任意语音频道被拒。
8. 到期自动解除：设置 60s 限制，到期后 B 收到 lift 事件、输入框自动恢复、收到解除通知；全程无需手动刷新。
9. 快捷静音：管理员右键语音成员「服务器静音」，限制管理页出现对应 Restriction 记录（VOICE_CHANNEL + speak_voice）；再次点击解除后记录变为已解除。
10. 来源区分：同一语音房内制造三种状态（手动禁说、server_mute、第 51 人 CAPACITY_QUEUE），管理面板三者图标/文案/可操作性均不同；CAPACITY_QUEUE 无解除按钮，且有人退出后按序自动恢复。
11. 协管账号：右键菜单仅「本频道禁说/抱下」，无全服与文字选项；操作生效并出现在限制列表（创建人为协管）。
12. Kick：B 被踢后其客户端服务器列表移除该服并 toast；B 可经邀请重新加入。Ban：B 无法重新加入，且其原有 Restriction 在限制管理页变为失效归档；解封后可再加入。
13. 审计：持 `VIEW_AUDIT_LOG` 的账号可在审计页看到上述第 3/9/12 步操作的完整流水（操作人、目标、字段）；无该权限账号看不到审计入口。
14. 修改限制：编辑弹窗中 scope/channel/target 只读；改 expires_at 成功后当事人横幅时间即时更新。
