## 1. 功能概述

### 1.1 目标

在 NewtSpeak 中补齐社交关系层，使桌面客户端具备对标 Discord 的完整能力：

1. **隐私与安全设置**：控制谁能加好友、谁能私信、资料可见性、活动状态暴露等。
2. **好友系统**：按用户名添加、请求/接受/拒绝、列表与在线状态、备注、移除、拉黑。
3. **私信（DM）**：一对一私信、消息请求收件箱、关闭会话、与公屏消息共用渲染与通知管线。
4. **群组私信（Group DM，P1）**：多人会话创建/邀请/离开/改名。

### 1.2 产品边界

| 域 | 归属 | 说明 |
|----|------|------|
| 本功能 | **本文** | 隐私策略、关系图、DM 频道与消息请求 |
| 服内「允许本服成员私信」开关 | [17](./17-每服务器客户端个人设置.md) FR-18 | 服级覆盖，裁决时作为输入 |
| 消息收发/Markdown/附件 | [05](./05-文本消息.md) / [07](./07-附件与文件.md) | DM 复用同一套消息体验 |
| 未读与系统通知 | [15](./15-通知与未读.md) | 扩展 DM 与好友请求通知 |
| 用户资料卡 | [01](./01-账号与用户体系.md) | 增加「加好友 / 发消息 / 屏蔽」操作 |
| 语音通话 1:1 | 预留 P2 | 首期 DM **不**强制含语音通话；架构预留 `DM` 通话入口 |

### 1.3 与服务器频道的差异

| 维度 | 服务器文字频道 | 私信 / 群组私信 |
|------|----------------|-----------------|
| 归属 | `guild_id` 非空 | `guild_id` 为空（或专用 DM 命名空间） |
| 权限 | RBAC + Overwrite + Restriction | **关系与隐私策略**裁决（好友/共同服/黑名单/消息请求） |
| 成员 | Guild Member | 固定参与者集合（1:1 两人；群组最多 N 人） |
| 可见性 | VIEW_CHANNEL | 仅参与者；关闭 DM 仅隐藏列表不删历史（可配置） |
| 搜索 | 全系统可见范围 | 仅自己参与的 DM（06 扩展） |

### 1.4 设计原则

1. **服务端权威**：能否加好友、能否开 DM、消息是否进「请求」箱，一律服务端裁决；客户端预检仅优化体验。
2. **最小暴露**：隐私错误对外统一为「无法完成操作」类文案，**不**区分「对方把你拉黑」与「对方关了私信」（对标 Discord 防探测）。
3. **复用消息栈**：DM 的消息、附件、编辑、反应、已读与 Gateway 事件与公屏同协议族，避免第二套聊天引擎。
4. **Home 为社交入口**：服务器栏最上方「主页」进入好友 + 私信列表（对标 Discord Home）。

## 3. 概念与数据模型

### 3.1 关系状态（Relationship）

对任意有序用户对，从「我」视角的关系类型（对标 Discord Relationship Type）：

| 值 | 含义 | 对称性 |
|----|------|--------|
| `none` | 无关系 | — |
| `friend` | 好友 | 对称 |
| `pending_outgoing` | 我发出的好友请求 | 对方见 `pending_incoming` |
| `pending_incoming` | 对方发来的请求 | 我发出侧为 `pending_outgoing` |
| `blocked` | 我屏蔽了对方 | **不对称**；对方对我可能仍是 none/friend/… |

规则：

- 成为 `friend` 时清除双方 pending。
- `blocked` 时：若曾是好友则解除好友；取消对方 pending；拒绝对方新请求与新 DM。
- 双向拉黑允许；解除屏蔽不自动恢复好友。

**存储建议（服务端）**：

```text
relationships (
  id, user_id, target_user_id,
  type,           -- friend | pending_outgoing | blocked  （incoming 由对端 pending_outgoing 投影）
  nickname,       -- 可选：我对好友的备注名
  created_at, updated_at
  UNIQUE(user_id, target_user_id)
)
```

查询「incoming」= `WHERE target_user_id = me AND type = pending_outgoing`（对端记录）。

### 3.2 隐私策略文档（Privacy Settings）

账号级，跨端同步（可挂在 `user_settings.privacy` 或独立表；**推荐独立表 + 设置 API 镜像**，便于服务端裁决）：

```ts
type PrivacySettings = {
  /** 谁可以向我发送好友请求 */
  friendRequestFrom: "everyone" | "mutual_friends" | "mutual_guilds" | "nobody"
  /** 默认谁可以给我发私信（全局默认；服级可收紧） */
  dmFrom: "everyone" | "friends" | "mutual_guilds" | "nobody"
  /**
   * 非好友私信是否进入「消息请求」而非直接会话
   * true = 非好友一律 Message Request（对标 Discord Filter）
   */
  messageRequestFilter: boolean
  /** 是否在资料卡等展示「共同服务器」（对非好友） */
  showMutualGuilds: boolean
  /** 是否允许非好友查看我的完整资料（bio/banner 等，P1） */
  publicProfileToNonFriends: boolean
  /** 活动/正在玩状态是否对好友可见（P2 预留） */
  showActivityTo: "everyone" | "friends" | "nobody"
  /** 在线状态对谁可见：所有人 / 仅好友 / 隐身等价由 presence 控制 */
  // 首期：在线状态仍由 presence（含隐身）主导，本字段 P1
}
```

**服级覆盖**（UI 入口在文档 17；存储已由 Server-16 BM.2/§13-D7 定稿为**服务端一等字段** + 专用 API，不在 `user_settings` JSON）：

```ts
// PUT /users/@me/guilds/{guildId}/privacy { allow_dm: boolean }  // 默认 true
// GET /users/@me/privacy 响应含 guild_overrides: { [guildId]: { allow_dm } }
```

语义：关闭后，**仅因「共同在该服」而获得的私信资格失效**；已是好友的 DM **不受影响**。

### 3.3 DM 频道模型

扩展频道类型（服务端 `ChannelType`）：

```text
TEXT | VOICE | CATEGORY | DM | GROUP_DM
```

| 字段 | DM | GROUP_DM |
|------|-----|----------|
| `guild_id` | null | null |
| `type` | `DM` | `GROUP_DM` |
| 参与者 | 恰好 2 人 | 2–10 人（上限可配，默认 10） |
| 名称 | 无（展示对方显示名） | 可选自定义；空则拼接成员名 |
| 图标 | 对方头像 | 拼接头像或自定义（P1） |
| 创建 | 首次合法私信时 get-or-create | 主动创建 |

**参与者表**：

```text
channel_recipients (
  channel_id, user_id,
  joined_at,
  hidden,           -- 用户「关闭私信」：列表隐藏，历史仍在
  last_read_message_id,
  message_request,  -- true：仍在请求箱，未接受
  muted, muted_until,
  UNIQUE(channel_id, user_id)
)
```

**1:1 唯一性**：对用户对 `(min_id, max_id)` 全局唯一一条 `DM` 频道（服务端唯一索引），避免重复会话。

### 3.4 消息请求（Message Request）

当发送方被允许「尝试联系」但未达「直接会话」门槛时：

- 创建/复用 DM 频道，接收方 `message_request = true`。
- 接收方在「消息请求」列表看到会话；**未接受前**发送方可能仍可发有限条数（防刷：见 §8 频控），或仅允许首条（产品默认：**接受前发送方可再发，但接收方未读计入请求箱且可一键拒绝+屏蔽**）。
- 接受：`message_request = false`，会话进入正常私信列表。
- 拒绝/忽略：对接收方 `hidden = true` 且可删请求视图；可选同时 block。
- **不**向发送方暴露「对方已读请求但未接受」。

### 3.5 实体关系图

```text
User ──< relationships >── User
  │
  ├── privacy_settings (1:1)
  │
  └── channel_recipients >── Channel (type DM | GROUP_DM)
                                   └── messages （复用 message 表）
```

## 4. 隐私设置（产品 FR）

### 4.1 设置入口

- **FR-P01** 用户设置（16）左侧导航增加正式分栏 **「隐私与安全」**（01/16 已预留文案），不再仅占位。
- **FR-P02** 分栏结构：
  1. 好友请求来源  
  2. 服务器私信默认 / 说明「可在每个服务器个人设置中覆盖」  
  3. 消息请求过滤  
  4. 资料可见性  
  5. 屏蔽列表管理  
  6. （P1）数据与安全说明链接  
- **FR-P03** 服级开关入口：服务器个人设置 → 隐私（17 FR-18）；与全局 `dmFrom` **同时满足**才允许「因共同服务器」发起的新 DM。

### 4.2 默认值（安全默认）

| 项 | 默认 | 理由 |
|----|------|------|
| `friendRequestFrom` | `mutual_guilds` | 减少陌生人骚扰，仍方便同服社交 |
| `dmFrom` | `friends` | 默认仅好友直接私信 |
| `messageRequestFilter` | `true` | 非好友进请求箱 |
| `allowDmsFromMembers`（每服） | `true` | 与 Discord 默认一致；用户可关 |
| `showMutualGuilds` | `true` | 便于辨认身份 |
| `publicProfileToNonFriends` | `true` | 基础资料可看；邮箱永不暴露 |

### 4.3 裁决矩阵：谁可以加我好友

记发送方 S，接收方 R。允许发送好友请求当且仅当：

1. S 未屏蔽 R，R 未屏蔽 S；
2. 当前不是已是好友 / 已有 pending；
3. R 的 `friendRequestFrom`：
   - `everyone` → 通过；
   - `mutual_friends` → 存在共同好友；
   - `mutual_guilds` → 存在共同服务器；
   - `nobody` → 拒绝。

### 4.4 裁决矩阵：谁可以给我发「新」私信

记发送方 S，接收方 R。目标：创建或向 R 侧未 hidden 的 DM 投递**首条/新会话**。

按序：

```text
1. 任一方 block 对方 → 拒绝（对外统一文案）
2. 已是好友 → 允许直接会话（忽略 dmFrom 中的 friends 以上限制）
3. 已存在非 message_request 的双向可见 DM → 允许继续发送
4. 检查 R.dmFrom：
   - nobody → 拒绝
   - friends → 非好友拒绝（除非步骤 2）
   - mutual_guilds / everyone → 继续
5. 若资格依赖「共同服务器」：
   - 取 S∩R 共同服集合 G
   - 对 R：存在 g∈G 使得 R.allowDmsFromMembers[g] !== false
   - 否则拒绝（「对方不接受来自服务器成员的私信」可对 S 模糊化）
6. 若 R.messageRequestFilter && 非好友 → 进入 Message Request
   否则 → 直接会话
7. dmFrom=everyone 且无共同服：仍允许（纯用户名私信）；建议强制走 Message Request
```

### 4.5 屏蔽列表 UI

- **FR-P04** 「隐私与安全」内「屏蔽」列表：搜索、解除屏蔽；显示屏蔽时间。
- **FR-P05** 资料卡 / 成员右键 / 私信顶栏菜单均提供「屏蔽」；二次确认。
- **FR-P06** 屏蔽后：本地移除好友关系展示、关闭相关 DM 通知、列表可「显示已屏蔽的私信」高级开关（默认关）。

## 5. 好友系统（产品 FR）

### 5.1 Home 信息架构（对标 Discord）

服务器栏顶部 **主页** 图标（Home）选中时，左侧栏切换为：

```text
┌ 私信 ──────────── [+] ┐
│ 好友                   │  ← 主内容区 Tab
│ ─────────────────      │
│ 置顶私信…              │
│ 最近私信列表           │
│  Alice · 在线          │
│  Bob · 昨天            │
└────────────────────────┘
```

主内容区 Tab：

| Tab | 内容 |
|-----|------|
| 在线 | 好友中非隐身/离线者 |
| 全部 | 全部好友 |
| 待处理 | 收到的 + 发出的请求 |
| 已屏蔽 | 快捷入口（或仅在设置） |
| 添加好友 | 按用户名添加表单 |

### 5.2 添加好友

- **FR-F01** 输入 **用户名**（全局唯一，01）；可选未来支持 `用户名#识别码` 若产品引入 discriminator。
- **FR-F02** 校验：不能加自己；已是好友提示「你们已经是好友」；已 pending 提示「请求已发送」。
- **FR-F03** 成功：toast「好友请求已发送」；失败统一「无法发送好友请求」+ 可选原因码映射（用户不存在可对存在性做有限提示：Discord 对错误用户名会提示找不到——NewtSpeak **允许**「找不到该用户」，**不允许**「对方关闭了好友请求」的精确原因）。
- **FR-F04** 资料卡按钮：非好友显示「添加好友」；pending 显示「请求已发送」；好友显示「发消息」。

### 5.3 接受 / 忽略 / 取消

- **FR-F05** 待处理列表：收到的请求 → 接受 / 忽略；发出的 → 取消。
- **FR-F06** 接受后双方 `friend`；Gateway 推送关系更新。
- **FR-F07** 忽略：删除该 pending，不通知对方。
- **FR-F08** 取消发出的请求：删除己方 pending_outgoing。

### 5.4 好友列表与展示

- **FR-F09** 展示：头像、显示名、用户名、presence、自定义状态（P1）、备注名（有则优先显示备注）。
- **FR-F10** 排序：在线优先，其次显示名；离线沉底。
- **FR-F11** 右键：发消息、邀请加入服务器（有 CREATE_INVITE 时）、备注、移除好友、屏蔽、资料卡。
- **FR-F12** 移除好友：二次确认；不自动删 DM 历史。
- **FR-F13** 备注名：仅自己可见，最长 32 字，存 relationship.nickname。

### 5.5 好友在线状态

- **FR-F14** READY 时下发好友列表 + 当前 presence 快照；之后 `PRESENCE_UPDATE` 仅对「对我可见状态的用户」推送。
- **FR-F15** 隐身：对好友显示离线（01 FR-20）；不泄露真实在线。
- **FR-F16** 非好友的 presence：仅在共同服务器成员列表场景下按服订阅规则推送；Home 好友列表不出现非好友。

### 5.6 通知

- **FR-F17** 新好友请求：系统通知 + 主页图标角标（待处理数）；勿扰时抑制横幅/声音（15 FR-14）。
- **FR-F18** 请求被接受：可选轻量 toast「Alice 已接受你的好友请求」（默认开，可在通知设置关）。

## 6. 私信功能（产品 FR）

### 6.1 列表与导航

- **FR-D01** 私信列表按「最近消息时间」降序；支持置顶（P1，本地或云端 `pinned_dm_ids`）。
- **FR-D02** 每行：头像（含 status）、标题、最后一条预览、时间、未读点/@ 数。
- **FR-D03** 「关闭私信」：会话从列表移除（`hidden=true`），**不删除**消息；再次收到消息或主动打开时取消 hidden。
- **FR-D04** 从好友/资料卡「发消息」：`POST /users/@me/channels { recipient_id }` get-or-create → 跳转。
- **FR-D05** 消息请求独立分组或子页，与正常私信视觉区分（对标 Discord Message Requests）。

### 6.2 会话内体验

- **FR-D06** 消息区复用 05 全套能力：发送、编辑、删除、回复、反应、Markdown、附件、typing、乐观回显。
- **FR-D07** 顶栏：对方头像/名、presence、语音通话按钮（P2 占位灰置）、置顶搜索、成员资料、更多菜单（固定/关闭/屏蔽/移除好友）。
- **FR-D08** 1:1 中 @提及仅对方与自己；无 @角色/@everyone。
- **FR-D09** 权限：无 RBAC；「能发」= 仍是 recipient 且未被对方 block 且会话未因隐私拒绝；输入框在被 block 或离开群组后禁用。
- **FR-D10** 附件大小：走**平台默认用户 DM 限额**（建议与系统默认附件上限一致或略低，由系统管配置；**不**走某服的服级上限）。
- **FR-D11** 搜索：06 增加 `in:dm` / 私信范围；默认全局搜索含 DM（可设排除）。

### 6.3 未读与通知

- **FR-D12** DM 未读计入：
  - 主页图标未读白点 / 提及红点；
  - 全局 Dock 角标（与 15 一致，含 DM 提及与可选「全部 DM 未读」策略）。
- **FR-D13** 通知决策扩展 15 FR-10：
  - 增加实体类型 `dm` / `group_dm`；
  - 默认层级建议：**全部消息**（对标 Discord DM 默认更灵敏）；用户可在通知设置对「私信与群组私信」设全局默认；
  - 单会话静音同 15 定时静音。
- **FR-D14** 消息请求：**默认不弹**系统通知横幅（或合并为「你有新的消息请求」一条），避免陌生人轰炸；角标可显示请求数。

### 6.4 群组私信（P1）

- **FR-G01** 从私信列表 `+` → 选择最多 9 名好友创建群组（自己+9）。
- **FR-G02** 群内：改名、加人（好友或已在群）、踢人（仅群主？**建议无群主，任何人可邀请，人满拒绝；离开即可**——对标 Discord 较松模型）、离开群组。
- **FR-G03** 系统消息：A 邀请了 B、A 离开了群组、群名变更。
- **FR-G04** 图标：无自定义时最多 4 头像拼接。

### 6.5 与语音（P2 预留）

- 1:1 / 群组「开始语音通话」走独立 call 状态机，**不**复用公屏语音频道；本文仅要求 UI 占位与权限预留，详细另立文档。

## 7. 客户端 UI / UX 要求

1. **Home 与服务器互斥选中态**：点主页清空当前 guild 焦点；点服务器离开 Home（对标 Discord）。
2. **空状态**：无好友 → 插画 +「添加好友」；无私信 →「选择好友开始聊天」。
3. **资料卡操作区**统一顺序：发消息 · 加好友 · 邀请 · 屏蔽 · 踢出（服管）… 按上下文显隐。
4. **危险操作**：屏蔽、移除好友需确认；关闭私信无需确认。
5. **键盘**：Home 内 `↑↓` 浏览私信列表，`Enter` 打开；Quick Switcher（⌘K）可搜好友与 DM。
6. **无障碍**：待处理角标有 aria-label「N 个待处理好友请求」；关系状态不只靠颜色。
7. **中文用户名搜索**：添加好友输入支持粘贴前后空格 trim。

## 8. 服务端 API 建议（立项清单）

> **已立项**：本节建议已由 Server-16《私信好友与隐私体系》定稿（含少量决议差异：无群主 Group DM、屏蔽后 DM 强制不投递、纯用户名私信强制走消息请求等，见 Server-16 §13）。实现以 Server-16 为准，本节保留为提案原文。
>
> 路径前缀示例：`/gapi/v1`（用户端）。错误码对外可映射模糊文案。

### 8.1 隐私

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/users/@me/privacy` | 读取隐私设置 |
| PATCH | `/users/@me/privacy` | 部分更新 |
| GET | `/users/@me/relationships` | 好友 + pending + blocked 列表 |
| POST | `/users/@me/relationships` | body: `{ username }` 或 `{ user_id }` 发请求 |
| PUT | `/users/@me/relationships/{user_id}` | body: `{ type: "friend" \| "blocked" }` 接受或屏蔽 |
| DELETE | `/users/@me/relationships/{user_id}` | 移除好友 / 取消请求 / 解除屏蔽（按当前类型） |
| PATCH | `/users/@me/relationships/{user_id}` | 备注名等 |

### 8.2 私信频道

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/users/@me/channels` | 我的 DM + GROUP_DM 列表（含 recipient 摘要、last_message） |
| POST | `/users/@me/channels` | `{ recipient_id }` → DM get-or-create；或 `{ recipients: [] }` → GROUP_DM |
| PATCH | `/channels/{id}/recipients/@me` | `{ hidden, message_request: false }` 关闭/接受请求 |
| PUT | `/channels/{id}/recipients/{user_id}` | 群组邀请 |
| DELETE | `/channels/{id}/recipients/{user_id}` | 离开或移除 |
| PATCH | `/channels/{id}` | 群组改名等 |

消息收发继续：

- `POST/GET /channels/{id}/messages`（05/13）
- 已读 `POST /channels/{id}/ack`

### 8.3 Gateway 事件（建议）

| 事件 | 何时 |
|------|------|
| `RELATIONSHIP_ADD` | 新关系行（请求/好友/屏蔽） |
| `RELATIONSHIP_UPDATE` | 备注等 |
| `RELATIONSHIP_REMOVE` | 删除关系 |
| `CHANNEL_CREATE` | 新 DM/群组对自己可见时 |
| `CHANNEL_UPDATE` | 群名、recipient 变更 |
| `CHANNEL_DELETE` / 或 `CHANNEL_RECIPIENT_REMOVE` | 离开群组后对自己不可见 |
| `MESSAGE_CREATE` 等 | 与公屏相同；仅 recipient 收到 |
| `MESSAGE_REQUEST_CREATE`（可选） | 明确标记进请求箱，或复用 CHANNEL_CREATE + flag |

READY 附加：

```jsonc
{
  "relationships": [ /* ... */ ],
  "private_channels": [ /* DM/GROUP_DM 摘要 */ ],
  "privacy": { /* ... */ }
}
```

### 8.4 频控与安全

| 项 | 建议 |
|----|------|
| 好友请求 | 每用户每小时 ≤ 20；对同一目标冷却 24h |
| 消息请求未接受 | 发送方对同一会话 ≤ 5 条/天 或 总字数上限 |
| 新账号 | 注册 24h 内限制陌生人 DM（可配） |
| 举报 | P1：私信更多菜单「举报」→ 审计工单 |
| 内容 | 与公屏同样的违禁与附件策略 |

### 8.5 数据与合规

- 用户注销：匿名化或删除其 DM 消息与关系（策略与账号删除一致，01）。
- 导出（P2）：用户可申请导出私信（隐私合规）。

## 10. 关键时序

### 10.1 添加好友

```text
A 输入用户名 → POST /users/@me/relationships { username: "B" }
  ├─ 200 → A 本地 pending_outgoing；B 收到 RELATIONSHIP_ADD(pending_incoming)
  │        B 角标 +1；可选系统通知
  └─ 404/403 → 模糊错误提示
B 接受 → PUT .../relationships/{A} { type: "friend" }
  → 双方 friend；RELATIONSHIP_UPDATE/ADD；待处理角标 -1
```

### 10.2 好友发起私信

```text
A 点「发消息」→ POST /users/@me/channels { recipient_id: B }
  → 200 { channel }（已有则返回）
  → 客户端打开 channel；双方 CHANNEL_CREATE（若新建）
A 发消息 → POST /channels/{id}/messages → MESSAGE_CREATE 给 A、B
```

### 10.3 非好友 + 消息请求

```text
S 与 R 共同服，R.dmFrom=mutual_guilds，filter=true
S → POST /users/@me/channels { recipient_id: R }
  → 服务端创建 DM，R.recipient.message_request=true
R 客户端：进「消息请求」而非主列表
R 接受 → PATCH recipients/@me { message_request: false }
R 拒绝 → hidden + 可选 block
```

### 10.4 服级关闭私信

```text
R 在服 G 关闭 allowDmsFromMembers
S 与 R 仅共同服为 G，非好友
S 尝试 DM → 403 PRIVACY_DENIED（对外文案模糊）
S 与 R 已是好友 → 仍可 DM
```

### 10.5 屏蔽

```text
A block B → PUT relationship type=blocked
  → 删除 friend/pending；B 侧对 A 的后续好友/DM 失败
  → A 隐藏 B 的 message requests；可选停止接收 B 的 MESSAGE_CREATE（服务端不投递）
```

## 11. 边界与异常

| 场景 | 行为 |
|------|------|
| 用户改名 | 关系按 user_id；列表显示新名 |
| 注销账号 | 对端好友列表移除；DM 显示「已注销用户」占位 |
| 同时互发好友请求 | 服务端合并为直接成为好友（对标常见 IM） |
| 屏蔽后看历史 DM | 本地仍可打开只读；新消息不投递 |
| 群组成员全员离开 | 频道归档/硬删（服务端 GC） |
| 隐私设置多端冲突 | 以最后 PATCH 为准 + Gateway 更新 |
| 无共同服且 dmFrom=friends | 非好友无法私信 |
| 搜索到不可见 DM | 不出现（06 权限过滤扩展） |
| 被限制用户（服内 Restriction） | **不**自动限制全局私信；私信与服内处罚解耦 |
| 系统管理员 | 无特权读他人私信（隐私红线）；除非独立合规工具与审计 |

## 12. 验收标准

| # | 验收项 | 通过条件 |
|---|--------|----------|
| AC-01 | 隐私默认 | 新账号默认 mutual_guilds 好友请求 + friends 私信 + 请求过滤开 |
| AC-02 | 加好友全流程 | 发送→待处理→接受→双方列表可见在线状态 |
| AC-03 | 拒绝原因模糊 | 对方 nobody 时，发送方看不到精确「已关闭请求」 |
| AC-04 | 好友 DM | 一点发消息即可聊天；刷新会话仍在 |
| AC-05 | 消息请求 | 非好友共同服用户私信进请求箱；接受后进主列表 |
| AC-06 | 服级关私信 | 关后非好友同服无法新会话；好友不受影响 |
| AC-07 | 屏蔽 | 无法再请求/私信；解除后需重新请求好友 |
| AC-08 | 关闭私信 | 列表消失；对方再发后重新出现 |
| AC-09 | 通知 | 好友请求有角标；勿扰不弹横幅；DM 通知可静音单会话 |
| AC-10 | 消息能力 | DM 内编辑/回复/附件/反应与公屏一致 |
| AC-11 | Home 导航 | 主页与服务器切换正确；⌘K 可搜好友 |
| AC-12 | 多端 | 一端接受好友，另一端 READY/事件后列表一致 |
