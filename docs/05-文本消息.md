## 1. 功能概述

本文档定义 Owl-Desktop 文字频道消息体验的完整需求，覆盖：

- **消息发送与接收**：REST 发送 + Gateway 实时推送，`nonce` 幂等去重与本地乐观回显。
- **富文本渲染**：有限 Markdown（粗体/斜体/链接/行内代码/代码块等，服务端 13 文档 AP.2 定义的白名单），渲染层防 XSS。
- **@提及**：@用户、@角色、@everyone / @here，输入自动补全与高亮渲染，对标 Discord mention 体验。
- **表情与 emoji**：正文内嵌 emoji、emoji 选择器、emoji 反应（Reaction，服务端 13 文档 AV.1–2 首期支持）。
- **回复引用**：单层 `reply_to_id` 引用回复（13 文档 AP.6，完整线程为二期）。
- **消息编辑**：仅作者可编辑正文，UI 显示「已编辑 + 编辑次数」，编辑历史由服务端全文快照审计（07 文档 5B.4、13 文档 AS 系列）。
- **消息删除**：本人删除或 `MANAGE_MESSAGES` 删除他人消息；软删除后显示 tombstone 或直接移除。
- **消息历史加载**：需 `READ_MESSAGE_HISTORY`；无权限时只显示进入频道后的实时消息（13 文档 AR.3）。
- **无限滚动分页**：游标分页（`before` / `after`），向上滚动加载更旧消息。
- **发送失败重试**：本地队列、失败标红、手动/自动重试，`nonce` 保证不重复落库。
- **输入状态（typing indicator）**：「xxx 正在输入…」提示。
- **pin 置顶消息**：服务端 13 文档 AV.3–4 已明确 **置顶为二期**，本文仅做 UI 占位说明，详见 §8。

对标说明：整体交互严格对标 Discord 文字频道——消息按作者连续分组、hover 出现快捷操作栏、上箭头快速编辑最近一条消息、Esc 取消编辑、回复引用显示原消息摘要并可点击跳转；同时参考 KOOK 的中文输入法兼容与 @ 选择面板习惯。

## 2. 用户故事 / 使用场景

| 编号 | 用户故事 |
|------|----------|
| US-01 | 作为成员，我在文字频道输入一段带粗体和代码块的文字并回车发送，消息立即出现在消息流中，其他在线成员实时看到。 |
| US-02 | 作为成员，我输入 `@` 后弹出成员/角色补全面板，选择某人后发送，对方收到提及高亮与通知。 |
| US-03 | 作为成员，我发现刚发的消息有错别字，按上箭头进入编辑态改正后回车，所有人看到的消息更新，并带「(已编辑 ×1)」标记。 |
| US-04 | 作为成员，我 hover 别人的消息点「回复」，发送后我的消息上方显示被引用消息的摘要，点击摘要可跳回原消息。 |
| US-05 | 作为管理员（持 `MANAGE_MESSAGES`），我可以删除任何人的违规消息，但不能编辑他人消息正文。 |
| US-06 | 作为新加入且无 `READ_MESSAGE_HISTORY` 的成员，我进入频道后看不到历史消息，只能看到从进入时刻起的新消息，界面明确提示原因。 |
| US-07 | 作为成员，我在网络波动时发送消息失败，消息在本地标红并提供「重试 / 删除」，重试成功后不会产生重复消息。 |
| US-08 | 作为成员，我看到输入框上方显示「Alice 正在输入…」，得知对方正在回复。 |
| US-09 | 作为成员，我给别人的消息添加 👍 反应，所有人实时看到反应计数 +1。 |
| US-10 | 作为被施加「禁发」Restriction 的成员，我打开该频道时输入框置灰并显示禁发原因与到期时间（详见 08 文档）。 |

## 3. 功能需求明细（FR）

### 3.1 消息发送

- **FR-01 发送入口**：每个文字频道底部固定多行输入框；`Enter` 发送，`Shift+Enter` 换行（对标 Discord 默认行为，可在设置中互换）。
- **FR-02 长度限制**：正文最大 **4000 字符**（13 文档 AP.3，可配）；超出时输入框计数器变红、发送按钮禁用，显示「-N」超出字数（对标 Discord 计数器）。
- **FR-03 空消息拦截**：禁止正文与附件皆空（13 文档 AP.4）；仅附件无正文允许发送。
- **FR-04 nonce 幂等**：每次发送生成客户端唯一 `nonce`（13 文档 AR.6），随 `POST /channels/{id}/messages` 提交；用于乐观回显与 Gateway 回包去重。
- **FR-05 乐观回显**：点击发送后立即在消息流底部插入「发送中」态本地消息（半透明），收到 `MESSAGE_CREATE`（nonce 匹配）后替换为正式消息；对标 Discord 的 pending 消息灰显。
- **FR-06 发送权限前置**：客户端根据缓存权限位判断 `SEND_MESSAGES` 且无禁发 Restriction（13 文档 §4「发送权限」）；无权限时输入框置灰并显示占位文案（见 §4）。前置判断仅为体验优化，最终以服务端裁决为准。
- **FR-07 发送失败重试**：请求超时/5xx/网络断开时消息标红，右侧显示「重试」「删除」按钮；点击重试沿用同一 `nonce`，服务端幂等去重保证不重复。断网恢复后可配置自动重试一次。
- **FR-08 发送频率限流**：收到服务端 429 时按 `retry_after` 冷却，输入框上方显示「发送过快，请稍候 N 秒」（对标 Discord slowmode 提示样式）。

### 3.2 消息接收与消息流

- **FR-09 实时接收**：订阅 Gateway `MESSAGE_CREATE` / `MESSAGE_UPDATE` / `MESSAGE_DELETE` 事件（13 文档 AR.5），按事件类型插入/更新/移除消息流条目。
- **FR-10 消息分组**：同一作者在 7 分钟内的连续消息合并为一组，仅首条显示头像+昵称+时间（对标 Discord 分组规则）。
- **FR-11 时间分割线**：跨自然日插入日期分割线；存在未读时插入红色「新消息」分割线（对标 Discord NEW divider）。
- **FR-12 自动滚动**：视口位于底部时新消息自动滚到底；用户上翻阅读历史时不打断，改为底部浮动「↓ N 条新消息」按钮，点击回到底部。
- **FR-13 系统消息**：`type` 为系统消息（13 文档 AP.5）时以居中灰色样式渲染（如成员加入），不显示头像操作栏。

### 3.3 Markdown 富文本渲染

- **FR-14 渲染白名单**：仅渲染服务端定义的有限 Markdown 集：粗体 `**`、斜体 `*`、删除线 `~~`、行内代码 `` ` ``、代码块 ```` ``` ````（含语言高亮）、链接、引用 `>`、有序/无序列表；白名单最终以服务端「有限 MD 白名单表」为准（13 文档 §13），未定义的语法按纯文本显示。
- **FR-15 防 XSS**：渲染前经统一 sanitize 管线；禁止内联 HTML、`javascript:` 协议链接；链接一律 `noopener noreferrer` 并在系统默认浏览器打开。
- **FR-16 链接处理**：URL 自动识别为可点击链接；链接卡片预览（embed）依赖 `EMBED_LINKS` 权限位（02 文档 bit 14），服务端未提供 embed 抓取服务前，客户端仅做纯链接渲染并在 §8 标注待补充。
- **FR-17 代码块体验**：代码块右上角提供「复制」按钮，超过 20 行折叠并显示「展开」（对标 Discord 代码块交互）。

### 3.4 @提及（Mention）

- **FR-18 输入补全**：输入 `@` 弹出补全面板，按「本频道可见成员 → 角色 → everyone/here」分组，支持拼音/前缀模糊匹配，↑↓ 选择、Tab/Enter 确认（对标 Discord mention picker）。
- **FR-19 提及类型**：支持 `@用户`、`@角色`（角色标记为 mentionable 时，02 文档 Role 字段）、`@everyone`、`@here`；后两者及大规模角色提及需 `MENTION_EVERYONE` 权限（02 文档 bit 17），无权限时补全面板不出现对应项。
- **FR-20 提及渲染**：提及以蓝底胶囊样式渲染；本人被提及的消息整行加黄色高亮背景（对标 Discord mention highlight）；点击 @用户 弹出成员卡片（见 08 文档）。
- **FR-21 提及确认**：发送含 `@everyone` / `@here` 的消息前弹确认框显示将通知的人数（对标 Discord 二次确认）。
- **FR-22 提及序列化**：消息正文中提及以服务端约定的占位格式传输（如 `<@user_id>` / `<@&role_id>`），具体 wire format 见 §8 待补充。

### 3.5 表情与 emoji

- **FR-23 emoji 输入**：输入框右侧 emoji 按钮打开选择器（分类 + 搜索 + 最近使用）；输入 `:` + 2 字符以上触发 shortcode 补全（对标 Discord `:joy:` 补全）。
- **FR-24 emoji 渲染**：正文 Unicode emoji 按统一表情集渲染；纯 emoji 消息（≤27 个字符全为 emoji）放大显示（对标 Discord jumbo emoji）。
- **FR-25 emoji 反应**：hover 消息操作栏「添加反应」打开选择器；调用 `PUT/DELETE /channels/{id}/messages/{mid}/reactions/{emoji}/@me`（13 文档 AV），需 `ADD_REACTIONS` 权限（02 文档 bit 6）。
- **FR-26 反应展示**：消息下方以「emoji + 计数」胶囊排列；本人已反应的胶囊高亮描边，点击切换添加/移除；hover 显示反应者列表；实时响应 `MESSAGE_REACTION_ADD / REMOVE` 事件。
- **FR-27 自定义服务器表情**：服务端未定义自定义表情上传/管理（`MANAGE_EXPRESSIONS` 仅预留位），首期客户端不做，见 §8。

### 3.6 回复引用

- **FR-28 发起回复**：hover 操作栏「回复」或右键菜单进入回复态；输入框上方显示被回复消息摘要条，带「×」可取消（对标 Discord reply bar）。
- **FR-29 回复渲染**：带 `reply_to_id` 的消息上方显示被引用消息的缩略行（作者头像+昵称+正文首行）；点击缩略行滚动定位并闪烁高亮原消息。
- **FR-30 引用失效**：被引用消息已删除时缩略行显示「原消息已删除」（对标 Discord）；仅单层引用，不展开引用链（13 文档 AP.6）。
- **FR-31 回复提及开关**：回复时可切换「是否 @ 原作者」开关，默认开（对标 Discord reply ping toggle）；通知语义依赖服务端提及模型，见 §8。

### 3.7 消息编辑

- **FR-32 编辑入口**：仅本人消息 hover 操作栏出现「编辑」；输入框聚焦且为空时按 `↑` 直接编辑自己最近一条消息（对标 Discord）。
- **FR-33 编辑态交互**：原消息位置原地变为编辑输入框，`Enter` 保存、`Esc` 取消，下方显示「Esc 取消 · Enter 保存」提示（对标 Discord 编辑态）。
- **FR-34 编辑范围**：首期仅可修改正文文本，不可增删附件（13 文档 AS.7）；编辑框中附件区只读。
- **FR-35 已编辑标记**：编辑成功后消息尾部显示「(已编辑 ×N)」，N 为服务端 `edit_count`（07 文档 5B.4、13 文档 AS.4）；hover 标记显示最后编辑时间 `edited_at`。次数一律以服务端字段为准，客户端不得本地累加。
- **FR-36 编辑历史查看**：作者本人、持 `MANAGE_MESSAGES` 者可通过消息右键菜单「查看编辑历史」查看全文快照列表（版本号、时间、内容 diff 高亮）；普通成员仅见次数（13 文档 AS.5）。历史查询 API 见 §8 待补充。
- **FR-37 无编辑时间窗**：不做客户端侧编辑时限（13 文档 AS.3，无时间窗）；若后续服务端加配置，客户端读取配置控制入口显隐。
- **FR-38 编辑同步**：收到 `MESSAGE_UPDATE` 时原地更新正文、`edit_count`、`edited_at`，不改变消息在流中的位置。

### 3.8 消息删除

- **FR-39 删除权限**：本人消息始终可删；他人消息仅持 `MANAGE_MESSAGES`（02 文档 bit 13、13 文档 AS.6）时显示删除入口。
- **FR-40 删除确认**：删除弹确认框并预览消息内容；`Shift+点击删除` 跳过确认（对标 Discord 快捷删除）。
- **FR-41 删除同步**：收到 `MESSAGE_DELETE` 后从消息流移除该消息；若该消息被他人引用，引用缩略行降级为「原消息已删除」（FR-30）。软删除与审计由服务端负责（13 文档 AQ.3），客户端不保留已删内容。
- **FR-42 管理删除区分**：`MANAGE_MESSAGES` 删除他人消息属管理行为，服务端审计记录；客户端在确认框中提示「你正在删除他人消息，该操作将被记录」。

### 3.9 消息历史与分页

- **FR-43 历史拉取**：进入频道调用 `GET /channels/{id}/messages?limit=50` 拉取最近消息（13 文档 AR.2/AR.4：默认 50、最大 100）；向上滚动至阈值（顶端剩余 <300px）时用最旧消息 ID 作 `before` 游标续拉，实现无限滚动。
- **FR-44 无历史权限表现**：无 `READ_MESSAGE_HISTORY` 时（13 文档 AR.3）：不调用历史接口（调用将得 404）；消息区顶部固定提示条「你没有查看历史消息的权限，只能看到进入频道后的新消息」；实时消息正常接收显示。
- **FR-45 历史到头**：拉取返回条数不足 `limit` 视为到头，顶部渲染频道欢迎块（频道名、创建说明，对标 Discord channel beginning）。
- **FR-46 滚动位置保持**：向上加载新一页时保持当前视口内容不跳动（prepend 补偿滚动偏移）；切换频道后返回时恢复上次阅读位置。
- **FR-47 消息缓存**：内存缓存最近 N 个频道各 ~200 条消息，减少切频道重复拉取；缓存以雪花 ID 排序（13 文档 AP.1，时间可排序），与 Gateway 事件合并去重。
- **FR-48 断线补齐**：Gateway 重连后对打开中的频道用最后已知消息 ID 作 `after` 参数补拉缺口，缺口过大（>100 条）时清空重拉最近一页。

### 3.10 输入状态（Typing Indicator）

- **FR-49 上报**：本人开始输入时向服务端上报 typing（节流：每 8s 最多一次；清空输入或发送后停止）。对标 Discord `POST /channels/{id}/typing`；服务端未定义该接口与事件，见 §8。
- **FR-50 展示**：输入框上方一行显示「Alice 正在输入…」；2 人显示「Alice 和 Bob 正在输入…」；≥3 人显示「多人正在输入…」；单人条目 10s 未续期自动消失（对标 Discord 展示规则）。

### 3.11 置顶（Pin）

- **FR-51 置顶占位**：服务端定稿置顶为二期（13 文档 AV.3–4）。首期客户端不实现置顶功能，不显示置顶入口；频道头部预留「📌 已置顶消息」按钮的布局位。二期规格随服务端定义补充，见 §8。

## 4. UI / UX 要求

- **UX-01 消息操作栏**：hover 消息右上浮现快捷栏：添加反应、回复、编辑（本人）、更多（右键菜单同源），对标 Discord hover toolbar。
- **UX-02 右键菜单**：右键消息弹出菜单：回复、复制文本、复制消息链接、复制消息 ID（开发者模式）、编辑/删除（按权限）、查看编辑历史（按权限）。
- **UX-03 输入框状态**：三态——正常可输入；禁发置灰（显示「你在此频道没有发言权限」或 Restriction 原因，见 08 文档）；限流冷却倒计时。
- **UX-04 无历史权限提示**：FR-44 的提示条使用信息蓝样式常驻，不可关闭，避免用户误以为频道为空。
- **UX-05 键盘可达**：全部核心操作可键盘完成：`↑` 编辑、`Esc` 取消/关闭回复、`PageUp/PageDown` 翻阅消息流、`Alt+↑/↓` 切换频道（对标 Discord 快捷键）。
- **UX-06 已编辑标记视觉**：「(已编辑 ×N)」使用次级灰色小字号，不干扰正文阅读；N=1 时可仅显示「(已编辑)」，hover 才显示次数。
- **UX-07 失败消息视觉**：发送失败消息整体红色调 + 感叹号图标，与正常消息明显区分（对标 Discord failed message）。
- **UX-08 长消息折叠**：单条超过 ~800px 高度折叠并显示「展开」；代码块单独折叠规则见 FR-17。
- **UX-09 时间显示**：组内首条显示「今天 14:32」式相对日期；hover 任意消息时间显示完整绝对时间 tooltip。
- **UX-10 无障碍**：消息流支持屏幕阅读器逐条朗读；提及、反应计数提供 aria-label。

## 5. 与服务端的交互

| 交互 | API / 事件 | 权限位 | 出处 |
|------|-----------|--------|------|
| 发送消息 | `POST /channels/{id}/messages`（含 `content` / `reply_to_id` / `attachment_ids` / `nonce`） | `VIEW_CHANNEL` + `SEND_MESSAGES` + 无禁发 Restriction | 13 AR.1、13 §4 |
| 拉取历史 | `GET /channels/{id}/messages?before=&after=&limit=` | `VIEW_CHANNEL` + `READ_MESSAGE_HISTORY` | 13 AR.2/AR.3 |
| 编辑消息 | PATCH 消息接口（路径以 OpenAPI 正式稿为准） | 仅作者本人 | 13 AS.1–2 |
| 删除消息 | DELETE 消息接口 | 作者本人 或 `MANAGE_MESSAGES` | 13 AS.6、02 bit 13 |
| 添加/移除反应 | `PUT/DELETE /channels/{id}/messages/{mid}/reactions/{emoji}/@me` | `ADD_REACTIONS` | 13 AV、02 bit 6 |
| 实时消息 | Gateway `MESSAGE_CREATE` / `MESSAGE_UPDATE` / `MESSAGE_DELETE` | 频道可见（`VIEW_CHANNEL` 且无禁看 Restriction） | 13 AR.5、13 §10 |
| 反应事件 | Gateway `MESSAGE_REACTION_ADD` / `MESSAGE_REACTION_REMOVE` | 同上 | 13 AV |
| 权限变更 | Gateway `PERMISSIONS_UPDATE` 或重拉 members/@me | — | 02 §9 |
| 限制事件 | Gateway `RESTRICTION_CREATE` / `RESTRICTION_LIFT` / `RESTRICTION_UPDATE` | 当事人必推 | 12 AL.5 |

关键约定：

1. 消息 ID 为雪花 ID / ULID，可按时间排序（13 AP.1），客户端排序与分页均以 ID 为准。
2. 无 `VIEW_CHANNEL` 或被禁看 Restriction 的频道：API 一律 **404**，Gateway 不推送（06 §8、12 AL §6.2）；客户端遇 404 应视为「频道不可见」，从列表移除，不展示「无权限」字样（防扫频语义）。
3. 客户端缓存的权限位仅用于展示优化，**不可信**，最终裁决在 Owl-Server（02 §8）。

## 6. 边界与异常情况

| 场景 | 客户端行为 |
|------|-----------|
| 发送时被实时禁发（收到 RESTRICTION_CREATE） | 输入框立即置灰；已在途请求返回 403 时消息标失败并提示受限原因 |
| 发送时频道被删/被禁看（404） | 移除该频道视图，回到频道列表并 toast「频道不可用」 |
| 编辑他人消息（异常路径） | 客户端不提供入口；若 API 被绕过调用，服务端 403，客户端 toast 通用错误 |
| 编辑与删除竞态（编辑中消息被管理删除） | 收到 MESSAGE_DELETE 时强制退出编辑态并提示「消息已被删除」 |
| 历史接口 404 但缓存有权限 | 以服务端为准：清除该频道历史 UI，回退到 FR-44 无历史模式，并触发权限重拉 |
| 分页游标失效/消息被清理 | 返回空页视为到头；不重试死循环 |
| nonce 冲突（重复回包） | 以 nonce 匹配去重，仅保留一条 |
| Gateway 断连期间的编辑/删除 | 重连补拉（FR-48）中以 `MESSAGE_UPDATE` 语义合并；无法补齐的以重拉页覆盖本地缓存 |
| 正文 4000 字 + 大量 emoji/提及 | 按服务端字符计数规则校验（以 OpenAPI 定义为准），客户端计数与服务端不一致时以服务端 400 提示 |
| 系统时钟偏差 | 消息时间显示以服务端 `created_at` 为准，不使用本地接收时间 |
| 频道 slowmode（若后续配置） | 预留 429 `retry_after` 通用处理（FR-08） |

## 7. 验收标准

1. 双端登录 A/B 两账号，A 发送消息后 B 在 1s 内（局域网）看到 `MESSAGE_CREATE` 渲染，消息分组、时间线正确。
2. A 弱网发送失败 → 消息标红 → 点击重试成功后，B 端只出现一条消息（nonce 幂等验证）。
3. Markdown：粗体/斜体/行内代码/代码块/链接正确渲染，`<script>` 与 `javascript:` 链接被安全处理为纯文本/拦截。
4. @提及：A 提及 B，B 端消息整行高亮；无 `MENTION_EVERYONE` 的账号在补全面板中看不到 @everyone。
5. 编辑：A 编辑两次后，双方消息尾部显示「(已编辑 ×2)」，`edit_count` 与服务端一致；B（普通成员）右键无「查看编辑历史」，持 `MANAGE_MESSAGES` 的 C 可以看到 2 个历史版本。
6. 删除：B 无法看到删除 A 消息的入口；C（`MANAGE_MESSAGES`）可删除且 A/B 端消息同步消失。
7. 历史权限：移除 B 的 `READ_MESSAGE_HISTORY` 后，B 重进频道看不到历史，顶部出现权限提示条，新消息实时可见；历史接口调用返回 404 不产生错误弹窗。
8. 无限滚动：在 500+ 条消息的频道连续上翻，每页 50 条无重复无遗漏，滚动位置不跳动，到头显示频道欢迎块。
9. 反应：A 添加 👍 后 B 实时看到计数 1，B 点击同一胶囊变 2 且高亮，再点回 1；无 `ADD_REACTIONS` 的账号无添加入口。
10. 回复：B 回复 A 的消息，点击引用摘要跳转定位并高亮原消息；删除原消息后摘要显示「原消息已删除」。
11. typing：A 输入时 B 端 1s 内出现「正在输入」，A 停止 10s 后消失（依赖 §8 接口就绪）。
12. 断线重连：断开 Gateway 30s 期间 A 发 5 条消息，B 重连后消息流自动补齐 5 条且顺序正确。
