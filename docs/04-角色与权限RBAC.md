## 1. 功能概述

本文档定义桌面客户端的角色与权限系统需求。服务端 02 文档已定稿权限模型：**uint64 位掩码 + 角色并集 + 频道 Overwrite**，业务权限唯一权威在 Newt-Server，客户端本地计算仅用于展示（02 §8：「客户端展示用权限可下发缓存，不可信」——即客户端计算结果只决定 UI，不作为安全边界）。客户端需求包括：

- **角色管理 UI**：创建 / 删除 / 重命名 / 颜色 / 拖拽排序（position）/ 权限位勾选。
- **频道权限覆盖编辑器**：对角色或成员的 allow/deny，三态开关「允许 ✓ / 继承 / / 拒绝 ✕」，对标 Discord。
- **本地权限计算引擎**：按服务端 02 §5 算法在客户端复算最终权限，即时驱动灰置按钮、隐藏频道、隐藏管理入口。
- **权限位清单**：以服务端 02 §3.2 为准逐项列出并说明客户端 UI 表现。
- **角色分配 UI**、**层级规则**（不能操作 position ≥ 自己的角色/成员）。
- **多维 Restriction 管理 UI**（07 专项 4）。

## 3. 功能需求明细（FR）

### 3.1 角色管理 UI

- **FR-01 角色列表页**：服务器设置「角色」页：左列角色列表按 `position` 从高到低排列，`@everyone` 恒在最底且不可拖动（position=0 固定，出处：02 §4）；右侧为选中角色的编辑区（显示 / 权限 / 成员管理三个 tab），布局对标 Discord Roles 页。
- **FR-02 创建/删除**：「创建角色」新建角色默认权限为 0（02 §3.3「新建自定义角色权限默认 0」）、插入到自己最高角色之下的最高位置；删除角色需确认，删除后其成员自动失去该角色。
- **FR-03 显示属性**：可编辑角色名（1–100 字符）、颜色（预设色板 + 自定义取色器）、`hoist`（在成员列表单独分组显示）、`mentionable`（允许任何人 @该角色）；hoist/mentionable 为 02 §2 定义的展示字段。
- **FR-04 权限勾选**：权限 tab 按「常规服务器权限 / 成员权限 / 文本频道权限 / 语音频道权限 / 高级权限」分组列出全部权限位开关（清单见 §3.5），每项含名称 + 中文说明；`ADMINISTRATOR` 单独置于「高级」并带红色警示文案「拥有全部权限并无视频道拒绝，请谨慎授予」（语义出处：06 §4）。
- **FR-05 拖拽排序**：角色列表支持拖拽调整 position；**只能在自己最高角色 position 之下的区间内拖动**，高于等于自己最高角色的角色显示锁标不可拖、不可编辑（02 §4「可管理的角色：操作者最高角色 position 严格大于目标角色」）。
- **FR-06 防提权勾选约束**：编辑角色权限时，自己不具备的权限位开关灰置并 tooltip「你不能授予自己没有的权限」（02 §4「MANAGE_ROLES 可分配的权限位不得超过操作者自身最终服务器权限」）。所有者与 `ADMINISTRATOR` 不受此限（管理员短路）。
- **FR-07 角色成员 tab**：查看/搜索该角色成员，支持批量添加/移除。
- **FR-08 API**：〔需服务端补充 API：角色 CRUD `POST/PATCH/DELETE /guilds/:id/roles`、批量排序、成员角色增删 `PUT/DELETE /guilds/:id/members/:uid/roles/:rid`；Gateway `GUILD_ROLE_*`、`GUILD_MEMBER_UPDATE` 事件〕

### 3.2 频道权限覆盖（Overwrite）编辑器

- **FR-09 入口**：频道设置「权限」tab；左列为已有 overwrite 目标列表（角色在上、成员在下），「+」可添加角色或成员目标；右侧为该目标的权限三态开关列表。完全对标 Discord Channel Permissions。
- **FR-10 三态开关**：每个权限位提供三态：**允许 ✓（绿）/ 继承 /（灰，中间态）/ 拒绝 ✕（红）**；「继承」即该位不出现在 allow 也不出现在 deny，删除覆盖 = 恢复继承（02 §6）。同一位不允许同时 allow+deny，UI 三态互斥天然保证（02 §6 约束）。
- **FR-11 展示的位集合**：文本频道只显示文本相关 + 通用位；语音频道只显示语音相关 + 通用位（作用域见 §3.5 清单「作用域」列）。
- **FR-12 编辑权限门槛**：编辑 overwrite 要求 `MANAGE_ROLES`（频道级可由 overwrite 授予）且授予的位不超自身（02 §8「编辑频道覆盖：建议需 MANAGE_ROLES 且位不超自身」；06 §7.3：仅 `MANAGE_CHANNELS` 不足以改敏感覆盖，以可配置权限节点为准）。不满足时权限 tab 只读。
- **FR-13 私密频道快捷开关**：权限 tab 顶部「私密频道」总开关 = 对 `@everyone` deny `VIEW_CHANNEL` 的语法糖（对标 Discord）。
- **FR-14 与分类同步**：属于分类的频道显示「已与分类同步/权限已不同步」状态；「与分类同步」按钮一键复制分类 overwrite（对标 Discord Sync Now）。
- **FR-15 API**：〔需服务端补充 API：`PUT/DELETE /channels/:id/permissions/:target_id`（type: ROLE=0/MEMBER=1, allow, deny，数据模型出处：02 §6）〕

### 3.3 本地权限计算与即时 UI 反映

- **FR-16 计算引擎**：客户端内置与服务端 02 §5 完全一致的纯函数计算库，输入（member, guild.roles, channel.overwrites）输出 uint64 bits，顺序为：
  1. 所有者 → 全权限（短路）；
  2. `@everyone` 权限 | 各角色权限并集；含 `ADMINISTRATOR` → 全权限（短路，且无视频道 deny，06 §4）；
  3. `@everyone` overwrite：先 `&~deny` 再 `|allow`；
  4. 成员所有角色 overwrite：deny 全部合并后先清除，allow 全部合并后再置位；
  5. 成员专属 overwrite：先 deny 后 allow（优先级最高）；
  6. 叠加 Restriction mask（只收紧，02 §11.1：`bits = apply_restrictions(bits, ...)`）。
- **FR-17 展示不可信原则**：本地计算仅驱动 UI；任何操作以服务端裁决为准，收到 403/404 时以服务端结果纠正本地缓存（02 §8）。
- **FR-18 即时反映**：收到角色/overwrite/成员角色/Restriction 变更事件（`PERMISSIONS_UPDATE` 或明细事件，02 §9）后重新计算受影响范围并在 300ms 内更新 UI：
  - 失去 `VIEW_CHANNEL` → 频道从列表消失（含正在浏览时的强制导航，见 03 文档 FR-17）；
  - 失去 `SEND_MESSAGES` → 输入框禁用 + 占位文案「你没有在此频道发言的权限」（对标 Discord）；
  - 失去 `CONNECT` → 语音频道点击变灰 tooltip；正在房内则等待服务端吊销会话；
  - 失去管理位 → 对应齿轮/右键菜单项消失或灰置。
- **FR-19 灰置 vs 隐藏规则**：**整块功能无权限 → 隐藏**（如服务器设置导航项、频道邀请按钮）；**上下文操作无权限但需要用户理解现状 → 灰置 + tooltip 说明缺什么权限**（如输入框、麦克风按钮）。全客户端统一遵循。
- **FR-20 缓存失效**：与 02 §9 对齐，本地权限缓存 key `(guild_id, user_id, channel_id?)`，在角色权限变更、成员角色变更、覆盖变更、所有者转让、Restriction 变更事件时失效重算。

### 3.4 角色分配与层级规则

- **FR-21 分配入口**：成员右键菜单「身份组」子菜单（复选列表）+ 资料卡「+」快捷添加 + 服务器设置成员页，三处入口一致。
- **FR-22 层级过滤**：分配列表中 position ≥ 操作者最高角色的角色不可勾选（锁标）；对最高角色 position ≥ 自己的成员，踢出/封禁/禁言/改昵称等管理项全部灰置（02 §4：可踢/禁的成员要求操作者最高角色 position 严格大于目标成员最高角色；所有者不受限制）。
- **FR-23 角色徽标**：成员名颜色取其**最高的带颜色角色**；资料卡列出全部角色（有权限者可在卡上直接增删）。对标 Discord。
- **FR-24 @提及角色**：`mentionable` 的角色可被所有人 @；不可提及角色仅 `MENTION_EVERYONE`（bit 17）持有者可 @（对标 Discord）。

### 3.6 多维 Restriction 管理 UI

依据 06 §6 与 07 专项 4：

- **FR-25 施加入口**：成员右键「限制…」（需 `MODERATE_MEMBERS` 或协管被授节点）打开弹窗：
  - 维度勾选：文字·观看 / 文字·发言 / 语音·收听 / 语音·发言（四维可组合，07 §4.1）；
  - 作用域：当前频道 / 指定频道 / 全服全部文字频道 / 全服全部语音频道（06 §6.1 矩阵）；
  - 时长：15 分钟 / 1 小时 / 1 天 / 7 天 / 自定义 / 永久（永久即无 `expires_at` 的频道级 ban，07 §4.5）；
  - 原因（必填，记审计）。
- **FR-26 保护对象**：对所有者、对 position ≥ 自己的成员，「限制」入口灰置（07 §4.3；系统管理员例外）。
- **FR-27 当事人展示**：被限制者在对应界面看到**原因 + 到期时间**（输入框占位、语音提示条，07 §4.6）；其他成员至多看到「该用户已被限制」角标。
- **FR-28 来源区分**：管理面板中人工 Restriction、`server_mute/deafen`（成员状态，非权限位，02 §5.4）、舞台自动禁说（`CAPACITY_QUEUE`）三类来源用不同标签区分（07 专项 4 注意 2）。
- **FR-29 限制列表**：服务器设置「限制」页列出生效中的 Restriction（对象、维度、作用域、剩余时间、操作者），可提前解除。
- **FR-30 API**：〔需服务端补充 API：Restriction CRUD 与事件（服务端 12 号文档《Restriction-API》已立项，客户端以其定稿为准）〕

### 3.7 三级权威与系统管理员

- **FR-31 层级模型**：客户端所有权限判断遵循 06 §7.1 三级权威：系统管理员（平台）> 服务器管理员（ADMINISTRATOR/所有者）> 子频道覆盖/协管。
- **FR-32 系统管视图**：`system_admin = true` 用户对任意服务器拥有管理视图（可见全部设置页），其操作均带「平台管理员操作将被审计」提示（06 §7.3：系统管改任意覆盖，审计必记）。
- **FR-33 系统管可限制服管**：Restriction 弹窗对系统管不做层级过滤（07 §4.2/§4.3 例外条款）。

## 4. UI / UX 要求

1. 角色页、overwrite 三态开关、私密频道向导、「与分类同步」全部对标 Discord 现行交互；三态开关三个格子（✕ / / ✓）水平排列，选中格填充红/灰/绿。
2. 每个权限开关下方一行灰字中文说明（参考本文 §3.5 说明列文案）。
3. 角色颜色即时预览：修改颜色时左列名称与右上预览头像名同步变色。
4. 未保存修改统一使用底部保存条（同 02 文档 FR-14）。
5. 权限相关 tooltip 文案模板：「需要「{权限名}」权限」；层级不足模板：「你不能管理与你同级或更高的角色/成员」。
6. 角色列表 250+ 角色（Discord 上限同为 250，可沿用）时虚拟滚动。
7. 「以身份查看」（P1）：顶部出现橙色横幅「正在以 {角色/成员} 视角查看」，一键退出。

## 5. 与服务端的交互

| 客户端动作 | 接口 / 事件 | 状态 | 出处 |

## 6. 边界与异常情况

| 场景 | 客户端行为 |
|------|-----------|
| 本地计算「有权限」但服务端 403/404 | 以服务端为准，纠正缓存并重拉权限相关数据（02 §8 不可信原则） |
| 编辑角色期间该角色被他人删除 | 收到 `GUILD_ROLE_DELETE` 后关闭编辑区并 toast |
| 两管理员并发改同一 overwrite | 后写覆盖；客户端收到事件后刷新编辑器当前值 |
| 把自己最高角色的关键权限勾掉 | 允许（服务端裁决）；若因此失去管理页权限，保存后按 FR-18 即时收起入口 |
| 拖拽角色到 ≥ 自己最高角色的位置 | 拖拽目标区间外显示禁止光标，释放无效 |
| `@everyone` 尝试删除/改名/拖动 | 均不可；仅权限位可编辑 |
| 权限位含未知 bit（服务端新增） | 按位保留原值透传，UI 不渲染未知位开关（前向兼容，02 §3.1「未列出的 bit 禁止使用」） |
| Restriction 到期 | 客户端按 `expires_at` 本地倒计时先行恢复 UI，同时以服务端事件为最终确认 |
| 被限制「语音·发言」时正在麦上 | 收到 `caps_updated`（去掉 publish_audio）强制闭麦并显示原因（协议 README §3：立即停收上行） |
| 角色排序批量提交部分失败 | 整体回滚到服务端返回的最新顺序 |
| 离线期间权限变更 | 重连后重拉 guild 快照全量重算，不信任本地旧缓存 |

## 7. 验收标准

1. 本地权限计算库对照服务端 02 §5 伪代码的单元测试全部通过，覆盖：所有者短路、ADMINISTRATOR 短路（无视频道 deny）、@everyone 覆盖、多角色 deny/allow 合并、成员覆盖优先、Restriction 收紧。
2. 管理员对 `@everyone` 在频道 X deny `VIEW_CHANNEL`：全体普通成员 2s 内频道消失；再对角色 Y allow：Y 成员频道恢复出现。
3. 三态开关：设置「拒绝」后再点同一格恢复「继承」，提交后服务端 overwrite 记录相应位被清除。
4. 版主（position 5）无法在任何入口对 position ≥ 5 的角色/成员执行管理操作：拖拽被阻止、菜单项灰置、身份组带锁标。
5. 版主编辑角色时，自己没有的 `BAN_MEMBERS` 开关灰置且提交请求被服务端拒绝时有兜底错误提示。
6. 成员失去 `SEND_MESSAGES` 后输入框即时禁用并显示原因；恢复后即时可用，全程无需刷新。
7. 对正在说话的成员施加「本语音频道禁说」：1s 内其上行停止、其客户端闭麦并显示「原因 + 到期时间」；到期后自动恢复。
8. 所有者在任何成员的限制/踢出菜单中不可被选为目标（灰置）；系统管理员账号则可以。
9. 客户端收到含未知权限 bit 的角色数据不崩溃、保存角色时未知位原样回传。
10. UI 一致性抽查：全客户端凡无权限的管理入口要么隐藏要么灰置 + 标准 tooltip，无「点击后才报错」的路径（服务端兜底除外）。
