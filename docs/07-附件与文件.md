## 1. 功能概述

本文档定义 Newt-Desktop 附件上传、预览、下载的完整体验，覆盖：

- **上传方式**：拖拽入窗口、剪贴板粘贴（截图/文件）、附件按钮文件选择器三通道，对标 Discord。
- **上传协议**：预签名直传对象存储（13 文档 AT.1–2）——先 `presign` 拿 `upload_url`，客户端 `PUT` 直传，再随消息提交 `attachment_ids`。
- **大小与数量限制**：单文件上限由**系统管理员按服务器（Guild）配置**，平台默认 25MB（07 文档 5B.3b、13 文档 AT.4）；客户端需从服务端获取当前服上限并**在选择文件时前置报错**；每消息最多 10 个附件（13 文档 AT.3）。
- **类型策略**：存储 MIME 不限、可上传任意类型；**内嵌预览白名单仅四类：图片、音频、视频、PDF**（07 文档 5B.3、13 文档 AT.5），其余类型一律呈现为下载卡片。
- **上传进度与取消**：逐文件进度条、可取消、失败重试。
- **图片查看器**：点击放大、缩放/旋转、查看原图、另存为。
- **下载管理**：下载进度、打开文件/所在文件夹、下载历史。
- **URL 鉴权**：下载走**短时签名 URL**，服务端签发前校验频道 `VIEW_CHANNEL`（13 文档 AT.7）；客户端不得长期缓存签名 URL，过期需重新获取。

## 3. 功能需求明细（FR）

### 3.1 上传入口

- **FR-01 拖拽上传**：文件拖入客户端窗口时显示全窗遮罩「拖放以上传到 #频道名」（对标 Discord drop overlay）；松手后文件进入输入框上方的待发附件区。支持多文件同时拖入。
- **FR-02 粘贴上传**：输入框聚焦时 `Ctrl/Cmd+V`：剪贴板为图片位图时自动生成 PNG 附件（命名 `image.png`，可重命名）；为文件引用时按文件添加；为文本时正常粘贴文本。
- **FR-03 选择器上传**：输入框左侧「+」按钮打开系统文件选择器，支持多选（对标 Discord「+」菜单）。
- **FR-04 权限门控**：附件能力依赖频道 `ATTACH_FILES` 权限（02 文档 bit 15）；无权限时隐藏「+」中的上传项，拖拽/粘贴时 toast「你在此频道没有上传文件的权限」，不进入待发区。
- **FR-05 待发附件区**：附件以缩略卡片横排显示在输入框上方：图片显示缩略图，其他显示类型图标 + 文件名 + 大小；每张卡片带「删除」与（图片）「编辑文件名/剧透标记（P1）」入口（对标 Discord attachment tray）。

### 3.2 大小与数量限制（前置校验）

- **FR-06 获取上限配置**：客户端进入服务器时获取该服的**单文件大小上限**（系统管理员按 Guild 配置，07 文档 5B.3b、13 文档 AT.4，平台默认 25MB），缓存并跟随配置变更事件/重拉更新。获取配置的 API 见 §8 待补充。
- **FR-07 超限前置报错**：文件加入待发区之前校验大小；超限文件不进入待发区，弹对话框「文件过大：xxx.zip (100MB)，本服务器单文件上限 25MB」（对标 Discord 超限弹窗）。多文件混合时仅拦截超限项，其余正常加入。
- **FR-08 数量上限**：每条消息最多 **10** 个附件（13 文档 AT.3）；超出时提示「一条消息最多 10 个附件」，多余文件不加入；不自动拆分成多条消息（用户可手动再发）。
- **FR-09 双重校验语义**：前置校验仅为体验优化；`presign` 阶段服务端仍会校验大小与配额（13 文档 §6.1 步骤 2），返回 400 时按服务端文案兜底展示（防止本地缓存的上限过期）。
- **FR-10 空文件与异常文件**：0 字节文件、无读取权限的本地文件在加入待发区时报错拦截。

### 3.3 上传流程与进度

- **FR-11 上传时序**（13 文档 §6.1）：
  1. 对每个文件调用 `POST /channels/{id}/attachments/presign { filename, size, mime }`；
  2. 得到 `upload_url + attachment_id`；
  3. 客户端 `PUT` 直传对象存储；
  4. 全部完成后 `POST /channels/{id}/messages { content, attachment_ids, nonce }`。
- **FR-12 上传时机**：文件加入待发区后**立即开始预签名+直传**（不等用户点发送），发送时若已传完则秒发；仍在传时发送按钮显示等待态（对标 Discord 提前上传行为）。
- **FR-13 进度显示**：每张待发卡片显示环形/条形进度与已传字节数；消息发出后若仍有上传中的实现路径，进度显示在消息气泡内（首期以「传完才可发」为准，简化状态机）。
- **FR-14 取消上传**：待发卡片「×」取消：中止 PUT 请求并将该 `attachment_id` 弃用（未绑定消息的 attachment 由服务端定时清理，13 文档 §6.1 注）；不需要客户端显式删除调用（若服务端提供 DELETE 则调用，见 §8）。
- **FR-15 上传失败重试**：PUT 失败的文件卡片标红并提供「重试」；重试重新走 presign（旧签名可能过期）。消息中其余已成功附件不受影响。
- **FR-16 并发控制**：同时上传最多 3 个文件，其余排队，避免占满上行带宽影响语音（语音进行中时可降为 1 并发 + 限速，P1）。

### 3.4 内嵌预览（白名单四类）

预览白名单严格遵循 07 文档 5B.3 / 13 文档 AT.5：**图片、音频、视频、PDF**；其余一律下载卡片，不做任何内嵌渲染。

- **FR-17 图片**：消息流内嵌缩略图（最大约 550×350，保持宽高比，对标 Discord 内嵌图）；GIF 悬停播放；点击进入图片查看器（§3.5）。加载用缩略/降采样资源（若服务端提供 thumbnail 变体，见 §8），失败显示占位与重试。
- **FR-18 音频**：内嵌音频播放器：播放/暂停、进度条、时长、音量、播放速度（1x/1.5x/2x）；同一时刻全局只播放一路音频（新播放自动暂停旧的）。
- **FR-19 视频**：内嵌视频卡片显示封面帧 + 播放按钮；点击原位播放，支持全屏、进度、音量；默认不自动播放。超大视频按流式/Range 请求播放，不强制全量下载。
- **FR-20 PDF**：消息流中显示 PDF 卡片（图标+文件名+页数若可得）；点击打开内嵌 PDF 查看器（分页/连续滚动、缩放、页码跳转、文本选择复制），并提供「下载」按钮。
- **FR-21 非白名单类型**：统一文件卡片：类型图标（按扩展名映射）、文件名（超长中间省略）、大小、下载按钮；**不做** txt/代码/Office 等任何内嵌渲染（严格遵循白名单，与 Discord 会内嵌 txt 的行为有意不同，以服务端定稿为准）。
- **FR-22 MIME 与扩展名不符**：预览类型判定以服务端返回的附件元数据 `mime` 为准（13 文档 attachments 表）；解码失败时降级为下载卡片，不崩溃。

### 3.5 图片查看器

- **FR-23 打开与布局**：点击内嵌图片打开全屏遮罩查看器（对标 Discord lightbox）：居中显示、背景 80% 黑、`Esc`/点击空白关闭。
- **FR-24 缩放与平移**：滚轮/双击缩放（fit → 100% → 200%），放大后可拖拽平移；显示当前缩放比例。
- **FR-25 原图查看**：默认加载适配屏幕的资源；提供「查看原图」入口加载完整原图（签名 URL 获取）；底部显示文件名、尺寸、大小。
- **FR-26 查看器操作**：工具栏：下载、复制图片到剪贴板、旋转 90°、在浏览器打开（签名 URL，注意短时效提示）。
- **FR-27 多图浏览**：同一条消息含多张图片时查看器内 `←→` 切换（对标 Discord 画廊导航）。

### 3.6 下载管理

- **FR-28 下载入口**：所有附件卡片/查看器均有下载按钮；默认下载到系统下载目录，设置中可改「每次询问保存位置」。
- **FR-29 签名 URL 获取**：下载前向服务端请求该附件的**短时签名 URL**（13 文档 AT.7，签发时校验频道 `VIEW_CHANNEL`）；客户端拿到后立即开始下载。签名 URL **不落盘持久化**、不写入日志。
- **FR-30 URL 过期处理**：下载中断超过签名有效期、或预览资源 403/过期时，自动重新请求签名 URL 并续传/重载（支持 Range 续传，以对象存储能力为准），对用户透明。
- **FR-31 下载进度**：进行中的下载在附件卡片上显示进度环；客户端提供「下载列表」浮层（最近下载、进度、取消、打开文件、打开所在文件夹）。
- **FR-32 文件名安全**：保存时清洗文件名中的路径分隔符与控制字符，防路径穿越；重名自动追加 `(1)`。
- **FR-33 附件失效**：消息删除后附件延迟 GC 7 天（13 文档 AT.8）；请求签名 URL 得到 404 时提示「附件已失效或被删除」，卡片置为失效态。

### 3.7 与消息的联动

- **FR-34 仅附件消息**：允许无正文仅附件发送（13 文档 AP.4）；消息气泡不渲染空正文行。
- **FR-35 编辑不动附件**：消息编辑仅改文本、附件区在编辑态只读（13 文档 AS.7，与 05 文档 FR-34 一致）。
- **FR-36 附件与失败重试**：消息发送失败重试（05 文档 FR-07）时复用已上传成功的 `attachment_ids`，不重新上传。

## 4. UI / UX 要求

- **UX-01 拖放遮罩**：拖拽进入窗口 100ms 内出现遮罩，视觉含目标频道名与上限说明「最大 25MB」（读取当前服配置动态显示）。
- **UX-02 待发区滚动**：待发附件超过一屏宽时横向滚动；10 个满员时「+」入口置灰并提示。
- **UX-03 进度可读**：进度显示百分比 + 速率（如 3.2MB/s）；速率低于阈值 10s 显示「网络较慢」。
- **UX-04 图片占位**：内嵌图片加载前按真实宽高比渲染灰色占位（依赖元数据中的宽高，若无则默认比例），避免消息流跳动。
- **UX-05 视频/音频控件风格**：统一自定义控件皮肤，深浅色主题适配，禁用系统原生控件外观差异。
- **UX-06 大文件警示**：>100MB 的下载在开始前提示预计大小（若服务器上限被系统管调高允许大文件）。
- **UX-07 键盘可达**：查看器 `Esc` 关闭、`←→` 切图、`+/-` 缩放；下载列表可 Tab 导航。
- **UX-08 剧透/敏感遮罩（P1）**：预留图片模糊遮罩（spoiler）交互位，对标 Discord spoiler，待服务端字段支持。
- **UX-09 错误文案**：超限、无权限、失效三类错误使用固定文案模板，包含具体数值（上限、文件大小），不用「未知错误」。

## 5. 与服务端的交互

| 交互 | API / 事件 | 权限/校验 | 出处 |
|------|-----------|----------|------|
| 预签名 | `POST /channels/{id}/attachments/presign { filename, size, mime }` → `upload_url + attachment_id` | `ATTACH_FILES`；服务端校验大小 ≤ 服上限、数量配额 | 13 §6.1、AT.4、02 bit 15 |
| 直传 | `PUT {upload_url}`（对象存储） | 签名 URL 自带鉴权 | 13 AT.1–2 |
| 绑定发送 | `POST /channels/{id}/messages { content, attachment_ids, nonce }` | 服务端确认对象存在且属该用户 | 13 §6.1 步骤 4–5 |
| 下载/预览 | 请求附件短时签名 URL（GET，具体路径待 OpenAPI） | 签发时校验频道 `VIEW_CHANNEL` | 13 AT.7 |
| 附件元数据 | 消息体内嵌 attachments（object_key、mime、size、uploader 等） | 随消息可见性 | 13 §3 attachments 表 |
| 服上限配置 | 单文件上限按 Guild 配置（获取接口见 §8） | 系统管理员配置 | 07 5B.3b、13 AT.4 |

关键约定：

1. 每消息最多 10 附件、单文件默认 25MB/服可调、预览白名单四类、GC 7 天（13 §12 结论 4）。
2. 未绑定消息的 attachment 由服务端定时清理（13 §6.1 注），客户端取消上传无需补偿操作。
3. 病毒扫描二期（13 AT.6）；若服务端异步标记危险文件，客户端预留「已被标记」卡片态（P1）。
4. 签名 URL 短时有效，客户端所有预览/下载资源请求均按「可过期、可重签」设计（FR-30）。

## 6. 边界与异常情况

| 场景 | 客户端行为 |
|------|-----------|
| presign 返回 400（超限/配额） | 按服务端错误展示，附件移出待发区；若因本地缓存上限过期导致，同时刷新服配置 |
| PUT 直传中断（网络切换） | 自动重试 1 次，仍失败标红等待手动重试（重新 presign） |
| 上传完成但发送消息失败 | attachment_ids 保留在待发区可再次发送；超时未绑定由服务端 GC 兜底 |
| 发送时部分附件仍在上传 | 发送按钮等待态；单个文件失败时询问「移除失败项并发送 / 取消」 |
| 收到消息但附件元数据缺失 | 渲染占位卡片「附件加载失败」+ 重试 |
| 签名 URL 过期（预览中） | 静默重签重载（FR-30），一次重签仍 403 则提示无权限 |
| 附件已 GC（404） | 卡片失效态「附件已失效」（FR-33） |
| 被移出频道/禁看后尝试下载旧附件 | 签名接口 404 → 按频道不可见语义处理，不提示「无权限」 |
| 磁盘空间不足 | 下载失败提示具体原因，保留续传能力 |
| 剪贴板超大位图（>上限） | 生成前估算体积，超限走 FR-07 前置报错 |
| 同名文件重复下载 | 自动追加 `(1)`（FR-32） |
| MIME 伪造（zip 改名 .png） | 以服务端 mime 判定预览；解码失败降级下载卡片（FR-22），不执行任何内容 |
| 语音通话中大文件上传 | P1：限速/降并发（FR-16），首期至少不阻塞 UI |

## 7. 验收标准

1. 三通道上传（拖拽/粘贴/选择器）均可成功发送附件消息，B 端实时收到并正确渲染。
2. 前置校验：本服上限 25MB 时选择 26MB 文件，**无任何网络请求发出**（抓包验证），本地弹窗包含文件名、实际大小与上限值。
3. 系统管把某服上限调至 50MB 后，客户端（重进服或收到配置更新后）允许 40MB 文件上传成功。
4. 一次加入 11 个文件时第 11 个被拒并提示；10 个附件的消息发送与渲染正常。
5. 四类预览各验证一例：png 内嵌缩略图 + 查看器缩放/原图；mp3 内嵌播放器可播放拖动；mp4 可原位播放与全屏；PDF 内嵌翻页阅读。`.zip`、`.txt`、`.docx` 均只显示下载卡片，无内嵌渲染。
6. 上传 20MB 文件过程中进度条平滑推进；中途取消后消息未发送、待发区移除；服务端侧该 attachment 最终被清理（联调验证）。
7. 上传中断网 → 卡片标红 → 恢复网络点重试 → 成功发送，消息仅一条（nonce 幂等）。
8. 图片查看器：Esc 关闭、滚轮缩放、多图消息内 ←→ 切换、「复制图片」可粘贴到外部应用。
9. 下载：进度环显示、完成后「打开所在文件夹」定位正确；重名文件自动 `(1)`。
10. 签名过期模拟：将预览资源 URL 手动置为过期后触发重载，用户无感知恢复显示。
11. 无 `ATTACH_FILES` 的账号：无上传入口，拖拽被拒并提示；已有消息中的附件仍可正常预览下载（下载权限只依赖 `VIEW_CHANNEL`）。
12. 删除含附件消息 7 天后（或联调模拟 GC），原签名请求返回 404，卡片显示失效态。
