## 1. 功能概述

Newt-Desktop 与 Newt-Server 之间维护一条**已认证的 Gateway WebSocket 长连接**（Server-05 §1「客户端 ↔ Newt-Server」通道），承载除媒体外的全部实时事件：消息、成员、角色/权限、频道、语音状态、Restriction、舞台等。客户端基于该事件流维护本地状态副本（服务器/频道/成员/消息/语音状态缓存），实现与 Discord/KOOK 一致的「打开即最新、变更即刻反映」体验。

设计原则：

1. **服务端权威**：本地缓存永远可被服务端事件与 REST 拉取结果覆盖；乐观更新必须可回滚。
2. **事件驱动 UI**：任何界面元素（消息列表、成员列表、频道树、语音成员卡片）均订阅本地 store，不直接消费网络帧。
3. **断线可恢复**：Gateway 断开重连后，通过 resume/重同步补齐缺失事件，用户无感。
4. **注意**：Newt-Server 的 Gateway 实现目前在服务端排期中（Server-15 §9.2 明确列为「目前缺失、需同步排期」的配套依赖）。本文中服务端文档已定义的事件均标注出处；未定义的连接层机制（心跳、resume、序列号等）按 **Discord Gateway 惯例**设计，并统一在 §7「依赖服务端待补充」列出。

## 2. 用户故事 / 使用场景

| # | 场景 | 期望 |
|---|------|------|
| US-1 | 他人在当前频道发消息 | 消息即时出现在列表底部，无需刷新（对标 Discord MESSAGE_CREATE） |
| US-2 | 自己发消息 | 消息立即显示（乐观更新、半透明态），服务端确认后转正；失败显示红色重试标记（对标 Discord 灰显 pending 消息） |
| US-3 | 管理员对我施加「禁看」某频道的 Restriction | 该频道从我的频道树**立即消失**，正在浏览则跳转到默认可见频道（Server-12 AL：view_text deny → 404 + Gateway 不推） |
| US-4 | 网络抖动 10 秒 | 重连后自动补齐期间的消息与状态变更，无需手动刷新，无重复消息 |
| US-5 | 我在手机端（未来）把自己静音 | 桌面端语音状态图标同步更新（多端 VoiceState 以 Server 为权威） |
| US-6 | 有人在语音频道说话 | 成员头像出现绿色发言圈（SFU WSS `speaking` 事件，~250ms 节流，Server-协议 §2.2） |
| US-7 | 管理员改了我的角色 | 我的权限相关 UI（可见频道、可用按钮）在 1 秒级内刷新 |
| US-8 | 舞台频道有人申请上麦 | 队列面板实时更新（`STAGE_QUEUE_UPDATE` 全员简表，Server-11 AE.1） |

## 3. 功能需求明细（FR）

### 3.1 Gateway 连接生命周期

- **FR-01** 客户端登录后建立 Gateway WSS 连接并完成认证（认证帧格式待服务端定义，见 §7-1）；认证成功后应收到初始快照（对标 Discord `READY`：自身用户、所在 guild 列表、每 guild 的频道/角色/自身成员信息、语音状态；字段清单见 §7-2）。
- **FR-02** 客户端按服务端下发的心跳间隔维持心跳（对标 Discord `HEARTBEAT`/`HEARTBEAT_ACK`；参数见 §7-3）；连续 2 次心跳无 ACK 即主动断开并重连。
- **FR-03** 客户端为每个收到的事件维护递增序列号 `seq`（对标 Discord `s` 字段；KOOK 为 `sn`），断线重连时携带 `session_id + last_seq` 请求 **resume**；服务端可补发则增量补齐，不可补发（超出回放窗口）则返回失效指令，客户端做**全量重同步**（见 FR-04）。协议细节见 §7-4。
- **FR-04（全量重同步）** resume 失败时：客户端保留 UI 骨架，后台重新走初始快照 + 按需 REST 拉取（当前频道最近消息 `GET /channels/{id}/messages?limit=50`，Server-13 AR.2/AR.4），以服务端结果**整体替换**本地对应缓存段；重同步期间 UI 显示顶部细条「正在同步…」（对标 Discord 连接横幅），不清空已渲染内容。
- **FR-05** Gateway 重连退避与文档 13 FR-20 一致（指数退避 + 抖动，上限 15s；断网时挂起）。
- **FR-06** Gateway 断开**不影响**已建立的 SFU 媒体连接（两条独立通道，Server-05 §1）；但语音编排事件不可达，客户端应在 Gateway 恢复后立即核对 VoiceState（文档 13 FR-08）。

### 3.2 事件目录与处理

**已由服务端文档定义的事件**（客户端必须实现处理器）：

| 事件 | 处理 | 出处 |
|------|------|------|
| `MESSAGE_CREATE` | 追加消息到对应频道缓存；触发未读/通知（文档 15） | Server-13 AR.5 |
| `MESSAGE_UPDATE` | 就地替换 content/edit_count/edited_at；UI 显示「已编辑 + 次数」。**流式终态兼容**：本地无此 id 时 upsert 插入（见文档 23） | Server-13 AR.5/AS.4；stream.go 兼容补发 |
| `MESSAGE_DELETE` | 移除或替换为 tombstone；同步未读计数 | Server-13 AR.5/AQ.3 |
| `MESSAGE_REACTION_ADD` / `REMOVE` | 更新消息反应聚合 | Server-13 AV |
| `MESSAGE_STREAM_START` | 插入流式占位（`stream_status=STREAMING`）；**未读/通知仅此计一次** | Bot 流式；[文档 23](./23-Bot流式消息与卡片.md) |
| `MESSAGE_STREAM_DELTA` | 按 `seq` 拼接 `delta`（批处理 + 乱序缓冲）；不计未读 | Bot 流式；文档 23 |
| `MESSAGE_STREAM_END` | 终态覆盖（可含 `card`）；清 `stream_status`；不计未读 | Bot 流式；文档 23 |
| `VOICE_STATE_UPDATE` | 更新语音频道成员卡片（进/出/mute/deaf/`stage_role`）；`channel_id=null` 即离房 | Server-05 §11、Server-11 §8.2 |
| `VOICE_SERVER_UPDATE` | 交由语音连接状态机（文档 13 FR-04） | Server-05 §11 |
| `VOICE_CAPS_UPDATE` | 更新本地能力（可否发言等），联动麦克风 UI | Server-05 §11 |
| `VOICE_CHANNEL_STATUS` | 频道人数/舞台状态角标 | Server-05 §11 |
| `VOICE_MIGRATING` / `VOICE_MIGRATED` | 迁移态 UI（文档 13 UX-01） | Server-09 §7.1 |
| `VOICE_PACK_PLAY` | 拉取短音频 URL 本地播放（入场语音包，不经 SFU） | Server-05 §11、Server-07 5A.3 |
| `RESTRICTION_CREATE` / `RESTRICTION_UPDATE` / `RESTRICTION_LIFT` | 更新本地权限投影；当事人展示 reason/expires，他人仅「被限制」徽章 | Server-12 AL.5/AM |
| `STAGE_QUEUE_UPDATE` | 舞台申请队列面板（全员简表；管理者扩展字段） | Server-11 AE.1 |
| `STAGE_INSTANCE_UPDATE`（或频道配置更新） | mode/max_speakers/开关变化 | Server-11 §8.2 |

另有 SFU WSS 侧事件（不经 Gateway，仅语音在房期间）：`participant_joined/left`、`track_published/ended`、`caps_updated`、`speaking`（Server-协议 §2.2）。客户端须将两路事件在本地 store 归一：**成员在房与否以 Gateway `VOICE_STATE_UPDATE` 为权威**，SFU 事件仅用于媒体层（订阅管理、发言指示）低延迟渲染。

**服务端文档未定义、客户端必需的事件**（按 Discord Gateway 惯例列出，全部标注「依赖服务端待补充」，汇总见 §7-5）：

| 事件（拟名） | 用途 |
|--------------|------|
| `GUILD_CREATE` / `UPDATE` / `DELETE` | 加入/更新/退出服务器 |
| `CHANNEL_CREATE` / `UPDATE` / `DELETE` | 频道增删改（含排序、分组） |
| `GUILD_MEMBER_ADD` / `UPDATE` / `REMOVE` | 成员进出、昵称/角色变化 |
| `GUILD_ROLE_CREATE` / `UPDATE` / `DELETE` | 角色定义变化 |
| `PRESENCE_UPDATE` | 成员在线状态（在线/离开/勿扰/隐身） |
| `TYPING_START` | 「正在输入」指示 |
| `USER_UPDATE` | 自身资料变化 |

- **FR-07** 所有事件处理器必须**幂等**：以实体 ID + 版本/时间戳去重，重复投递（resume 补发重叠）不得产生重复 UI 项。
- **FR-08** 未知事件类型必须安全忽略并记诊断日志（向前兼容）。

### 3.3 本地缓存与状态管理

- **FR-09（缓存分层）** 内存 store 为唯一 UI 数据源；持久层（磁盘，如 SQLite/LevelDB）缓存：guild/频道/角色元数据、成员片段、每频道最近 N 条消息（建议 50，对齐 Server-13 AR.4 默认分页）、自身设置。冷启动先渲染持久缓存（灰色「同步中」态），Gateway 快照到达后校正。
- **FR-10（消息缓存）** 每频道消息按雪花 ID 有序存储（Server-13 AP.1 可时间排序）；向上滚动分页用 `before` 游标拉取（Server-13 AR.2），`limit` 不超过 100。无 `READ_MESSAGE_HISTORY` 权限时历史接口返回 404，客户端只显示进频后实时消息并提示「无历史消息权限」（Server-13 AR.3）。
- **FR-11（成员列表）** 大服务器成员列表不全量缓存：按当前可视区域 + 语音在房成员 + 最近发言者做**懒加载**（对标 Discord Lazy Guilds 的成员列表分片订阅）；接口见 §7-6。
- **FR-12（乐观更新）** 以下操作采用乐观更新，并以 `nonce` 保证与服务端回包/广播的匹配（Server-13 AR.6）：发消息（pending 半透明 → `MESSAGE_CREATE` 带同 nonce 转正）、编辑/删除自己消息、添加/移除反应、self_mute/self_deaf。失败回滚并给出内联错误（消息旁红色感叹号 + 重试/删除，对标 Discord）。
- **FR-13（服务端纠正）** 任何乐观状态在收到服务端权威事件后无条件对齐；冲突时以服务端为准且不弹错误框（静默校正），仅操作被明确拒绝（403/400）时提示。
- **FR-14（权限投影缓存）** 客户端本地实现 RBAC + Restriction 的权限计算投影（顺序：RBAC → Restriction 并集收紧，Server-12 AL.1），用于即时 UI 判定（按钮可用性、频道可见性）；但**只作预判**，最终以服务端 API 结果为准。角色/overwrite/Restriction 相关事件到达时立即失效重算。

### 3.4 权限变更的即时 UI 反映

- **FR-15** 收到导致**频道不可见**的变更（失去 `VIEW_CHANNEL`、`view_text` Restriction，Server-12 §6.2）：该频道立即从频道树移除；若用户正停留在该频道，切换到该服务器第一个可见频道并显示轻提示「你已无法查看该频道」。本地缓存中该频道消息标记不可用（不必立即删除，但不得再展示）。
- **FR-16** 收到 `listen_voice` deny 且自己在该语音频道：等待/配合服务端 disconnect（Server-12 AL.3），按文档 13 权威移出路径处理，展示当事人可见的 reason/expires（Server-12 AM.1）。
- **FR-17** 权限恢复（`RESTRICTION_LIFT`/角色变更）同样即时生效：频道重新出现在频道树。
- **FR-18** 他人被限制时，成员列表显示受限徽章（默认开启、服配置可关，Server-12 AM.4）；不展示 reason（Server-12 AM.2）。

### 3.5 多端在线状态同步

- **FR-19** 同一账号允许多客户端同时在线，各自独立 Gateway 会话；语音会话遵循「同 guild 同时仅一个语音频道」（Server-05 §2.2）：另一端加入语音时，本端收到 `VOICE_STATE_UPDATE`，若 `session_id` 非本端则展示「已在其他设备进入语音」并将本端语音 UI 置为旁观态。多端语音会话互斥的具体仲裁规则见 §7-7。
- **FR-20** 自身 presence（在线/离开/勿扰/隐身）为账号级：任一端修改，其他端经 `PRESENCE_UPDATE`（拟）同步；勿扰状态被文档 15 的通知抑制逻辑消费。
- **FR-21** 已读状态跨端同步：任一端阅读频道后，其他端未读角标同步清除（对标 Discord read state 同步；协议见 §7-8，亦为文档 15 的依赖）。

## 4. UI/UX 要求

- **UX-01** 连接状态横幅对标 Discord：正常时无任何显示；重连中在窗口顶部显示细横幅「正在重新连接…」；resume 成功横幅立即消失；全量重同步显示「正在同步…」。禁止全屏遮罩。
- **UX-02** 消息 pending 态：乐观消息半透明；确认后恢复正常不闪烁；失败红色标记 + hover 重试（对标 Discord）。
- **UX-03** 「正在输入」指示显示在输入框上方，多人时聚合为「A、B 正在输入…」（对标 Discord），10s 无后续事件自动消失。
- **UX-04** 发言绿圈渲染延迟 ≤ 300ms（`speaking` 事件节流 ~250ms 之上尽量即时，Server-协议 §2.2）。
- **UX-05** 频道因权限消失/出现时使用平滑过渡（淡出/淡入），不整树重排闪烁。
- **UX-06** 编辑过的消息尾部显示「(已编辑)」，hover 显示编辑次数；仅作者/管理者入口可见完整编辑历史（Server-13 AS.4/AS.5）。
- **UX-07** 冷启动：≤ 1s 内以持久缓存渲染出主界面骨架；同步完成前旧数据不加遮罩，仅在标题栏区域给出同步中的微状态。

## 6. 边界与异常情况

| 场景 | 客户端行为 |
|------|-----------|
| resume 窗口过期 | 全量重同步（FR-04）；期间不清空 UI |
| 事件与 REST 拉取结果交叉（拉取历史时收到新消息） | 按消息 ID 有序合并去重（FR-07 幂等） |
| 乐观消息发送超时（无回包、无广播） | 30s 后标记失败可重试；重试沿用同 nonce 防重复（Server-13 AR.6） |
| 收到自己不可见频道的事件（服务端过滤缺陷） | 客户端权限投影兜底：不渲染、记日志 |
| 本地时钟偏差 | 所有过期判断（Restriction expires_at 等）以服务端 UTC 为准（Server-12 AN.3），倒计时类 UI 以服务端时间戳差值计算 |
| Gateway 与 SFU 状态矛盾（如 Gateway 说在房、SFU 已断） | Gateway 为业务权威；媒体层矛盾走文档 13 恢复流程 |
| 被踢出服务器 | 收到成员移除事件后清理该 guild 全部缓存与 UI；若在语音则同时关闭媒体（Server-05 §7.3） |
| 消息软删 tombstone | 列表中移除；若为回复引用的父消息，引用处显示「消息已删除」（对标 Discord） |
| 极端事件风暴（大服刷屏） | 渲染批处理（合并 ≥60Hz 帧内的多事件）；未读计数聚合更新，不逐条动画 |

## 7. 依赖服务端待补充

1. **Gateway 认证帧**：连接后如何出示登录凭据（token 帧 vs header），认证超时与失败码。
2. **初始快照（READY）字段清单**：guild/频道/角色/自身成员/语音状态/已读状态的快照结构。
3. **心跳协议**：间隔下发方式、ACK 帧、超时语义（对标 Discord `HELLO.heartbeat_interval`）。
4. **resume 协议**：`session_id`、事件序列号字段、回放窗口大小、失效指令（对标 Discord `RESUME`/`INVALID_SESSION`；KOOK `sn` 补偿）。
5. **常规业务事件**：`GUILD_*` / `CHANNEL_*` / `GUILD_MEMBER_*` / `GUILD_ROLE_*` / `PRESENCE_UPDATE` / `TYPING_START` / `USER_UPDATE` 均未在服务端文档出现，需定义 payload。
6. **成员列表懒加载/分片订阅接口**（大服成员列表）。
7. **多端语音互斥仲裁**：同账号第二端 join 时，旧端会话是被顶掉还是拒绝新 join。
8. **已读状态（read state）API 与同步事件**：ack 上报、跨端广播（文档 15 强依赖）。
9. **`TYPING` 上报端点**（POST typing）。

## 8. 本地 Store 结构（参考实现约定）

为保证各功能文档（13/15/16）消费同一数据源，本地 store 至少划分以下域，均由 §3.2 事件目录驱动：

| 域 | 内容 | 持久化 |
|----|------|--------|
| `guilds` | guild 元数据、角色表、自身成员信息 | 是 |
| `channels` | 频道树（含排序/分组）、每频道权限投影结果缓存 | 是 |
| `messages` | 每频道有序消息窗口（雪花 ID 索引）+ pending 队列（nonce 键） | 最近 N 条 |
| `members` | 懒加载成员分片（FR-11） | 否（会话级） |
| `voice` | 每 guild VoiceState 集合、本地语音连接状态机（文档 13） | 否 |
| `restrictions` | 自身生效中的 Restriction（`GET /restrictions/@me` + 事件增量） | 否 |
| `readState` | 每频道 last_read_message_id 与 mention 计数（文档 15） | 是 |
| `presence` | 成员在线状态 | 否 |

## 9. 验收标准
