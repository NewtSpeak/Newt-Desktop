## 1. 功能概述

入场语音包是用户「进场彩蛋」：当用户 **进服首次出现** 或 **进入指定语音频道**（两种触发可配，07 5A.1）时，向可听范围内的其他成员播放一段其选定的短音频（如「XXX 闪亮登场！」）。该功能主对标 KOOK 的进场语音/特效体系，稀有语音包可按角色/资产授权，构成社区身份感与商业化点。

**实现方式已定稿（07 5A.3）**：客户端收到 Gateway `VOICE_PACK_PLAY`（或等价）事件后，**拉取短音频 URL 并在本地混音播放**，**不经 SFU 长轨道**——即语音包不占用 WebRTC 上下行，与通话音频在客户端输出端混合。

范围与开关（07 5A）：

- 触发：进服首次出现 / 进指定语音频道，**默认不做「每次切频都放」**（5A.1）。
- 频道开关：**每个子频道管理员可配置本频道是否允许播放**（5A.1b）。
- 听到范围：默认 **同语音频道**；可配 **全服在线**（谨慎使用）（5A.2）。
- 权限：**配置包 = 服管**；**使用稀有包 = 角色/资产授权**（5A.4）。

本文档覆盖：播放端行为、用户选包/试听、服管配置管理 UI、频道开关、防刷屏与频控的客户端处理。

## 2. 用户故事 / 使用场景

| # | 用户故事 |
|---|----------|
| US-1 | 作为普通成员，我在「服务器 → 个人设置 → 入场语音」中从可用语音包列表挑选一个，试听后保存；下次我进语音频道时同频道成员会听到它。 |
| US-2 | 作为拥有「传说」身份组的成员，我能看到并使用带稀有标识的专属语音包；失去身份组后该包自动不可用并回退默认。 |
| US-3 | 作为同频道成员，有人带语音包进场时我听到音频并看到轻量视觉提示（谁的语音包），音量随「提示音音量」设置调节。 |
| US-4 | 作为不想被打扰的用户，我在设置中关闭「播放他人入场语音」，之后只看到视觉提示不再出声。 |
| US-5 | 作为子频道管理员，我关闭本频道的入场语音开关，之后任何人进入该频道都不触发播放。 |
| US-6 | 作为服务器管理员，我在服务器设置中上传/管理语音包（名称、音频、时长限制、授权身份组），并配置触发场景与听到范围。 |
| US-7 | 作为听众，某人反复进出频道试图刷屏，我不会被轰炸——客户端与服务端双层频控保证同一用户短时间内不重复出声。 |
| US-8 | 作为正在专注通话的用户，多人同时进场时语音包按队列限流播放而非同时轰鸣。 |

## 3. 功能需求明细（FR）

### 3.1 播放端（接收方）

| 编号 | 需求 | 验收口径 |
|------|------|----------|
| FR-01 | 客户端监听 Gateway `VOICE_PACK_PLAY`（05 §11）事件，载荷预期含：触发用户、场景（进服/进频道）、音频 URL（或资源 ID）、目标范围。收到后校验本地条件（FR-03/04）再拉取音频本地播放。 | 事件驱动播放 |
| FR-02 | 播放实现：HTTP(S) 拉取短音频（预期 ≤5s、≤500KB 量级，具体上限见待补充），解码后混入本地输出（与通话下行混音），**不经任何 WebRTC 轨道**（07 5A.3）。播放音量挂接「提示音/音效音量」独立滑杆。 | 不占用 SFU 轨 |
| FR-03 | 本地过滤条件（任一不满足则不出声，仅可显示视觉提示）：① 用户设置「播放他人入场语音」开启；② 自己未处于 self_deaf（闭听时不放）；③ 该触发用户未被我本地静音/屏蔽；④ 客户端频控未命中（FR-14）。 | 四条件逐一测试 |
| FR-04 | 范围判定以服务端事件为准：服务端只会把事件推给应听到的人（默认同语音频道，可配全服在线，07 5A.2），客户端**不自行扩大**范围；若收到与自己状态不符的事件（如已离开该频道）则丢弃。 | 不越范围播放 |
| FR-05 | 视觉提示：语音包播放时在频道消息流/语音面板显示轻量条目「🔊 {昵称} 使用了入场语音《{包名}》」，点击可查看包详情；关闭声音的用户仍可见该条目。 | 声画分离可用 |
| FR-06 | 并发限流：同时收到多条播放事件时，本地队列串行播放，队列上限 3 条，超出丢弃最旧未播条目；同一用户在队列中只保留最新一条。 | 多人进场不轰鸣 |
| FR-07 | 自己进场：默认也向自己回放一次自己的语音包（可在设置关闭「播放我自己的入场语音」），便于确认生效。 | 开关可用 |
| FR-08 | 拉取失败（404/超时 3s）：静默放弃本次播放，仅保留视觉提示；不重试轰炸资源服务器（单事件最多 1 次重试）。 | 失败静默降级 |

### 3.2 用户选包与试听

| 编号 | 需求 | 验收口径 |
|------|------|----------|
| FR-09 | 入口：服务器右键菜单/成员资料 →「入场语音」设置页（按服务器维度配置，同一用户在不同服可用不同包）。列表展示该服全部语音包：名称、时长、稀有度标识、可用性（可用/需要某身份组/需要某资产）。 | 按服维度生效 |
| FR-10 | 不可用的稀有包置灰展示（对标 KOOK 商城化陈列：可见不可用，附获取条件文案），点击展示「需要 XX 身份组/资产」说明（07 5A.4）。 | 获取条件可见 |
| FR-11 | 试听：每个包提供试听按钮，本地拉 URL 播放，不发任何广播事件；试听走与 FR-02 相同的音量通道。 | 试听不打扰他人 |
| FR-12 | 选定/更换/关闭：用户可选择一个包、更换或选择「不使用」；保存调用服务端接口（见待补充），成功后立即生效。授权变化（失去身份组）后服务端应拒绝越权包，客户端收到配置校验失败时回退「不使用」并提示。 | 越权自动回退 |

### 3.3 服管配置管理

| 编号 | 需求 | 验收口径 |
|------|------|----------|
| FR-13 | 服务器设置 →「入场语音包」管理页（仅服管可见，07 5A.4）：包列表 CRUD——上传音频（客户端校验格式/时长/大小上限）、命名、设为默认可用或绑定授权（身份组多选 / 资产标识）、启用/停用。 | 服管专属入口 |
| FR-14 | 全局策略配置：触发场景勾选（进服首次出现 / 进指定语音频道，07 5A.1；**无**「每次切频都放」选项，明确不提供该配置）、听到范围（同语音频道【默认】/ 全服在线——选择全服在线时二次确认并显示打扰警告，07 5A.2 谨慎）、指定触发频道多选。 | 无切频即放选项 |
| FR-15 | 频道级开关（07 5A.1b）：语音频道设置页新增「允许播放入场语音」开关，**子频道管理员**可操作；关闭后该频道不触发（服务端不推事件，客户端设置页显示当前状态）。 | 频道开关生效 |
| FR-16 | 审计与预览：管理页支持试听任意包；变更操作提示将影响的范围。 | 管理可试听 |

### 3.4 防刷屏 / 频控（客户端侧）

| 编号 | 需求 | 验收口径 |
|------|------|----------|
| FR-17 | 客户端本地频控（防御性，与服务端频控叠加）：同一触发用户 **60s 冷却**——冷却期内再次收到其播放事件只显示视觉提示不出声；全局节流——任意语音包播放间隔 ≥2s（队列自然实现）。 | 双层频控生效 |
| FR-18 | 「进服首次出现」语义由服务端判定（07 5A.1），客户端不缓存判定；但对异常重复事件（相同 user + 相同场景 60s 内重复）按 FR-17 去重。 | 重复事件去抖 |
| FR-19 | 快捷屏蔽：视觉提示条目右键「不再播放此人的入场语音」（加入本地静音语音包名单，按服持久化）；设置页可管理该名单。 | 单人屏蔽可用 |
| FR-20 | 正在说话保护（可选增强，默认开）：本地检测当前有人在麦上持续讲话时，将语音包音量自动衰减 50%（ducking），避免盖过正在进行的对话。 | 衰减可感知 |

## 4. UI / UX 要求

1. **主对标 KOOK**：语音包列表卡片式陈列，稀有度用颜色边框/角标区分（普通/稀有/传说）；不可用包置灰但可见获取途径——形成收集激励。
2. **参照 Discord Soundboard 的克制原则**：他人音效可被本地关闭、有独立音量通道、有单人屏蔽——所有打扰均可被接收方单方面终止。
3. **设置分层清晰**：接收侧开关（是否听别人的、音量、单人屏蔽）在「语音设置」；发送侧选包在「服务器个人设置」；管理侧在「服务器设置」——三处入口不混放。
4. **视觉提示轻量**：进场提示条目复用系统消息样式，不弹 toast、不抢焦点。
5. **试听与真实播放同响度**：避免「试听小声、实际扰民」。
6. **上传体验**：拖拽上传、波形预览、超限（时长/大小）即时前端校验报错，不等服务端。
7. **无障碍**：视觉提示条目可被屏幕阅读器朗读；纯听觉信息（语音包内容）不承载必要信息。

## 5. 与服务端 / SFU 的交互

### 5.1 播放链路（07 5A.3 + 05 §11）

```text
用户A                        Owl-Server                     同频道成员B/C…
 │ POST /voice/join（进入频道）│
 │                            │ 判定触发（进服首次/进指定频道）
 │                            │ 检查：频道开关(5A.1b)、A的包授权(5A.4)、服务端频控
 │                            │ 按范围（默认同语音频道）推送
 │                            │ ── VOICE_PACK_PLAY {user_id, pack_id,
 │                            │      audio_url, scene, channel_id} ──► B/C
 │                            │                    B/C：本地过滤(FR-03/17)
 │                            │                    → GET audio_url（CDN）
 │                            │                    → 本地解码混音播放 + 视觉提示
```

要点：**SFU 全程不参与**；音频资源建议走 CDN 直拉；播放决策权在接收端客户端（本地开关/频控是最后一道闸）。

### 5.2 客户端本地数据模型（逻辑）

```text
VoicePackLocalState {
  per_guild:
    selected_pack_id?          // 我在该服选定的包
    muted_pack_users: []       // 「不再播放此人」名单（FR-19）
  global:
    play_others_enabled: bool  // 播放他人入场语音（默认 true）
    play_self_enabled: bool    // 播放我自己的（默认 true）
    volume: 0..100             // 挂接提示音音量通道
  runtime:
    cooldown: Map<user_id, last_played_at>   // 60s 冷却（FR-17）
    play_queue: [event]                      // 上限 3（FR-06）
    audio_cache: LRU<url, decoded>           // 已拉取音频短缓存
}
```

`audio_cache` 建议 LRU ≤20 条、TTL 10 分钟：同一批人反复进出时避免重复下载；缓存键为资源 URL，服务端换包即换 URL 自然失效。

### 5.3 涉及的接口与事件

| 类型 | 名称 | 用途 |
|------|------|------|
| Gateway | `VOICE_PACK_PLAY`（或等价，05 §11 已列） | 触发播放 |
| REST | 语音包 CRUD / 用户选包 / 频道开关 / 全局策略 | 见 §6.1 待补充（05/07 未给出具体路径） |
| 静态 | 音频资源 URL（CDN） | 客户端 GET 拉取 |

### 5.4 与其他文档的关系

- 进房时序（文档 09）：语音包事件在 join 成功、Server 广播 `VOICE_STATE_UPDATE` 前后到达均可能，播放不阻塞进房流程，两者完全解耦。
- 舞台（文档 10）：舞台频道同样受频道开关控制；大房（>50）场景建议服管关闭本频道语音包或由服务端频控收紧（客户端不做特殊逻辑，按事件执行）。

## 6. 边界与异常情况

1. **事件先于本地入房状态就绪**：若收到本频道的 VOICE_PACK_PLAY 时自己的语音连接尚在协商中，允许播放（已在 VoiceState 中即算在频道内）；若自己已发起离开则丢弃。
2. **音频资源异常**：损坏/格式不支持 → 解码失败静默放弃，保留视觉提示，上报埋点。
3. **闭听（deafen）期间**：不播放（FR-03），也不入队补播；解除闭听不追播历史事件。
4. **多端在线**：同账号多端均会收到事件，各端独立按本地设置决定是否出声（与 Discord 提示音多端行为一致）。
5. **时钟/顺序**：事件乱序或迟到 >10s（对比事件时间戳，若有）则丢弃不播，防「幽灵进场」。
6. **全服在线范围**：该模式下不在语音频道的成员也会收到事件，播放走同样的本地过滤；客户端对此模式无特殊逻辑，但设置页向服管展示打扰警告（FR-14）。
7. **与通话回声**：本地播放的语音包可能被开麦者的麦克风拾取（扬声器外放场景）——依赖 AEC（文档 09 FR-37）消除，语音包播放期间不做特殊处理。
8. **离服/被踢**：离开服务器后清理该服的选包与屏蔽名单缓存。

| 全服在线范围的推送规模保护 | 大服全员推送的服务端限流策略未定义 |

## 7. 验收标准

1. 进服首次出现、进指定语音频道两种触发场景联调通过；反复切换频道**不**重复触发（07 5A.1 默认）。
2. 播放全程无 WebRTC 轨道参与（抓包核验：音频经 HTTPS 拉取，SFU 无新增轨）。
3. 频道开关关闭后，该频道任何进入均无事件/无播放；重新开启后恢复。
4. 稀有包授权：赋予/移除身份组后，选包列表可用性即时刷新；越权保存被拒并回退。
5. 本地过滤四条件（接收开关、闭听、单人屏蔽、频控）逐一验证；60s 冷却期内重复进出只出视觉提示。
6. 5 人同时进场：串行播放、队列上限 3、无叠音轰鸣。
7. 资源 404/超时场景静默降级，视觉提示保留，重试 ≤1 次。
8. 试听不产生任何对外事件（服务端日志核验）。
9. 音量独立通道、ducking 衰减、自我回放开关全部手测通过。
