## 1. 功能概述

本文档定义 Newt-Desktop 桌面客户端的账号与用户体系需求，覆盖：

- **注册 / 登录 / 登出**：邮箱 + 用户名 + 密码注册；用户名或邮箱登录；access/refresh 双 token 会话管理。
- **用户资料**：用户名（全局唯一标识）、显示名（Display Name）、头像、个性签名。
- **在线状态（Presence）**：在线 / 闲置 / 勿扰 / 隐身四态，对标 Discord presence 模型。
- **多设备登录**：同一账号可在多个桌面/移动/网页端同时在线，会话互不干扰，可查看与踢出其他会话。
- **账号安全**：修改密码、会话管理、（预留）两步验证。

服务端现状（依据 `swagger.json` v0.1.0）：已提供 `POST /api/v1/auth/register`、`POST /api/v1/auth/login`（返回 `access_token` / `refresh_token` / `user`），User 模型含 `id / username / email / system_admin`。**头像、显示名、个性签名、Presence、登出、改密码等均未提供**，相关条目按 Discord/KOOK 通行做法给出客户端需求，并标注「需服务端补充 API」，汇总见 §8。

## 2. 用户故事 / 使用场景

| 编号 | 用户故事 |
|------|----------|
| US-01 | 作为新用户，我希望用邮箱 + 用户名 + 密码快速注册，注册成功后直接进入主界面，无需重新登录。 |
| US-02 | 作为老用户，我希望用「用户名或邮箱」+ 密码登录，客户端记住会话，下次启动免登录。 |

## 3. 功能需求明细（FR）

### 3.1 注册

- **FR-01 注册表单**：提供邮箱（≤255 字符）、用户名（2–32 字符）、密码（8–128 字符）三个字段，与服务端 `registerRequest` 校验规则完全一致，客户端本地先行校验并即时提示。
- **FR-02 注册即登录**：调用 `POST /auth/register` 返回 201 后，客户端直接持久化返回的 `access_token` / `refresh_token` 并进入主界面，不再要求二次登录。
- **FR-03 错误呈现**：服务端返回 400（如用户名/邮箱已占用）时，按 `error.code` 映射为中文文案展示在对应字段下方，不弹全局错误框。
- **FR-04 密码强度提示**：输入密码时实时显示强度条（弱/中/强），仅作提示不阻断（服务端仅约束长度）。
- **FR-05 协议勾选**：注册需勾选《用户协议》《隐私政策》（占位链接），未勾选时注册按钮置灰。

### 3.2 登录 / 登出 / 会话保持

- **FR-06 登录表单**：单一 `identifier` 输入框（自动识别用户名或邮箱）+ 密码框，调用 `POST /auth/login`；401 时提示「账号或密码错误」，不区分具体哪项错误（防枚举）。
- **FR-07 Token 持久化**：`refresh_token` 使用操作系统安全存储（macOS Keychain / Windows Credential Manager / Linux Secret Service）保存；`access_token` 仅存内存。
- **FR-08 静默续期**：`access_token` 到期前（按 `access_expires_at` 提前 60s）用 `refresh_token` 静默刷新；刷新失败则回登录页并提示会话过期。〔需服务端补充 API：`POST /auth/refresh`〕
- **FR-09 登出**：用户主动登出时，客户端调用登出接口使当前 refresh_token 失效，随后清空本地 token、断开 Gateway 与 SFU 连接、清空内存缓存。〔需服务端补充 API：`POST /auth/logout`〕
- **FR-10 自动登录**：启动时若存在有效 refresh_token 则跳过登录页直接进入主界面，期间显示启动加载页（对标 Discord 启动画面）。
- **FR-11 多账号切换（P1）**：客户端可保存多个账号的凭据并快速切换（对标 Discord Account Switcher），首期可仅支持单账号。

### 3.3 用户资料

- **FR-12 资料字段**：用户资料包含用户名（不可随意修改，全局唯一）、显示名（1–32 字符，可随时修改，展示优先级高于用户名）、头像（图片，≤8MB，裁剪为正方形）、个性签名（≤190 字符，对标 Discord About Me）。〔需服务端补充 API：`GET /users/@me`、`PATCH /users/@me`、头像上传〕
- **FR-13 资料卡**：点击任意位置的用户头像/名字弹出资料卡（Popover），显示头像、显示名、用户名、个性签名、共同服务器、在线状态；再点「查看完整资料」进入资料弹窗。对标 Discord 用户资料卡。操作区「发消息 / 添加好友 / 屏蔽」等见 [文档 19](./19-隐私设置好友与私信.md) §5–§7。
- **FR-14 服务器内昵称**：成员在每个服务器可有独立昵称（受 `CHANGE_NICKNAME` / `MANAGE_NICKNAMES` 权限位控制，出处：服务端 02 文档 §3.2 bit 26/27）；展示优先级：服务器昵称 > 显示名 > 用户名。
- **FR-15 默认头像**：未设置头像时按用户 ID 哈希分配 6 色系之一的默认头像（对标 Discord 默认头像逻辑）。
- **FR-16 头像编辑器**：上传头像时提供圆形预览 + 缩放/拖拽裁剪；支持 PNG/JPG/WebP/GIF（GIF 动图为 P1）。

### 3.4 在线状态（Presence）

- **FR-17 四态模型**：支持 在线（绿）/ 闲置（黄月牙）/ 勿扰（红减号）/ 隐身（灰空心圆），图标与颜色语义严格对标 Discord。
- **FR-18 手动切换**：点击左下角自己的头像弹出状态菜单，可选四态；勿扰项下方注明「不会收到任何桌面通知」。
- **FR-19 自动闲置**：用户手动状态为「在线」且本机无键鼠活动超过 10 分钟时，客户端自动上报「闲置」；恢复活动后自动回「在线」。手动选择的闲置/勿扰/隐身不受自动逻辑影响。
- **FR-20 隐身语义**：隐身用户对他人显示为离线（成员列表沉底、灰色），但本人功能完全正常；服务端不得向其他客户端泄露隐身用户的真实状态。
- **FR-21 勿扰语义**：勿扰状态下客户端抑制全部系统通知与提示音，但未读红点、@提及徽标照常累积。
- **FR-22 状态订阅**：客户端通过 Gateway 接收 `PRESENCE_UPDATE` 事件更新成员列表、资料卡、私信列表中的状态点。〔需服务端补充：Presence 上报/订阅协议，含 `status` 字段与自定义状态〕
- **FR-23 自定义状态（P1）**：支持设置 emoji + 文本的自定义状态（对标 Discord Custom Status），可设过期时间（30 分钟 / 1 小时 / 今天 / 不清除）。

### 3.5 多设备登录

- **FR-24 并行会话**：同一账号允许多端同时在线；每端独立持有 refresh_token 与 Gateway 连接；一端操作（发消息、已读）通过 Gateway 事件同步到其他端。
- **FR-25 Presence 合并**：多端在线时对外状态按优先级合并：勿扰 > 在线 > 闲置 > 隐身/离线（对标 Discord 多端 presence 合并规则）；由服务端合并，客户端只展示结果。
- **FR-26 语音单端**：语音会话同一时刻仅允许一端接入；另一端点击加入语音时，提示「将把语音转移到本设备」，确认后旧端被服务端断开媒体会话（服务端 `DisconnectUser` 能力，出处：协议 README §3）。
- **FR-27 会话列表**：设置页「已登录设备」展示所有活跃会话（设备名、平台、IP 归属地、最近活跃时间），支持单个下线与「登出所有其他设备」。〔需服务端补充 API：会话列表/吊销〕

### 3.6 账号安全

- **FR-28 修改密码**：需输入当前密码 + 新密码（8–128 字符）+ 确认；成功后除当前会话外其余 refresh_token 全部失效，并提示用户。〔需服务端补充 API：`PATCH /users/@me/password`〕
- **FR-29 修改邮箱（P1）**：需当前密码验证 + 新邮箱验证码确认。〔需服务端补充 API〕
- **FR-30 两步验证（P1，预留）**：TOTP 两步验证的开启/关闭/恢复码 UI 预留入口，首期显示「即将推出」。
- **FR-31 敏感操作二次确认**：登出所有设备、修改密码、删除账号等操作均需再次输入密码确认。
- **FR-32 本地安全**：客户端崩溃日志与本地缓存中不得出现明文 token 与密码；退出登录后清除全部账号相关缓存。

## 4. UI / UX 要求

1. **登录/注册页**：居中卡片式布局（对标 Discord 登录页），支持回车提交、Tab 焦点顺序正确；注册与登录之间以链接互相跳转。
2. **左下角用户栏**（对标 Discord User Panel）：常驻显示自己的头像（含状态点）、显示名、用户名；内含麦克风静音、耳机静音、设置齿轮三个按钮。
3. **设置页**：全屏覆盖式设置（对标 Discord 设置页，ESC 关闭），左侧分组导航：「我的账号」「个人资料」「隐私与安全」「已登录设备」「语音与视频」「通知」「外观」。
4. **状态点渲染**：头像右下角以「挖孔」形式叠加状态点（Discord 风格 masked badge），在成员列表、消息头像、资料卡、私信列表一致呈现。
5. **表单反馈**：所有网络请求期间按钮进入 loading 态并禁用；失败在字段级或表单级红字提示；成功用轻量 toast。
6. **无障碍**：状态不只靠颜色区分（图标形状不同：实心圆/月牙/减号/空心圆）；表单控件带 aria 标签。
7. **暗色优先**：默认暗色主题（对标 Discord/KOOK 默认观感），亮色主题 P1。

## 6. 边界与异常情况

| 场景 | 客户端行为 |
|------|-----------|
| 注册时用户名/邮箱已存在 | 字段级红字提示，保留已填内容 |
| 登录 401 | 统一提示「账号或密码错误」，连续 5 次失败后前端冷却 30s（服务端限流为准） |
| refresh 失败 / token 被吊销 | 清空会话回登录页，toast「登录已过期，请重新登录」 |
| 网络断开 | 顶部显示重连横幅，Gateway 指数退避重连（1s→2s→4s…上限 60s），恢复后重放 presence 与订阅 |
| 改密码后其他端 | 其他端下次请求收到 401 → 回登录页 |
| 头像上传超限 | 上传前本地校验大小/格式，直接拦截并提示 |
| 系统时钟漂移 | token 过期判断以服务端返回的 `access_expires_at` 与本地单调时钟差值计算，不直接信任本地墙钟 |
| 多端同时改资料 | 以服务端最后写入为准，收到资料更新事件后覆盖本地表单外的展示 |
| 隐身时被 @ | 正常收到消息与红点，不暴露在线状态 |

## 7. 验收标准

1. 使用合法邮箱/用户名/密码注册，201 后无需再登录即进入主界面；重复用户名注册得到字段级错误提示。
2. 用「用户名」与「邮箱」两种 identifier 均可登录成功；错误密码提示统一文案。
3. 杀掉进程重启客户端，凭 Keychain 中 refresh_token 自动登录成功；手动登出后重启回到登录页。
4. 四种在线状态切换后，另一台登录同服的账号在 2s 内看到状态点变化（依赖 Presence 协议落地）。
5. 无键鼠操作 10 分钟后自动转闲置；动一下鼠标 5s 内恢复在线。
6. 勿扰状态下收到 @提及：无系统通知、无提示音，但红点与提及数正常累积。
7. 两台设备同时在线，A 端进语音后 B 端点同一语音频道，确认弹窗后语音在 1s 级转移到 B 端（对齐 `DisconnectUser` P99 < 1s）。
8. 修改密码后，其他设备在下次 API 请求时被登出。
9. 本地磁盘（日志、LevelDB/SQLite 缓存等）中检索不到明文 access/refresh token。

## 9. 关键时序（参考实现）

### 9.1 冷启动自动登录

```text
启动 → 读取 Keychain refresh_token
  ├─ 无 token ────────────────► 登录页
  └─ 有 token → POST /auth/refresh
        ├─ 200 → 持 access_token 建立 Gateway → READY → 主界面
        └─ 401/网络失败(重试3次) → 清理会话 → 登录页（网络失败则提示离线并允许重试）
```

### 9.2 Presence 生命周期

```text
Gateway 连接成功 → 上报本地持久化的手动状态（默认「在线」）
键鼠空闲 10min（且手动状态=在线）→ 上报 idle
恢复活动 → 上报 online
用户手动切换 → 立即上报 + 持久化到本地与云端（多端同步）
Gateway 断开 → 服务端按会话断开自动转离线（客户端无需动作）
```

## 10. 非功能需求

| 指标 | 要求 |
|------|------|
| 登录接口往返到主界面可交互 | ≤ 3s（正常网络） |
| 冷启动自动登录到主界面 | ≤ 5s |
| 状态切换端到端可见延迟 | ≤ 2s |
| token 刷新失败重试 | 指数退避，最多 3 次后判定会话失效 |
| 凭据存储 | 仅 OS 安全存储，禁止明文落盘（含日志脱敏） |
| 头像缓存 | 本地磁盘 LRU 缓存，按 URL 哈希命名，上限 256MB |

## 11. 术语表

| 术语 | 说明 |
|------|------|
| Presence | 用户在线状态（在线/闲置/勿扰/隐身），Discord 术语 |
| identifier | 登录标识，用户名或邮箱二选一（swagger `loginRequest`） |
| 显示名 | Display Name，非唯一，可随时修改；用户名全局唯一 |
| 会话（Session） | 一对 refresh_token + Gateway 连接，对应一台设备 |
