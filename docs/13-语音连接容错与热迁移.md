## 1. 功能概述

本文档定义 Owl-Desktop 在语音链路发生任何故障（SFU 节点死亡、网络分区、节点排空 Drain、过载迁移、Token 过期、本机网络切换等）时的客户端行为。

**体验底线（Server-07 专项 1.1、Server-09 §0，硬性约束）：**

1. **绝不允许**「掉线回大厅 / 要求用户手动重新点击进房」作为任何故障恢复路径。
2. **允许**换节点过程中出现**短暂静音**，恢复目标为**秒级**（对齐 Server-07 SLA 与 Server-15 BI 检出增强的动机说明）。
3. 迁移期间 UI 只做**微弱提示**（对标 Discord 顶部小字「RTC 正在重新连接」与 KOOK 的「网络重连中」角标），不弹对话框、不打断用户当前操作、不清空语音频道成员列表。

客户端的角色定位：**执行者而非决策者**。选点、建边、换根、迁移编排全部由 Owl-Server 完成（Server-08 §1、Server-10 §1）；客户端只负责按 `VOICE_SERVER_UPDATE` 携带的**单一目标节点**执行双 PC 热切（Server-10 X.3：fallback 列表不下发客户端），并上报 RTT 样本与 ICE 失败信号作为服务端决策输入（Server-10 §7、Server-15 BI.2）。

## 2. 用户故事 / 使用场景

| # | 场景 | 期望 |
|---|------|------|
| US-1 | 玩家开黑中，所在 SFU 节点宕机 | 语音短暂静音（秒级），自动恢复到新节点，队友列表不消失，用户最多注意到一条「线路优化中」小提示 |
| US-2 | 运维对节点执行 Drain 升级 | 用户在 60s 窗口内被平滑迁走（Server-09 I.6），几乎无感 |

## 3. 功能需求明细（FR）

### 3.1 总体状态机

- **FR-01** 客户端必须维护一个语音连接状态机，状态至少包含：`IDLE`（未在语音）、`JOINING`（REST join 至媒体连通）、`CONNECTED`（媒体正常）、`MIGRATING`（收到 `VOICE_MIGRATING`/`VOICE_SERVER_UPDATE` 后的双 PC 热切期）、`RECOVERING`（本地检测到故障、自行重连中）、`SUSPENDED`（Gateway 与 SFU 均不可达，等待网络恢复）。任何状态下不得转移到「已退出频道、需用户手动进房」——除非用户主动离开或收到服务端权威的移出事件（`VOICE_STATE_UPDATE channel_id=null`，Server-05 §8）。
- **FR-02** 状态机的所有权威输入为：Gateway 事件（`VOICE_SERVER_UPDATE` / `VOICE_MIGRATING` / `VOICE_MIGRATED` / `VOICE_STATE_UPDATE` / `VOICE_CAPS_UPDATE`，Server-05 §11、Server-09 §7.1）、SFU WSS 事件（`closed`、`caps_updated` 等，Server-协议 §2.2）、本地网络探测（ICE 状态、系统网络接口变化）。
- **FR-03** 同一时刻客户端最多持有**两个** PeerConnection（旧 + 新，即双 PC 热切，Server-08 G.3）；禁止长期双发音频（防回声/抢麦，Server-09 M.3）。

### 3.2 `VOICE_SERVER_UPDATE` 驱动的换节点流程

- **FR-04** 收到 `VOICE_SERVER_UPDATE`（携带新 node 接入信息 + 新 Media Token，Server-09 §7.1）后，客户端必须按以下顺序执行，全程不销毁 UI 层的频道会话：
  1. 解析新 endpoint（`wss://<node>/ws`）与新 token；新 token 的 `sid` 为**新的** `voice_session_id`（Server-15 BJ.2）。
  2. 建立到新节点的 WSS 连接，**5 秒内**以首帧发送 `auth { token }`（token 不得放 URL query，Server-协议 §2、Server-15 BF.2）。
  3. 收到 `ready`（含 `session_id`、`room_id`、`participants` 快照）后，发送 `offer`（含上行音频轨），完成与新节点的 SDP/ICE 协商（Server-协议 §2.3）。
  4. **新旧会话并存期**：SFU 侧会话键 = `sid`，同一用户在新旧节点各持一个会话互不冲突（Server-15 BJ.2）。接收侧可先切到新 PC（或双收选优）；**发送侧继续走旧 PC**，直到 CUTOVER（Server-09 M.3）。
  5. **CUTOVER**：新 PC 媒体连通且下行正常后，发送侧一次性切到新 PC；允许切换瞬间极短静音作缓冲。
  6. **CLEANUP**：关闭旧 PC 与旧 WSS；本地丢弃旧 `sid` 关联状态。若旧节点已死，关闭操作按尽力而为处理（超时直接丢弃）。
- **FR-05** 若迁移伴随 `VOICE_MIGRATING` 事件（含 `migration_id`），客户端必须在后续日志、诊断上报中携带该 `migration_id`（Server-09 K.5 / O.1 全链路可观测）。
- **FR-06** `VOICE_MIGRATING` 与 `VOICE_SERVER_UPDATE` 的到达顺序不做假设：任一先到都应能驱动状态机进入 `MIGRATING`；收到 `VOICE_MIGRATED`（建议事件，Server-09 §7.1）或新 PC 稳定后清除迁移态 UI。
- **FR-07** CONNECT 阶段客户端侧超时预算与服务端对齐（PREPARE ~2s / CONNECT ~5–8s / CUTOVER ~2s / CLEANUP ~3s，Server-09 K.2）：客户端在约 8s 内未能与新节点建立媒体时，保持旧 PC 收发（若旧节点尚存活），并等待服务端换目标后的下一个 `VOICE_SERVER_UPDATE`（重试与换目标是服务端职责，最多 3 次后排队继续，Server-09 K.3）。客户端**不得**自行选择其他节点。
- **FR-08** 客户端在迁移期间若 Gateway 恰好断开（客户端无响应场景，Server-09 M.4）：Gateway 重连后必须主动拉取自身 VoiceState 并请求补发 `VOICE_SERVER_UPDATE`（或依据重连后快照中的 `node_id` 与本地对比，不一致即触发换节点流程）。

### 3.3 Token 生命周期

- **FR-09** Media Token TTL 为 2–5 分钟（Server-协议 §1）。客户端必须在 `exp` 前（建议提前 TTL 的 25%–33%）调用 `POST /voice/refresh-token` 获取新 token，并通过**重发 `auth` 帧**在位更新，不中断媒体（Server-协议 §2.3 第 3 条）。
- **FR-10** refresh 失败（网络错误/5xx）按退避重试（见 FR-20）；若返回表明 caps 已无 `join`，则该用户已被踢出流程覆盖，客户端等待 `VOICE_STATE_UPDATE` 权威事件后关闭 PC 并给出被移出提示（Server-05 §4）。
- **FR-11** 刷新与换节点竞争时：若刷新请求在途收到 `VOICE_SERVER_UPDATE`，丢弃旧刷新结果，直接使用新事件中的 token。

### 3.4 WSS 关闭码处理策略表

收到 SFU `closed { code, message }` 或 WSS 异常关闭时，按下表处理（关闭码定义：Server-协议 §2.4，源自 Server-05 §3.3）。所有路径均**限次**防死循环（Server-05 §3.3），限次耗尽后进入 FR-19 的完整重进流程，仍不回大厅。

| 关闭码 | 含义 | 客户端策略 |
|--------|------|------------|
| `TOKEN_EXPIRED` | token 过期 | 立即 `POST /voice/refresh-token` → 重连同节点 WSS → `auth`。连续 2 次仍过期 → 走 FR-19 完整重进。不提示用户 |
| `TOKEN_INVALID` | 签名/格式非法 | 不重试同 token；直接走 FR-19 完整重进（重新 `POST /voice/join` 拿全新 token）。记录诊断日志 |
| `WRONG_NODE` | token `nid` 与节点不符 | 说明本地缓存的 endpoint 与 token 不一致（多为迁移竞态）。丢弃本地 endpoint 缓存，等待/拉取最新 `VOICE_SERVER_UPDATE`；1s 内未获得则 FR-19 重进 |
| `ROOM_MISMATCH` | token `rid` 与房间不符 | 同 `WRONG_NODE` 处理；额外校验本地频道状态是否已过期（可能用户已被移动频道，检查最新 `VOICE_STATE_UPDATE`） |
| `CAP_DENIED` | caps 不含 `join` | 权限已被收紧（Restriction/踢出）。**不重试**；等待 Gateway 的 `VOICE_STATE_UPDATE` / `RESTRICTION_CREATE` 权威事件，按其结果关闭会话并展示对应文案（Server-12 AL.3）|
| `SESSION_REVOKED` | 会话被服务端吊销 | 多为管理员断开或迁移清理。**不自动重连该 sid**；等待权威事件：若 VoiceState 仍显示在频道内且无新事件，2s 后走 FR-19 重进 |
| `NODE_DRAINING` | 节点排空中 | **不重连该节点**。见 FR-12 主动迁移 |
| `AUTH_TIMEOUT` | 5s 内未发 auth 首帧 | 本地缺陷或网络极差。立即重连并保证 auth 首帧优先发出；连续 2 次超时 → 退避后 FR-19 |

- **FR-12（NODE_DRAINING 主动迁移）** 收到 `NODE_DRAINING` 时，正常情况下服务端 Drain 流程会在 60s 内主动推 `VOICE_SERVER_UPDATE`（Server-09 I.6）。客户端策略：保持 UI 在频道内、静音容忍，等待事件最多 3s；超时未收到则主动 `POST /voice/join`（幂等重进，服务端调度器会硬过滤 DRAINING 节点，必然返回新节点，Server-10 §3）。全程用户无感或仅见微提示。
- **FR-13** 未在上表中的未知关闭码：按一次退避重连处理，重连仍失败走 FR-19；未知码写诊断日志并上报。

### 3.5 本地故障检测与网络切换

- **FR-14** 客户端必须监听 PeerConnection ICE 连接状态：`disconnected` 持续超过 2s 或进入 `failed` 时，视为媒体故障，进入 `RECOVERING`。
- **FR-15（ICE restart）** 本机网络路径变化（Wi-Fi↔有线、IP 变化、系统网络接口事件）但 WSS 仍可达时：优先执行 **ICE restart**——通过现有 WSS 信令通道发送带 `iceRestart` 的新 `offer`，走标准 renegotiation（Server-协议 §2.1 `offer`/`ice` 帧）恢复媒体，不重建会话。若 WSS 同时断开，则重连 WSS → 重发 `auth`（同 token 未过期时可复用）→ 重新协商。SFU 对 ICE restart 的支持程度见 §7「依赖服务端待补充」。
- **FR-16（ICE 失败上报）** ICE `disconnected/failed` 事件必须经 Gateway 上行通道上报 Owl-Server，作为节点死亡的提前判定信号源之一（Server-15 BI.2：≥2 个独立信号源 + ≥1 次心跳失败即可提前判死）。上报应节流（同一节点 10s 内至多 1 次）。
- **FR-17（WSS 心跳）** 客户端对 SFU WSS 按建议 15s 间隔发送 `ping`（Server-协议 §2.1）；连续 2 个 `pong` 丢失（约 30s）视为信令通道故障，触发 FR-15 的重连路径。
- **FR-18** 系统休眠唤醒：唤醒后立刻做一次健康检查（WSS ping + ICE 状态 + token exp）；token 已过期直接走 FR-19。

### 3.6 完整重进与退避

- **FR-19（完整重进流程）** 定义为：客户端在 UI 保持「频道内 + 重连中」状态的前提下，重新执行 `POST /voice/join`（Server-05 §3）→ 用响应的 token/node 建立新会话。该流程对用户完全透明，**不是**「回大厅重进」。join 返回 503 `NO_SFU_CAPACITY` 时按退避继续重试并保持「切换中」UI（Server-10 §2.2：迁移无节点时排队重试、不回大厅）。
- **FR-20（退避策略）** 所有客户端自主重试（WSS 重连、refresh-token、re-join）统一采用**指数退避 + 抖动**：初始 500ms，倍率 2，上限 15s，抖动 ±20%；进入 `SUSPENDED`（本机完全断网）后暂停计时，网络恢复事件触发立即重试。用户主动点击「重试」（若展示）可重置退避。
- **FR-21** 重试全程保留：本地 self_mute/self_deaf 状态、每用户本地音量、被本地静音（=已退订）的用户集合；新会话建立后重放这些状态（退订集合通过重新发送 `unsubscribe` 恢复，Server-08 D.5）。

### 3.7 RTT 探测

- **FR-22** 客户端必须对**本服候选节点池**做 RTT 探测：**后台周期探测**（建议 30s 一轮，错峰）+ **进房前补测**（Server-10 S.1）。探测方式为 `GET /rtt`（无鉴权、限速端点，Server-协议 §2、Server-15 BF.5）。
- **FR-23** 探测结果通过 `ClientReportRtt { samples: [{ node_id, rtt_ms, measured_at }] }` 上报 Server（Server-10 §7）；样本 TTL 为 60s，客户端应保证上报频率使服务端持有新鲜样本（建议每轮探测后立即上报）。
- **FR-24** 客户端理解并接受：RTT 仅是调度的**软因子**，服务端会截断异常值防作弊（Server-10 S.3）；探测失败不影响进房（无样本时服务端按 0.5 中性分处理，Server-10 R.4/S.5）。客户端不得基于本地 RTT 自行选择节点或拒绝服务端指派的节点。
- **FR-25** 候选节点列表的获取接口见 §7「依赖服务端待补充」。

## 4. UI/UX 要求

对标 Discord：语音故障时 Discord 在语音状态卡片处显示黄色/红色的「RTC 正在连接」小字与信号图标变化，频道 UI 不变；KOOK 类似地仅在底部语音条显示重连状态。Owl-Desktop 要求：

- **UX-01** `MIGRATING`/`RECOVERING` 期间：语音状态卡片（左下角常驻区）显示微弱状态文案 + 图标变化（如信号图标变黄）。默认文案使用**模糊措辞**：「线路优化中…」「网络重连中…」（Server-09 O.2 默认模糊）。禁止 Toast 弹窗、禁止模态框、禁止音效打断。
- **UX-02** 系统管理员开启「详细原因」模式时（Server-09 O.2），状态卡片 hover 可见技术详情：reason 码、from/to node_id、migration_id、当前阶段。普通用户默认不可见。
- **UX-03** 频道成员列表在迁移/重连期间**保持不变**（以最近一次 Gateway 快照为准），不得清空闪烁。
- **UX-04** 静音窗口期间本地麦克风指示保持原状；恢复后无需用户任何操作。
- **UX-05** 若重连持续超过 30s，状态文案可升级为「网络状况不佳，仍在重连…」并提供「查看网络诊断」入口（跳转文档 16 的诊断面板），但**仍不提供**「离开重进」作为推荐操作；用户始终保留手动「断开语音」的自由。
- **UX-06** `RECOVERING`→`CONNECTED` 恢复瞬间不播放进房提示音（避免误导为他人进房）；`MIGRATING` 全程同理。
- **UX-07** 边就绪前的短静音（新用户进房或迁移入点在级联边未 Up 时，Server-08 C.4/E.3、Server-09 L.3）：UI 表现为正常在房但对端声音未出，不显示任何错误——这是协议内正常窗口。

## 6. 边界与异常情况

| 场景 | 客户端行为 |
|------|-----------|
| 迁移中用户主动点「断开语音」 | 立即 `POST /voice/leave`，关闭双 PC；服务端会取消迁移 job（Server-09 §10） |
| 迁移中用户切换语音频道 | 按正常 leave+join 走（Server-09 §10）；丢弃在途迁移状态 |
| 新节点 CONNECT 期间也死亡 | 客户端保持旧 PC（若可用）；等服务端换目标重推事件（Server-09 §10） |
| 旧节点已死、新会话又失败 | 完全静音期；UI「线路优化中」持续；客户端按 FR-20 退避执行 FR-19，同时等待服务端事件，两路先到先用 |
| `VOICE_SERVER_UPDATE` 指向的 node 与当前相同 | 视为 token/参数更新：重发 `auth` 即可，无需重建 PC |
| 收到过期/乱序的 `VOICE_SERVER_UPDATE` | 以最后收到者为准；正在执行的热切若目标不同，中止并按最新事件重来 |
| 频道被强制切为 STAGE、本人被容量禁说 | 属 caps 变更非连接故障：按 `caps_updated`/`VOICE_CAPS_UPDATE` 处理，不触发重连（Server-11 Z） |
| 本机完全断网 > token TTL | 网络恢复后 token 必然过期：直接 FR-19 完整重进；期间 UI `SUSPENDED` 态提示「等待网络…」 |
| join 持续 503（池满） | 退避重试 + 「切换中」UI；禁止引导回大厅（Server-09 J.4） |
| 用户被管理员断开（reason=ADMIN_DISCONNECT） | 权威移出：关闭 PC、退出频道 UI、给出明确提示（Server-05 §8.1）；这是唯一允许的「离开频道」类故障出口之一 |

## 7. 依赖服务端待补充

以下能力客户端必需、但服务端文档尚未定义，需在联调前补充定稿：

1. **候选节点池列表下发**：客户端做后台 RTT 探测需要知道本服候选节点的 `node_id + rtt 探测地址` 列表。建议 REST `GET /guilds/{gid}/voice/nodes` 或 Gateway 快照携带。
2. **`ClientReportRtt` 的具体承载**：REST endpoint 还是 Gateway 上行帧，字段已定（Server-10 §7）但传输路径未定。
3. **客户端 ICE 失败上报的事件格式**（Server-15 §9.2 已列为 Server 配套依赖，格式未定）。
4. **SFU 对标准 ICE restart（`iceRestart: true` offer）的支持确认**：Server-15 BG 仅定义了级联侧行为，客户端侧 renegotiation 已有 `offer/answer` 帧，需确认 ICE restart 语义在 SFU 实现内的支持与限制。
5. **`VOICE_MIGRATED` 事件**：Server-09 §7.1 标注为「建议」，需确认是否实装；未实装时客户端以「新 PC 稳定 + 超时」自行清除迁移态。
6. **`POST /voice/join` 的幂等语义确认**：已在频道内重复 join 是否等价于「重发凭据」（FR-12/FR-19 依赖此行为）。

## 8. 客户端观测埋点（与 Server-09 §11 / Server-08 §11 指标对账）

客户端必须采集并可导出（诊断包，见文档 16 FR-37）以下指标，口径与服务端观测指标对齐：

| 指标 | 口径 |
|------|------|
| 静音窗口时长 | 从「最后一个正常下行音频帧」到「新会话首个下行音频帧」的间隔；按 reason（迁移/重连/网络切换）分桶 |
| 双 PC 热切成功率 | 进入 `MIGRATING` 后未退化为完整重进（FR-19）的比例（对齐 Server-08 §11） |
| 迁移端到端耗时 | 收到 `VOICE_MIGRATING`（或 `VOICE_SERVER_UPDATE`）到 CLEANUP 完成，关联 `migration_id` |
| 关闭码分布 | 8 种关闭码 + 未知码的出现次数 |
| ICE restart 次数与耗时 | 网络切换场景（FR-15） |
| 完整重进次数 | FR-19 触发次数及触发原因 |
| RTT 探测成功率 | 每轮探测中可达节点比例 |

## 9. 验收标准

| # | 验收项 | 通过条件 |
|---|--------|----------|
| AC-01 | 杀死用户所在 SFU 节点（叶死） | 客户端自动恢复媒体；全程 UI 未离开频道；无任何需用户点击的弹窗；静音窗口计入指标 |
| AC-02 | 杀死 Anchor 节点（根死，走 Server-08 §7.1 切根） | 同 AC-01；双 PC 热切成功 |
| AC-03 | 对节点执行 Drain | 60s 内用户被迁走；用户侧最多见微弱提示 |
| AC-04 | 模拟 8 种关闭码逐一注入 | 客户端行为逐条符合 §3.4 策略表；无死循环重试（限次生效） |
| AC-05 | token 到期不干预 | 客户端提前刷新，媒体零中断（在位 auth 更新） |
| AC-06 | Wi-Fi ↔ 有线切换 | ICE restart 自动完成；不重建会话（WSS 存活时）；恢复 < 5s |
| AC-07 | 断网 30s 再恢复 | 自动完整重进；恢复后 self_mute、本地音量、本地静音（退订）状态全部还原 |
| AC-08 | join 持续 503 | 指数退避可观测（日志间隔递增至 15s 封顶）；UI 持续「切换中」；无回大厅 |
| AC-09 | 迁移期间抓包 | CUTOVER 前发送侧仅旧 PC 有上行；CUTOVER 后仅新 PC；无双发窗口 > 200ms |
| AC-10 | 迁移日志 | 每次迁移日志含 migration_id、新旧 sid、各阶段时间戳，可与服务端审计对账（Server-09 O.1） |
| AC-11 | RTT 探测 | 后台周期探测与进房前补测均发生；上报样本 `measured_at` 距上报时刻 < 60s |
| AC-12 | UI 走查 | 迁移/重连全程无模态框、无 Toast、成员列表无清空；状态卡片文案为模糊措辞 |
